## 環境変数が消えた場合

`manifest.env`を保存した作業directoryを探し、値を復元します。ID類は作成後に追加されていないため、APIから名前で検索して復元します。

<Command>

```bash
export RAG_WORK_DIR="$(find "$HOME" -maxdepth 2 -type f -name manifest.env -printf '%T@ %h\n' 2>/dev/null | sort -nr | head -1 | cut -d' ' -f2-)"
test -n "$RAG_WORK_DIR"
set -a
source "$RAG_WORK_DIR/manifest.env"
set +a

export RAG_ROLE_ARN="$(aws iam get-role --role-name "$RAG_ROLE_NAME" --query 'Role.Arn' --output text)"
export RAG_VECTOR_BUCKET_ARN="$(aws s3vectors get-vector-bucket --vector-bucket-name "$RAG_VECTOR_BUCKET" --query 'vectorBucket.vectorBucketArn' --output text)"
export RAG_INDEX_ARN="$(aws s3vectors get-index --vector-bucket-name "$RAG_VECTOR_BUCKET" --index-name "$RAG_INDEX_NAME" --query 'index.indexArn' --output text)"
export RAG_KB_ID="$(aws bedrock-agent list-knowledge-bases --query "knowledgeBaseSummaries[?name=='$RAG_KB_NAME'].knowledgeBaseId | [0]" --output text)"
export RAG_DS_ID="$(aws bedrock-agent list-data-sources --knowledge-base-id "$RAG_KB_ID" --query "dataSourceSummaries[?name=='$RAG_DS_NAME'].dataSourceId | [0]" --output text)"

printf 'work=%s\nkb=%s\nds=%s\n' "$RAG_WORK_DIR" "$RAG_KB_ID" "$RAG_DS_ID"
```

</Command>

値が`None`の場合は、そのresourceをまだ作成していないか、別リージョンを参照しています。

## `aws s3vectors`が利用できないコマンドとして扱われる

AWS CLIがS3 Vectorsへ未対応です。

```bash
aws --version
aws s3vectors help
```

[AWS CLI公式手順](https://docs.aws.amazon.com/cli/latest/userguide/getting-started-install.html)で最新版へ更新してください。command名を推測して代替せず、CLI referenceに`aws s3vectors`があるversionを使用します。

## `curl`でPDFを取得できない・PDF検査に失敗する

未完了の`.part` fileを削除してから、HTTP statusと取得内容を確認します。

```bash
rm -f "$RAG_DOCUMENT_PATH.part"
curl --head --location --max-time 30 "$RAG_DOCUMENT_URL"
curl --fail --location --retry 3 --retry-all-errors \
  --output "$RAG_DOCUMENT_PATH.part" "$RAG_DOCUMENT_URL"
head -c 5 "$RAG_DOCUMENT_PATH.part"
```

- `curl: (22)`：HTTP 4xx/5xxです。URLを推測して変更せず、[AWS公式文書](https://docs.aws.amazon.com/ja_jp/wellarchitected/latest/framework/welcome.html)のPDFリンクを確認します。
- 先頭が`%PDF-`ではない：HTMLのerror pageやredirect先を保存しています。完成fileへrenameせず停止します。
- timeout：実行環境のnetwork到達性を確認し、時間を置いて再試行します。失敗時に別サイトの転載PDFへ切り替えません。
- AWSが`latest`を更新した場合：sizeとhashが以前と異なるのは正常です。取得日時と今回のhashを記録します。

## `AccessDeniedException`になる

最初に、どのprincipalとresourceが拒否されたかを確認します。

```bash
aws sts get-caller-identity
printf 'region=%s\n' "$AWS_REGION"
```

- 実習者principalの権限不足：拒否されたAPI actionを管理者へ提示します。
- `iam:PassRole`不足：作成した`RAG_ROLE_ARN`をBedrockへpassできるようにします。
- Knowledge Base service role不足：inline policyとvector bucket policyをread-backします。
- SCPやpermissions boundary：identity policyを追加しても解消しません。組織管理者へ確認します。

## モデルが見つからない・呼び出せない

modelの存在と実際のinvokeは別々に検証します。

```bash
aws bedrock get-foundation-model --model-identifier "$RAG_GENERATION_MODEL_ID"
aws bedrock-runtime converse \
  --model-id "$RAG_GENERATION_MODEL_ID" \
  --messages '[{"role":"user","content":[{"text":"OK"}]}]' \
  --inference-config '{"maxTokens":8,"temperature":0}'
```

東京リージョンのmodel availability、Marketplace entitlement、組織policy、cross-region inferenceの要否を確認します。教材のmodel IDを無条件に別modelへ置換すると、費用・機能・リージョン条件が変わるため注意してください。

## Knowledge Baseの作成に失敗する

```bash
aws iam get-role --role-name "$RAG_ROLE_NAME"
aws iam get-role-policy --role-name "$RAG_ROLE_NAME" --policy-name "$RAG_POLICY_NAME"
aws s3vectors get-vector-bucket-policy --vector-bucket-name "$RAG_VECTOR_BUCKET"
aws s3vectors get-index --index-arn "$RAG_INDEX_ARN"
```

確認項目は次のとおりです。

- roleのtrust先が`bedrock.amazonaws.com`
- `aws:SourceAccount`が現在のaccount ID
- embedding model ARNが東京リージョンのTitan V2
- indexは`FLOAT32 / 1024 / cosine`
- vector bucket policyのprincipalがKnowledge Base service role
- IAM作成直後なら30〜60秒待って1回再試行

## 取り込みジョブがFAILEDになる

失敗理由と統計を省略せず取得します。

```bash
aws bedrock-agent get-ingestion-job \
  --knowledge-base-id "$RAG_KB_ID" \
  --data-source-id "$RAG_DS_ID" \
  --ingestion-job-id "$RAG_INGESTION_JOB_ID" \
  --query 'ingestionJob.{status:status,reasons:failureReasons,statistics:statistics}' \
  --output yaml
```

よく確認する箇所は、S3 `ListBucket/GetObject`、embedding `InvokeModel`、S3 Vectorsの5 action、index dimension、metadata JSONの構文です。原因を直した後に新しいingestion jobを開始します。

## Retrieveが0件・誤った根拠を返す

1. filterを外した同じqueryで結果があるか確認します。
2. `list-knowledge-base-documents`で元文書が`INDEXED`か確認します。
3. queryと正解根拠の語彙・意味を確認します。
4. `numberOfResults`を1、3、5で比較します。
5. 固有名詞や型番が問題ならHYBRID対応storeまたは別BM25 retrieverを検討します。

<Aside type="caution" title="生成モデルの変更を最初にしない">
  正解根拠がRetrieve候補にない場合、generation modelの性能を上げても取得できなかった根拠は復元できません。
</Aside>

## 後片付けでベクトルインデックスを削除できない

data source削除とKnowledge Base削除が終端状態になるまで待ちます。`dataDeletionPolicy=DELETE`によるvector削除中は、service roleを先に消さないでください。

```bash
aws bedrock-agent list-data-sources --knowledge-base-id "$RAG_KB_ID"
aws s3vectors list-vectors --index-arn "$RAG_INDEX_ARN" --max-items 10
```

依存resourceが残っている場合は、[Cleanup](/rag-guide/10-cleanup/)の順番へ戻ります。
