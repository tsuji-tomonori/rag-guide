このページではまだAWSリソースを作りません。後続の失敗を早期に見つけるため、認証、リージョン、AWS CLIのservice command、利用モデルを先に確認します。

## 手順 1.1. AWS CLI実行環境を確認する

<CliStep number="1.1" title="AWS CLI実行環境を確認する">

AWS CLIを実行できるターミナルを開き、想定したAWSアカウントへ認証されていることを確認します。認証方式は、AWS CLIの設定済みprofile、IAM Identity Center、環境変数など、利用する実行環境に合わせてください。

<Command phase="verify" title="AWS CLIの認証を確認" final>

```bash
export RAG_CALLER_IDENTITY="$(aws sts get-caller-identity --output json)"
printf '%s\n' "$RAG_CALLER_IDENTITY"

jq -e '
  (.Account | strings | length == 12) and
  (.Arn | strings | startswith("arn:aws:")) and
  (.UserId | strings | length > 0)
' <<< "$RAG_CALLER_IDENTITY" >/dev/null

export RAG_CALLER_ARN="$(jq -r '.Arn' <<< "$RAG_CALLER_IDENTITY")"
printf '[CHECK] caller identity fields: Account / Arn / UserId\n'
printf '[CHECK] caller principal: %s\n' "$RAG_CALLER_ARN"
printf 'caller identity verification: PASS\n'
```

</Command>

<ExpectedResult id="s1-1-identity" verification="AWS CLIの認証を確認">

次の3行が表示され、`caller principal`が想定したハンズオン用principalであれば成功です。

```text
[CHECK] caller identity fields: Account / Arn / UserId
[CHECK] caller principal: arn:aws:sts::123456789012:assumed-role/WorkshopRole/terminal-session
caller identity verification: PASS
```

- `[CHECK] caller identity fields: Account / Arn / UserId`が表示される
- `[CHECK] caller principal:`に今回の実習用principalが表示される
- `caller identity verification: PASS`が表示される

</ExpectedResult>

</CliStep>

## 手順 1.2. 共通変数を設定する

<CliStep number="1.2" title="共通変数を設定する">

以降は同じターミナルセッションで作業します。複数人が同じAWS account・Regionで同時に実施しても名前が衝突しにくいよう、UTC時刻に6桁のランダムな16進数を加えたrun IDを使います。また、ターミナルセッションが途中で再作成されても復旧できるよう、環境変数を`$HOME`配下へ保存します。

<Command phase="prepare" title="共通変数と設定値を準備">

```bash
export AWS_REGION="ap-northeast-1"
export AWS_DEFAULT_REGION="$AWS_REGION"

export RAG_ACCOUNT_ID="$(aws sts get-caller-identity --query Account --output text)"
export RAG_RUN_ID="$(date -u +%m%d%H%M%S)-$(openssl rand -hex 3)"
export RAG_WORK_DIR="$HOME/rag-handson-$RAG_RUN_ID"
export RAG_STATE_FILE="$RAG_WORK_DIR/state.env"

export RAG_SOURCE_BUCKET="rag-handson-${RAG_ACCOUNT_ID}-${RAG_RUN_ID}"
export RAG_VECTOR_BUCKET="rag-handson-vectors-${RAG_ACCOUNT_ID}-${RAG_RUN_ID}"
export RAG_INDEX_NAME="rag-titan-v2-1024"
export RAG_ROLE_NAME="BedrockKnowledgeBaseRole-${RAG_RUN_ID}"
export RAG_POLICY_NAME="BedrockKnowledgeBasePolicy-${RAG_RUN_ID}"
export RAG_KB_NAME="rag-handson-kb-${RAG_RUN_ID}"
export RAG_DS_NAME="rag-handson-s3-${RAG_RUN_ID}"
export RAG_EMBED_MODEL_ID="amazon.titan-embed-text-v2:0"
export RAG_GENERATION_MODEL_ID="amazon.nova-lite-v1:0"
export RAG_GENERATION_MODEL_ARN="arn:aws:bedrock:${AWS_REGION}::foundation-model/${RAG_GENERATION_MODEL_ID}"
export RAG_DOCUMENT_URL="https://docs.aws.amazon.com/ja_jp/prescriptive-guidance/latest/retrieval-augmented-generation-options/retrieval-augmented-generation-options.pdf"
export RAG_DOCUMENT_PATH="$RAG_WORK_DIR/documents/aws-rag-options-and-architectures.pdf"

mkdir -p "$RAG_WORK_DIR/documents"

declare -p \
  AWS_REGION AWS_DEFAULT_REGION \
  RAG_ACCOUNT_ID RAG_RUN_ID RAG_WORK_DIR RAG_STATE_FILE \
  RAG_SOURCE_BUCKET RAG_VECTOR_BUCKET RAG_INDEX_NAME \
  RAG_ROLE_NAME RAG_POLICY_NAME RAG_KB_NAME RAG_DS_NAME \
  RAG_EMBED_MODEL_ID RAG_GENERATION_MODEL_ID RAG_GENERATION_MODEL_ARN \
  RAG_DOCUMENT_URL RAG_DOCUMENT_PATH \
  > "$RAG_STATE_FILE"

printf 'source %q\n' "$RAG_STATE_FILE" > "$HOME/.rag-handson-current"
cat "$RAG_STATE_FILE"
```

</Command>

<Command phase="verify" title="変数を検証" final>

```bash
test "$AWS_REGION" = "ap-northeast-1"
test "${#RAG_ACCOUNT_ID}" -eq 12
[[ "$RAG_RUN_ID" =~ ^[0-9]{10}-[0-9a-f]{6}$ ]]
test -d "$RAG_WORK_DIR/documents"
test -s "$RAG_STATE_FILE"
test -s "$HOME/.rag-handson-current"
[[ "$RAG_DOCUMENT_URL" == https://docs.aws.amazon.com/* ]]
[[ "$RAG_GENERATION_MODEL_ARN" == "arn:aws:bedrock:${AWS_REGION}::foundation-model/${RAG_GENERATION_MODEL_ID}" ]]
printf '[CHECK] region: %s\n' "$AWS_REGION"
printf '[CHECK] run ID format: UTC timestamp + 6-digit hex (%s)\n' "$RAG_RUN_ID"
printf '[CHECK] state files: READY\n'
printf '[CHECK] generation model ARN: %s\n' "$RAG_GENERATION_MODEL_ARN"
printf 'environment verification: PASS\n'
```

</Command>

<ExpectedResult id="s1-2-variables" verification="変数を検証">

次の5行が表示されれば成功です。run IDと生成モデルARNには、このrunの実値が入ります。

```text
[CHECK] region: ap-northeast-1
[CHECK] run ID format: UTC timestamp + 6-digit hex (0816071530-a41f92)
[CHECK] state files: READY
[CHECK] generation model ARN: arn:aws:bedrock:ap-northeast-1::foundation-model/amazon.nova-lite-v1:0
environment verification: PASS
```

- `[CHECK] region: ap-northeast-1`が表示される
- `[CHECK] run ID format: UTC timestamp + 6-digit hex`が表示される
- `[CHECK] state files: READY`が表示される
- `[CHECK] generation model ARN:`に東京リージョンのNova Lite ARNが表示される
- `environment verification: PASS`が表示される

</ExpectedResult>

<Aside type="note" title="ターミナルを開き直した場合">
  セッションが切り替わると、`export`した環境変数は消えます。ハンズオンの作業ファイルと状態ファイルは`$HOME`配下へ保存しているため、`source "$HOME/.rag-handson-current"`を実行すれば、現在のrunの環境変数を復元できます。
</Aside>

</CliStep>

## 手順 1.3. CLIとAWSサービスを検証する

<CliStep number="1.3" title="CLIとAWSサービスを検証する">

<Command phase="verify" title="CLIとAWSサービスを検証" final>

```bash
export RAG_AWS_CLI_VERSION="$(aws --version 2>&1)"
export RAG_JQ_VERSION="$(jq --version)"

aws s3vectors list-vector-buckets \
  --max-results 1 \
  --output json \
  | tee "$RAG_WORK_DIR/list-vector-buckets.json" >/dev/null
jq -e '.vectorBuckets | type == "array"' \
  "$RAG_WORK_DIR/list-vector-buckets.json" >/dev/null

export RAG_FOUNDATION_MODEL_COUNT="$(aws bedrock list-foundation-models \
  --region "$AWS_REGION" \
  --query 'length(modelSummaries)' \
  --output text)"
test "$RAG_FOUNDATION_MODEL_COUNT" -ge 1

printf '[CHECK] AWS CLI version: %s\n' "$RAG_AWS_CLI_VERSION"
printf '[CHECK] jq version: %s\n' "$RAG_JQ_VERSION"
printf '[CHECK] S3 Vectors API: AVAILABLE\n'
printf '[CHECK] foundation models: %s (>= 1)\n' "$RAG_FOUNDATION_MODEL_COUNT"
printf 'CLI and service verification: PASS\n'
```

</Command>

<ExpectedResult id="s1-3-cli" verification="CLIとAWSサービスを検証">

次の5行が表示されれば成功です。vector bucketが0件でも、APIがJSONを返せれば`AVAILABLE`になります。

```text
[CHECK] AWS CLI version: aws-cli/2.x.x ...
[CHECK] jq version: jq-1.7
[CHECK] S3 Vectors API: AVAILABLE
[CHECK] foundation models: 20 (>= 1)
CLI and service verification: PASS
```

- `[CHECK] AWS CLI version:`が表示される
- `[CHECK] jq version:`が表示される
- `[CHECK] S3 Vectors API: AVAILABLE`が表示される
- `[CHECK] foundation models:`に`1`以上の件数が表示される
- `CLI and service verification: PASS`が表示される

</ExpectedResult>

<Aside type="caution" title="aws: error: argument command: Invalid choice の場合">
  利用中のAWS CLIが`aws s3vectors`へ未対応です。古いCLIのままハンズオンを進めず、[AWS CLIの更新手順](https://docs.aws.amazon.com/cli/latest/userguide/getting-started-install.html)で最新版へ更新してください。
</Aside>

</CliStep>

## 手順 1.4. 利用モデルを検証する

<CliStep number="1.4" title="利用モデルを検証する">

まず、東京リージョンにmodel IDが存在することを確認します。その後、Nova Liteへ短い`Converse`を1回だけ実行し、実際にinvokeできることを確認します。

<Command phase="verify" title="利用モデルを検証">

```bash
aws bedrock get-foundation-model \
  --region "$AWS_REGION" \
  --model-identifier "$RAG_EMBED_MODEL_ID" \
  --query 'modelDetails' \
  --output json \
  | tee "$RAG_WORK_DIR/embed-model.json" >/dev/null

aws bedrock get-foundation-model \
  --region "$AWS_REGION" \
  --model-identifier "$RAG_GENERATION_MODEL_ID" \
  --query 'modelDetails' \
  --output json \
  | tee "$RAG_WORK_DIR/generation-model.json" >/dev/null

jq -e --arg modelId "$RAG_EMBED_MODEL_ID" '
  .modelId == $modelId and
  (.inputModalities | index("TEXT")) and
  (.outputModalities | index("FLOAT"))
' "$RAG_WORK_DIR/embed-model.json" >/dev/null

jq -e --arg modelId "$RAG_GENERATION_MODEL_ID" '
  .modelId == $modelId and
  (.inputModalities | index("TEXT")) and
  (.outputModalities | index("TEXT"))
' "$RAG_WORK_DIR/generation-model.json" >/dev/null

printf '[CHECK] embedding model: %s (TEXT -> FLOAT)\n' "$RAG_EMBED_MODEL_ID"
printf '[CHECK] generation model: %s (TEXT -> TEXT)\n' "$RAG_GENERATION_MODEL_ID"
```

</Command>

<Command phase="execute" title="Converseの疎通確認（少量の推論料金が発生します）">

```bash
export RAG_SMOKE_RESPONSE="$(aws bedrock-runtime converse \
  --region "$AWS_REGION" \
  --model-id "$RAG_GENERATION_MODEL_ID" \
  --messages '[{"role":"user","content":[{"text":"OKとだけ答えてください。"}]}]' \
  --inference-config '{"maxTokens":8,"temperature":0}' \
  --query 'output.message.content[0].text' \
  --output text)"

[[ "$RAG_SMOKE_RESPONSE" == *"OK"* ]]
printf '[CHECK] Converse response: %s\n' "$RAG_SMOKE_RESPONSE"
printf 'model verification: PASS\n'
```

</Command>

<ExpectedResult id="s1-4-models" verification="Converseの疎通確認（少量の推論料金が発生します）">

次の4行が表示されれば成功です。

```text
[CHECK] embedding model: amazon.titan-embed-text-v2:0 (TEXT -> FLOAT)
[CHECK] generation model: amazon.nova-lite-v1:0 (TEXT -> TEXT)
[CHECK] Converse response: OK
model verification: PASS
```

- `[CHECK] embedding model:`にTitan Text Embeddings V2が表示される
- `[CHECK] generation model:`にNova Liteが表示される
- `[CHECK] Converse response:`に`OK`を含む応答が表示される
- `model verification: PASS`が表示される

</ExpectedResult>

</CliStep>

<Checkpoint>

- caller identityが想定した実習用principalである
- `AWS_REGION`は`ap-northeast-1`である
- `RAG_RUN_ID`はUTC時刻と6桁hexのランダムサフィックスを含む
- `$HOME/.rag-handson-current`から現在のrunを復元できる
- `aws s3vectors`を実行できる
- Titan Text Embeddings V2とNova Liteを東京リージョンで利用できる

</Checkpoint>
