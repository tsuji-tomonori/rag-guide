<CloudShellStep number="10.2" title="データソースとナレッジベースを削除する">

data deletion policyを`DELETE`にしているため、data source削除時に取り込んだvectorの削除も要求されます。service roleはこの処理が終わるまで残します。

<Command phase="execute" title="データソースとKnowledge Baseを削除">

```bash
aws bedrock-agent delete-data-source \
  --region "$AWS_REGION" \
  --knowledge-base-id "$RAG_KB_ID" \
  --data-source-id "$RAG_DS_ID"

for attempt in {1..30}; do
  if ! aws bedrock-agent get-data-source \
    --region "$AWS_REGION" \
    --knowledge-base-id "$RAG_KB_ID" \
    --data-source-id "$RAG_DS_ID" >/dev/null 2>&1; then
    printf 'data source deleted\n'
    break
  fi
  printf '[%02d/30] waiting for data source deletion\n' "$attempt"
  sleep 10
done

if aws bedrock-agent get-data-source \
  --region "$AWS_REGION" \
  --knowledge-base-id "$RAG_KB_ID" \
  --data-source-id "$RAG_DS_ID" >/dev/null 2>&1; then
  printf 'ERROR: data source still exists\n' >&2
  exit 1
fi

aws bedrock-agent delete-knowledge-base \
  --region "$AWS_REGION" \
  --knowledge-base-id "$RAG_KB_ID"

for attempt in {1..30}; do
  if ! aws bedrock-agent get-knowledge-base \
    --region "$AWS_REGION" \
    --knowledge-base-id "$RAG_KB_ID" >/dev/null 2>&1; then
    printf 'knowledge base deleted\n'
    break
  fi
  printf '[%02d/30] waiting for knowledge base deletion\n' "$attempt"
  sleep 10
done

if aws bedrock-agent get-knowledge-base \
  --region "$AWS_REGION" \
  --knowledge-base-id "$RAG_KB_ID" >/dev/null 2>&1; then
  printf 'ERROR: knowledge base still exists\n' >&2
  exit 1
fi

printf '[CHECK] data source deletion: COMPLETE (absent)\n'
printf '[CHECK] knowledge base deletion: COMPLETE (absent)\n'
printf 'Bedrock deletion: PASS\n'
```

</Command>

<Aside type="note" title="削除後のgetは待機確認だけに使います">
  delete API自体が成功したことを主な判定とし、続くget APIは削除完了待ちの補助に使います。caller側のread権限や一時的なAPI errorまで「削除済み」と誤認しないよう、最後は10.4の独立した残存確認も実施します。
</Aside>

<CloudShellStep number="10.4" title="S3とIAMロールを削除する">

<Command phase="execute" title="原文書用バケットを削除">

```bash
aws s3 rm "s3://$RAG_SOURCE_BUCKET" --recursive --region "$AWS_REGION"
aws s3api delete-bucket \
  --region "$AWS_REGION" \
  --bucket "$RAG_SOURCE_BUCKET"
```

</Command>

<Command phase="execute" title="IAMロールに実在するポリシーを削除してからロールを削除">

```bash
policy_names="$(aws iam list-role-policies \
  --role-name "$RAG_ROLE_NAME" \
  --query 'PolicyNames[]' \
  --output text)"
if [ "$policy_names" != "None" ]; then
  for policy_name in $policy_names; do
    printf 'Deleting inline policy: %s\n' "$policy_name"
    aws iam delete-role-policy \
      --role-name "$RAG_ROLE_NAME" \
      --policy-name "$policy_name"
  done
fi

attached_policy_arns="$(aws iam list-attached-role-policies \
  --role-name "$RAG_ROLE_NAME" \
  --query 'AttachedPolicies[].PolicyArn' \
  --output text)"
if [ "$attached_policy_arns" != "None" ]; then
  for policy_arn in $attached_policy_arns; do
    printf 'Detaching managed policy: %s\n' "$policy_arn"
    aws iam detach-role-policy \
      --role-name "$RAG_ROLE_NAME" \
      --policy-arn "$policy_arn"
  done
fi

test "$(aws iam list-role-policies \
  --role-name "$RAG_ROLE_NAME" \
  --query 'length(PolicyNames)' \
  --output text)" = "0"

test "$(aws iam list-attached-role-policies \
  --role-name "$RAG_ROLE_NAME" \
  --query 'length(AttachedPolicies)' \
  --output text)" = "0"

aws iam delete-role --role-name "$RAG_ROLE_NAME"
```

</Command>

<Aside type="note" title="ポリシー名を固定して削除しない理由">
  トラブルシューティング中に`AllowTitanEmbeddingInvoke`のような追加inline policyを付けることがあります。`RAG_POLICY_NAME`だけを削除すると追加policyが残り、`DeleteConflict: must delete policies first`でrole削除に失敗します。このハンズオン専用roleでは、削除時に実在するinline policyを列挙して全削除し、attached managed policyがあればdetachしてからroleを削除します。
</Aside>

<Command phase="verify" title="全リソースの削除結果を最終確認" final>

```bash
RAG_CLEANUP_FAILURES=0

aws s3api head-bucket \
  --region "$AWS_REGION" \
  --bucket "$RAG_SOURCE_BUCKET" >/dev/null 2>&1 && {
  printf 'ERROR: source bucket remains\n' >&2
  RAG_CLEANUP_FAILURES=$((RAG_CLEANUP_FAILURES + 1))
}

aws s3vectors get-vector-bucket \
  --region "$AWS_REGION" \
  --vector-bucket-name "$RAG_VECTOR_BUCKET" >/dev/null 2>&1 && {
  printf 'ERROR: vector bucket remains\n' >&2
  RAG_CLEANUP_FAILURES=$((RAG_CLEANUP_FAILURES + 1))
}

aws iam get-role --role-name "$RAG_ROLE_NAME" >/dev/null 2>&1 && {
  printf 'ERROR: IAM role remains\n' >&2
  RAG_CLEANUP_FAILURES=$((RAG_CLEANUP_FAILURES + 1))
}

aws bedrock-agent get-data-source \
  --region "$AWS_REGION" \
  --knowledge-base-id "$RAG_KB_ID" \
  --data-source-id "$RAG_DS_ID" >/dev/null 2>&1 && {
  printf 'ERROR: data source remains\n' >&2
  RAG_CLEANUP_FAILURES=$((RAG_CLEANUP_FAILURES + 1))
}

aws bedrock-agent get-knowledge-base \
  --region "$AWS_REGION" \
  --knowledge-base-id "$RAG_KB_ID" >/dev/null 2>&1 && {
  printf 'ERROR: knowledge base remains\n' >&2
  RAG_CLEANUP_FAILURES=$((RAG_CLEANUP_FAILURES + 1))
}

test "$RAG_CLEANUP_FAILURES" -eq 0
printf '[CHECK] source bucket deletion: COMPLETE (absent)\n'
printf '[CHECK] vector bucket deletion: COMPLETE (absent)\n'
printf '[CHECK] IAM role deletion: COMPLETE (absent)\n'

```

</Command>
