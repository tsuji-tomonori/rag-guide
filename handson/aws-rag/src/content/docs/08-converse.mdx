ここでは`RetrieveAndGenerate`を使わず、PDFの4ステップのうち「リトリーバー」と「ジェネレーター」を明示的に分けます。`Retrieve`で返ったコンテキストを確認してから`Converse`へ渡すため、生成前の重複排除、版の確認、根拠不足判定を追加できます。`RetrieveAndGenerate`は、取得・プロンプト拡張・生成を一つのAPIで行う比較対象です。

<CloudShellStep number="8.1" title="根拠セット付きメッセージを作成する">

<Command phase="prepare" title="根拠セット付きメッセージを準備">

```bash
export RAG_EVIDENCE="$(cat "$RAG_WORK_DIR/evidence.txt")"

jq -n \
  --arg question "$RAG_QUESTION" \
  --arg evidence "$RAG_EVIDENCE" \
  '[{
    role:"user",
    content:[{
      text:(
        "あなたは根拠に基づいて回答するアシスタントです。\n" +
        "次のEvidence Setだけを使って日本語で簡潔に回答してください。\n" +
        "PDFのRAG 4ステップ（文書の取り込み、自然言語クエリ、類似度検索による関連データの取得、クエリとコンテキストを使ったLLM回答）に沿って説明してください。\n" +
        "Knowledge Basesのチャンク化・埋め込み・ベクトルデータベースへの保存、RetrieveとRetrieveAndGenerateの役割の違いを区別してください。\n" +
        "各主張の末尾に[E1]形式のcitation IDを付けてください。\n" +
        "根拠が不足する場合は、推測せず『根拠不足です』と回答してください。\n\n" +
        "質問:\n" + $question + "\n\n" +
        "Evidence Set:\n" + $evidence
      )
    }]
  }]' | tee "$RAG_WORK_DIR/converse-messages.json"

jq -e 'length == 1 and .[0].role == "user" and (.[] | .content | length == 1)' \
  "$RAG_WORK_DIR/converse-messages.json" >/dev/null
```

</Command>

<ExpectedResult id="s8-1-message" verification="根拠セット付きメッセージを準備">

message JSONが表示され、質問、制約、`[E1]`を含むEvidence Setが1つのuser messageへ入っています。

```json
[
  {
    "role": "user",
    "content": [
      {"text": "...質問...\n\nEvidence Set:\n[E1] ... source=s3://..."}
    ]
  }
]
```

- messageが1件のuser messageである
- 質問、Evidence Set、`[E1]`形式の指示が含まれる

</ExpectedResult>

</CloudShellStep>

<CloudShellStep number="8.2" title="Converseを呼び出す">

<Command phase="execute" title="Converseを呼び出す">

```bash
aws bedrock-runtime converse \
  --model-id "$RAG_GENERATION_MODEL_ID" \
  --messages "file://$RAG_WORK_DIR/converse-messages.json" \
  --inference-config '{"maxTokens":400,"temperature":0.1,"topP":0.9}' \
  | tee "$RAG_WORK_DIR/converse-output.json"

jq -r '.output.message.content[] | select(.text) | .text' \
  "$RAG_WORK_DIR/converse-output.json" \
  | tee "$RAG_WORK_DIR/answer.txt"
```

</Command>

<ExpectedResult id="s8-2-answer" verification="Converseを呼び出す">

回答に、PDFのRAG 4ステップ、Knowledge Basesが文書をチャンク化・埋め込みしてベクトルデータベースへ保存する流れ、リトリーバーによる類似度検索、`Retrieve`と`RetrieveAndGenerate`の役割の違いが含まれます。各主張にはEvidence Setに対応する`[E1]`形式のcitationが付き、Evidence Setにない説明を創作していません。

```text
AWS Well-Architected Frameworkの柱は次の6つです。
1. 運用上の優秀性 [E1]
2. セキュリティ [E1]
3. 信頼性 [E1]
4. パフォーマンス効率 [E1]
5. コスト最適化 [E1]
6. 持続可能性 [E1]
```

- 6本の柱が回答に含まれる
- 回答に`[E1]`形式のcitationがある
- Evidence Setにない内容を根拠として追加していない

</ExpectedResult>

</CloudShellStep>

<CloudShellStep number="8.3" title="最低限の引用検査を行う">

<Command phase="verify" title="最低限の引用検査を行う" final>

```bash
test -s "$RAG_WORK_DIR/answer.txt"
grep -Eq 'ナレッジベース|Knowledge Bases' "$RAG_WORK_DIR/answer.txt"
grep -Eq '4[[:space:]]*つのステップ|4[[:space:]]*ステップ' "$RAG_WORK_DIR/answer.txt"
grep -Eq 'チャンク|chunk' "$RAG_WORK_DIR/answer.txt"
grep -Eq '埋め込み|embedding' "$RAG_WORK_DIR/answer.txt"
grep -q 'ベクトルデータベース' "$RAG_WORK_DIR/answer.txt"
grep -Eq '類似度検索|関連データ' "$RAG_WORK_DIR/answer.txt"
grep -Eq '取得|Retrieve' "$RAG_WORK_DIR/answer.txt"
grep -q 'RetrieveAndGenerate' "$RAG_WORK_DIR/answer.txt"
grep -Eq '\[E[0-9]+\]' "$RAG_WORK_DIR/answer.txt"

for citation in $(grep -oE '\[E[0-9]+\]' "$RAG_WORK_DIR/answer.txt" | sort -u); do
  grep -Fq "$citation" "$RAG_WORK_DIR/evidence.txt" || {
    printf 'unknown citation: %s\n' "$citation" >&2
    exit 1
  }
done

printf 'citation validation: PASS\n'
```

</Command>

<ExpectedResult id="s8-3-citation" verification="最低限の引用検査を行う">

`citation validation: PASS`と表示されます。回答内のcitation IDが、実際のEvidence Setに存在します。さらに、RAG 4ステップ、Knowledge Basesの取り込み、リトリーバーの類似度検索、2つのAPIの役割が質問に対応して説明されます。

```text
citation validation: PASS
```

- `answer.txt`が空でない
- 必須の柱の語と`[E1]`形式がある
- 回答内の全citation IDがEvidence Setに存在する
- `citation validation: PASS`が表示される

</ExpectedResult>

<Aside type="note" title="この検査だけでは主張の根拠付けを証明できません">
  citation IDの存在確認とキーワード検査は最低限の構文検査です。合格判定は、(1) PDFの4ステップに沿っている、(2) `Retrieve`と`RetrieveAndGenerate`を混同していない、(3)各claimが参照本文に支持されている、(4)根拠がなければ推測せず「根拠不足です」と答える、の4点で行います。
</Aside>

</CloudShellStep>

- すべてのcitation IDがEvidence Set内に存在する
- 検索結果と生成結果を別ファイルへ保存した

</Checkpoint>
