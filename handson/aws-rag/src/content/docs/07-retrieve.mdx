生成モデルを呼ぶ前に、PDFが説明する「リトリーバーが関連データを取得する」段階だけを観察します。検索結果に必要な根拠がなければ、生成モデルを変更しても根本原因は解消しません。

| 判定対象 | PDFに対応する根拠 | 合格の見方 |
|---|---|---|
| 取り込み | チャンク、埋め込み、ベクトルデータベース | 文書を分割して埋め込みを保存する説明が候補にある |
| リトリーバー | 自然言語クエリ、類似度検索、関連データ | 質問に対応する本文が上位候補にあり、source URIへ追跡できる |
| API境界 | 取得（`Retrieve`）と`RetrieveAndGenerate` | 取得結果を後続処理へ渡すAPIと、取得・生成をまとめるAPIを区別できる |
| スコア | 同一条件内の順位比較 | 固定閾値ではなく、根拠の有無と順位を比較する |

## 手順 7.1. 意味検索を実行する

<CliStep number="7.1" title="意味検索を実行する">

<Command phase="prepare" title="検索条件を準備">

```bash
export RAG_QUESTION="この資料の説明に沿って、RAGの4つのステップ（文書の取り込み、自然言語クエリ、類似度検索による関連データの取得、クエリとコンテキストを使ったLLM回答）を説明してください。さらに、Amazon Bedrockナレッジベースの文書のチャンク化・埋め込み・ベクトルデータベースへの保存と、取得API（Retrieve）／RetrieveAndGenerate APIの違いも説明してください。"

jq -n \
  --arg kbId "$RAG_KB_ID" \
  --arg question "$RAG_QUESTION" \
  '{
    knowledgeBaseId:$kbId,
    retrievalQuery:{text:$question},
    retrievalConfiguration:{
      vectorSearchConfiguration:{
        numberOfResults:5,
        overrideSearchType:"SEMANTIC"
      }
    }
  }' | tee "$RAG_WORK_DIR/retrieve-input.json"

```

</Command>

<Command phase="execute" title="Retrieveを実行">

```bash
aws bedrock-agent-runtime retrieve \
  --region "$AWS_REGION" \
  --cli-input-json "file://$RAG_WORK_DIR/retrieve-input.json" \
  | tee "$RAG_WORK_DIR/retrieve-output.json"

jq -e '
  (.retrievalResults | length) > 0 and
  all(.retrievalResults[];
    (.content.text | type == "string" and length > 0) and
    (.score | type == "number") and
    (.location.s3Location.uri | type == "string" and startswith("s3://")) and
    (.metadata | type == "object"))
' "$RAG_WORK_DIR/retrieve-output.json" >/dev/null

export RAG_RETRIEVAL_COUNT="$(jq '.retrievalResults | length' \
  "$RAG_WORK_DIR/retrieve-output.json")"
printf '[CHECK] Retrieve API: COMPLETE\n'
printf '[CHECK] retrieval candidates: %s (>= 1)\n' "$RAG_RETRIEVAL_COUNT"
printf '[CHECK] candidate fields: text / score / S3 source URI / metadata\n'
printf 'Retrieve execution verification: PASS\n'
```

</Command>

<ExpectedResult id="s7-1-retrieve" verification="Retrieveを実行">

次の4行が表示されれば成功です。

```text
[CHECK] Retrieve API: COMPLETE
[CHECK] retrieval candidates: 5 (>= 1)
[CHECK] candidate fields: text / score / S3 source URI / metadata
Retrieve execution verification: PASS
```

- `[CHECK] Retrieve API: COMPLETE`が表示される
- `[CHECK] retrieval candidates:`に`1`以上の件数が表示される
- `[CHECK] candidate fields: text / score / S3 source URI / metadata`が表示される
- `Retrieve execution verification: PASS`が表示される

</ExpectedResult>

</CliStep>

## 手順 7.2. 検索結果を検証する

<CliStep number="7.2" title="検索結果を検証する">

<Command phase="verify" title="検索結果を検証する" final>

```bash
jq -r '
  .retrievalResults
  | to_entries[]
  | "rank=\(.key + 1) score=\(.value.score) category=\(.value.metadata.category // "-") status=\(.value.metadata.status // "-")\nlanguage=\(.value.metadata.language // "-")\nsource=\(.value.location.s3Location.uri // "-")\ntext=\(.value.content.text)\n"
' "$RAG_WORK_DIR/retrieve-output.json"

jq '
  (.retrievalResults // []) as $results |
  ($results | map(.content.text // "") | join("\n")) as $text |
  {
    returned: ($results | length),
    topScore: ($results[0].score // null),
    coverage: {
      ingestion: ($text | (test("チャンク|チャンキング") and contains("埋め込み") and contains("ベクトルデータベース"))),
      retrieval: ($text | (test("自然言語|クエリ|質問") and test("類似度検索|類似性検索|関連データ"))),
      api: ($text | (test("取得|Retrieve") and contains("RetrieveAndGenerate")))
    },
    sourceTraceable: all($results[];
      ((.location.s3Location.uri // "") | contains("aws-rag-options-and-architectures.pdf"))
      and (.metadata.category // "") == "rag-guidance"
    )
  }
' "$RAG_WORK_DIR/retrieve-output.json" \
  | tee "$RAG_WORK_DIR/retrieve-coverage.json" >/dev/null

jq -e '
  .returned > 0 and
  .coverage.ingestion and
  .coverage.retrieval and
  .coverage.api and
  .sourceTraceable
' "$RAG_WORK_DIR/retrieve-coverage.json" >/dev/null

export RAG_RETRIEVAL_COUNT="$(jq '.returned' \
  "$RAG_WORK_DIR/retrieve-coverage.json")"
printf '[CHECK] retrieval candidates: %s (>= 1)\n' "$RAG_RETRIEVAL_COUNT"
printf '[CHECK] evidence coverage: ingestion / retrieval / API boundary\n'
printf '[CHECK] source and category: expected PDF / rag-guidance\n'
printf 'retrieval verification: PASS\n'
```

</Command>

表示される各candidateでは、`rank`がリトリーバーの返却順、`score`が同一条件内の関連度比較、`source`が根拠PDFのS3 URI、`text`が実際に取り出されたchunk本文です。`retrieve-coverage.json`では、PDFの「取り込み」「リトリーバー」「API境界」に対応する根拠が検索結果全体に含まれるかを確認します。候補数だけでなく、質問への根拠があり、source URIへ追跡できることを合格条件にします。

<ExpectedResult id="s7-2-results" verification="検索結果を検証する">

次の4行が表示されれば成功です。

```text
[CHECK] retrieval candidates: 5 (>= 1)
[CHECK] evidence coverage: ingestion / retrieval / API boundary
[CHECK] source and category: expected PDF / rag-guidance
retrieval verification: PASS
```

- `[CHECK] retrieval candidates:`に`1`以上の件数が表示される
- `[CHECK] evidence coverage: ingestion / retrieval / API boundary`が表示される
- `[CHECK] source and category: expected PDF / rag-guidance`が表示される
- `retrieval verification: PASS`が表示される

</ExpectedResult>

<Aside type="caution" title="スコアへ固定閾値を置かないでください">
  scoreの尺度はmodel、store、query、設定によって変わります。単発の値から「0.7以上なら正しい」と決めず、同じ質問・同じ設定で順位を比較し、必要な根拠が上位候補にあるか、無関係なchunkが増えていないか、source URIへ追跡できるかで判断します。
</Aside>

</CliStep>

## 手順 7.3. 検索結果を根拠セットへ整形する

<CliStep number="7.3" title="検索結果を根拠セットへ整形する">

<Command phase="verify" title="検索結果を根拠セットへ整形" final>

```bash
jq -r '
  .retrievalResults
  | to_entries
  | map(
      "[E\(.key + 1)]\n" +
      .value.content.text + "\n" +
      "source=" + (.value.location.s3Location.uri // "unknown")
    )
  | join("\n\n")
' "$RAG_WORK_DIR/retrieve-output.json" \
  | tee "$RAG_WORK_DIR/evidence.txt"

test -s "$RAG_WORK_DIR/evidence.txt"
grep -q '\[E1\]' "$RAG_WORK_DIR/evidence.txt"
grep -q 'source=s3://' "$RAG_WORK_DIR/evidence.txt"

export RAG_EVIDENCE_COUNT="$(grep -c '^\[E[0-9][0-9]*\]$' \
  "$RAG_WORK_DIR/evidence.txt")"
export RAG_EVIDENCE_SOURCE_COUNT="$(grep -c '^source=s3://' \
  "$RAG_WORK_DIR/evidence.txt")"
test "$RAG_EVIDENCE_COUNT" -ge 1
test "$RAG_EVIDENCE_SOURCE_COUNT" -eq "$RAG_EVIDENCE_COUNT"

printf '[CHECK] evidence blocks: %s (>= 1)\n' "$RAG_EVIDENCE_COUNT"
printf '[CHECK] each block: citation ID / text / S3 source URI\n'
printf 'evidence set verification: PASS\n'
```

</Command>

<ExpectedResult id="s7-3-evidence" verification="検索結果を根拠セットへ整形">

次の3行が表示されれば成功です。

```text
[CHECK] evidence blocks: 5 (>= 1)
[CHECK] each block: citation ID / text / S3 source URI
evidence set verification: PASS
```

- `[CHECK] evidence blocks:`に`1`以上の件数が表示される
- `[CHECK] each block: citation ID / text / S3 source URI`が表示される
- `evidence set verification: PASS`が表示される

</ExpectedResult>

</CliStep>

<Checkpoint>

- `Retrieve`は1件以上を返した
- `retrieve-coverage.json`でPDFの取り込み・リトリーバー・API境界のcoverageがすべて`true`である
- source URIが`aws-rag-options-and-architectures.pdf`を指す
- scoreの固定閾値ではなく、根拠本文・順位・source traceabilityで合否を判断した
- `evidence.txt`にcitation ID、本文、source URIがある

</Checkpoint>
