このページは、ハンズオンで作成するAWSリソースの**設定値の正本**です。各手順ページでは作成コマンドを順番に実行し、このページでは「何を、どの名前で、どの設定で作るか」を横断して確認します。

値が実行ごとに変わる項目は、1ページの準備で設定する環境変数をそのまま記載しています。`RAG_RUN_ID`を含む名前は、表示例と実際の値が異なります。

## 読み方

| 表記 | 意味 |
|---|---|
| `RAG_...` | 1. AWS CLI実行環境を準備するページで設定・保存する環境変数 |
| `${RAG_RUN_ID}` | UTC時刻と6桁のランダムな16進数からなる実行識別子 |
| 「CLI指定値」 | `create-*`、`put-*`などの作成コマンドで明示する値 |
| 「確認値」 | `get-*`などの結果確認で一致を確認する値。サービス側の既定値を含む |
| 「生成値」 | AWSが作成時に返し、state fileへ保存するIDやARN |

## 共通パラメータ

| 項目 | CLI変数 | 値・形式 | 用途 |
|---|---|---|---|
| AWSリージョン | `AWS_REGION` / `AWS_DEFAULT_REGION` | `ap-northeast-1` | S3、S3 Vectors、BedrockのAPI呼び出しを東京リージョンに統一 |
| AWSアカウント | `RAG_ACCOUNT_ID` | `aws sts get-caller-identity`の`Account`（12桁） | バケット名、ARN、trust policyの条件 |
| 実行識別子 | `RAG_RUN_ID` | `$(date -u +%m%d%H%M%S)-$(openssl rand -hex 3)` | 同じアカウントで複数人が実施しても名前を分離 |
| 作業ディレクトリ | `RAG_WORK_DIR` | `$HOME/rag-handson-${RAG_RUN_ID}` | PDF、JSON、結果、state fileの保存先 |
| 状態ファイル | `RAG_STATE_FILE` | `$RAG_WORK_DIR/state.env` | 作成後のARN・IDを保存し、後続ページとCleanupで復元 |
| 原文書URL | `RAG_DOCUMENT_URL` | `https://docs.aws.amazon.com/ja_jp/prescriptive-guidance/latest/retrieval-augmented-generation-options/retrieval-augmented-generation-options.pdf` | `curl`で取得する検索対象 |
| 原文書パス | `RAG_DOCUMENT_PATH` | `$RAG_WORK_DIR/documents/aws-rag-options-and-architectures.pdf` | 取得したPDFのローカルパス |
| 埋め込みモデル | `RAG_EMBED_MODEL_ID` | `amazon.titan-embed-text-v2:0` | Knowledge Baseのベクトル化 |
| 生成モデル | `RAG_GENERATION_MODEL_ID` | `amazon.nova-lite-v1:0` | `Converse`による回答生成 |
| 生成モデルARN | `RAG_GENERATION_MODEL_ARN` | `arn:aws:bedrock:${AWS_REGION}::foundation-model/${RAG_GENERATION_MODEL_ID}` | `RetrieveAndGenerate`の`modelArn` |

Knowledge Base、data source、ingestion jobのIDはAWSが生成します。作成後のIDを一覧から推測せず、各ページのコマンドで返された値を`RAG_STATE_FILE`へ保存して次の操作に渡します。

## 1. S3ソースバケットとオブジェクト

### バケット

| 設定項目 | CLI指定値 | 確認値・補足 |
|---|---|---|
| バケット名 | `--bucket "$RAG_SOURCE_BUCKET"` | `rag-handson-${RAG_ACCOUNT_ID}-${RAG_RUN_ID}` |
| リージョン | `--region "$AWS_REGION"` | `ap-northeast-1` |
| Location constraint | `--create-bucket-configuration "LocationConstraint=$AWS_REGION"` | `ap-northeast-1` |
| Public Access Block | `BlockPublicAcls=true`; `IgnorePublicAcls=true`; `BlockPublicPolicy=true`; `RestrictPublicBuckets=true` | 4項目すべて`true` |
| バケットポリシー | 指定なし | ソースバケットは公開せず、Knowledge Base roleのS3読み取りだけをIAMで許可 |

作成コマンドは次の設定に対応します。

```bash
aws s3api create-bucket \
  --bucket "$RAG_SOURCE_BUCKET" \
  --region "$AWS_REGION" \
  --create-bucket-configuration "LocationConstraint=$AWS_REGION"

aws s3api put-public-access-block \
  --bucket "$RAG_SOURCE_BUCKET" \
  --public-access-block-configuration \
    'BlockPublicAcls=true,IgnorePublicAcls=true,BlockPublicPolicy=true,RestrictPublicBuckets=true'
```

### 配置するオブジェクト

| オブジェクト | S3キー | 内容 |
|---|---|---|
| PDF | `documents/aws-rag-options-and-architectures.pdf` | `RAG_DOCUMENT_URL`から`curl`で取得した日本語PDF |
| メタデータ | `documents/aws-rag-options-and-architectures.pdf.metadata.json` | `source_url`、`retrieved_at`、`category=rag-guidance`、`status=published`、`language=ja`を持つsidecar metadata |
| 取り込み対象 | `documents/` | Knowledge Base data sourceの`inclusionPrefixes`で指定するprefix |

PDFのバイト数とSHA-256は実行ごとに変わり得るため、固定値として扱いません。手順ページの結果確認で、PDF形式、1 MiB超50 MiB未満、S3上の`ContentLength`一致を確認します。

## 2. S3 Vectors

### vector bucket

| 設定項目 | CLI指定値 | 確認値・補足 |
|---|---|---|
| vector bucket名 | `--vector-bucket-name "$RAG_VECTOR_BUCKET"` | `rag-handson-vectors-${RAG_ACCOUNT_ID}-${RAG_RUN_ID}` |
| リージョン | `--region "$AWS_REGION"` | `ap-northeast-1` |
| 暗号化 | CLIで指定しない | `get-vector-bucket`の確認値は`AES256` |
| ARN | 生成値 | `RAG_VECTOR_BUCKET_ARN`へ保存 |

### vector index

| 設定項目 | CLI指定値 | 確認値・補足 |
|---|---|---|
| index名 | `--index-name "$RAG_INDEX_NAME"` | `rag-titan-v2-1024` |
| データ型 | `--data-type float32` | `float32` |
| 次元数 | `--dimension 1024` | Titan Text Embeddings V2の1024次元と一致 |
| 距離指標 | `--distance-metric cosine` | `cosine` |
| 非フィルタ可能metadata key | `AMAZON_BEDROCK_TEXT`、`AMAZON_BEDROCK_METADATA` | 2つを`nonFilterableMetadataKeys`へ指定 |
| ARN | 生成値 | `RAG_INDEX_ARN`へ保存 |
| 検索方式 | CLIのindex設定ではなく構成上の前提 | S3 Vectorsをdense semantic searchの基準構成として使用。HYBRID検索は指定しない |

作成時のindex設定は次のJSONです。

```bash
aws s3vectors create-index \
  --vector-bucket-name "$RAG_VECTOR_BUCKET" \
  --index-name "$RAG_INDEX_NAME" \
  --data-type float32 \
  --dimension 1024 \
  --distance-metric cosine \
  --metadata-configuration \
    '{"nonFilterableMetadataKeys":["AMAZON_BEDROCK_TEXT","AMAZON_BEDROCK_METADATA"]}' \
  --region "$AWS_REGION"
```

## 3. IAM service role、inline policy、vector bucket policy

### service roleとtrust policy

| 設定項目 | CLI指定値 | 確認値・補足 |
|---|---|---|
| role名 | `--role-name "$RAG_ROLE_NAME"` | `BedrockKnowledgeBaseRole-${RAG_RUN_ID}` |
| 説明 | `Amazon Bedrock Knowledge Bases role for RAG hands-on ${RAG_RUN_ID}` | Knowledge Baseが使うservice role |
| Principal | `bedrock.amazonaws.com` | Bedrock Knowledge Basesだけが引き受ける |
| AssumeRole action | `sts:AssumeRole` | trust policyで許可 |
| Source account条件 | `aws:SourceAccount = RAG_ACCOUNT_ID` | 実習アカウントに限定 |
| Source ARN条件 | `arn:aws:bedrock:${AWS_REGION}:${RAG_ACCOUNT_ID}:knowledge-base/*` | 東京リージョンのKnowledge Baseに限定 |

### Knowledge Base roleのinline policy

| SID | Action | Resource | 条件・目的 |
|---|---|---|---|
| `InvokeEmbeddingModel` | `bedrock:InvokeModel` | `arn:aws:bedrock:${AWS_REGION}::foundation-model/${RAG_EMBED_MODEL_ID}` | Titan Text Embeddings V2だけを呼び出す |
| `ListSourceBucket` | `s3:ListBucket` | `arn:aws:s3:::${RAG_SOURCE_BUCKET}` | source bucketの一覧取得。`aws:ResourceAccount = RAG_ACCOUNT_ID` |
| `ReadSourceDocuments` | `s3:GetObject` | `arn:aws:s3:::${RAG_SOURCE_BUCKET}/documents/*` | `documents/`配下のPDF・metadataを読む。`aws:ResourceAccount = RAG_ACCOUNT_ID` |
| `ReadWriteVectorIndex` | `s3vectors:PutVectors`、`GetVectors`、`DeleteVectors`、`QueryVectors`、`GetIndex` | `RAG_INDEX_ARN` | Knowledge Baseが同じindexへ取り込み・検索する |

inline policy名は`BedrockKnowledgeBasePolicy-${RAG_RUN_ID}`です。managed policy ARNは作成せず、`put-role-policy`でこのroleにinline policyを設定します。

### S3 Vectors bucket policy

| 設定項目 | 値 |
|---|---|
| 設定対象 | `RAG_VECTOR_BUCKET` |
| Principal | `RAG_ROLE_ARN` |
| Action | `s3vectors:PutVectors`、`GetVectors`、`DeleteVectors`、`QueryVectors`、`GetIndex` |
| Resource | `RAG_INDEX_ARN` |
| 設定CLI | `aws s3vectors put-vector-bucket-policy --vector-bucket-name "$RAG_VECTOR_BUCKET" --policy file://$RAG_WORK_DIR/vector-bucket-policy.json` |

## 4. Amazon Bedrock Knowledge Base

| 設定項目 | CLI入力JSONの値 | 確認値・補足 |
|---|---|---|
| Knowledge Base名 | `RAG_KB_NAME` | `rag-handson-kb-${RAG_RUN_ID}` |
| 説明 | `RAG hands-on knowledge base` | 作成時の説明。AWS CLI版ではこの文字列を使用 |
| service role | `RAG_ROLE_ARN` | 4で作成したrole |
| Knowledge Base type | `VECTOR` | ベクトル検索用Knowledge Base |
| embedding model ARN | `arn:aws:bedrock:${AWS_REGION}::foundation-model/${RAG_EMBED_MODEL_ID}` | `amazon.titan-embed-text-v2:0` |
| embedding次元数 | `1024` | indexのdimensionと一致 |
| embeddingデータ型 | `FLOAT32` | indexの`float32`と一致 |
| storage type | `S3_VECTORS` | 既存のS3 Vectorsへ接続 |
| vector bucket ARN | `RAG_VECTOR_BUCKET_ARN` | 3で作成したvector bucket |
| index ARN | `RAG_INDEX_ARN` | 3で作成した同じindex |
| 生成ID | AWSが返す値 | `RAG_KB_ID`へ保存。例：`RQVIZHNFAN` |

Knowledge Base作成時の重要な境界は、Knowledge Basesが取り込み・chunk化・embedding・vector登録を担当し、回答生成は後の`Converse`で呼び出し元が行うことです。

## 5. Knowledge Base data source

| 設定項目 | CLI入力JSONの値 | 確認値・補足 |
|---|---|---|
| data source名 | `RAG_DS_NAME` | `rag-handson-s3-${RAG_RUN_ID}` |
| 説明 | `S3 documents for RAG hands-on` | 作成時の説明 |
| data source type | `S3` | source bucketを参照 |
| bucket ARN | `arn:aws:s3:::${RAG_SOURCE_BUCKET}` | 2で作成したS3ソースバケット |
| inclusion prefix | `documents/` | PDFとsidecar metadataだけを取り込み |
| data deletion policy | `DELETE` | data source削除時に取り込みデータも削除 |
| chunking strategy | `FIXED_SIZE` | 固定長chunkingのbaseline |
| max tokens | `300` | chunkあたりの最大token数 |
| overlap percentage | `10` | 隣接chunkの重複率 |
| 生成ID | AWSが返す値 | `RAG_DS_ID`へ保存。例：`H63CPNRSM9` |

## 6. ingestion job

ingestion jobは長期保存する構成リソースではなく、data sourceをKnowledge Baseへ取り込むための実行単位です。ただし、CLIで作成してIDを取得するため、パラメータシートに含めます。

| 設定項目 | CLI指定値 | 確認値・補足 |
|---|---|---|
| リージョン | `--region "$AWS_REGION"` | `ap-northeast-1` |
| Knowledge Base | `--knowledge-base-id "$RAG_KB_ID"` | 5で生成したID |
| data source | `--data-source-id "$RAG_DS_ID"` | 5で生成したID |
| 説明 | `Initial sync for RAG hands-on ${RAG_RUN_ID}` | 同じrunの取り込みであることを識別 |
| 初期status | AWSが返す値 | `STARTING`または`IN_PROGRESS` |
| 終了status | 検証条件 | `COMPLETE`。`FAILED`や`STOPPED`では次へ進まない |
| 生成ID | AWSが返す値 | `RAG_INGESTION_JOB_ID`へ保存 |

## 作成しないもの

次のAPIはAWSリソースを新規作成せず、作成済みのKnowledge Baseやモデルを利用します。リソースの設定値とAPI実行時の入力値を混同しないように分けて扱います。

| API | このハンズオンでの入力値 | 役割 |
|---|---|---|
| `Retrieve` | `RAG_KB_ID`、検索方式`SEMANTIC`、候補数`1 / 3 / 5`（比較時） | S3 Vectorsから検索結果、score、source URI、metadataを取得 |
| `Converse` | `RAG_GENERATION_MODEL_ID`、`maxTokens=400`、`temperature=0.1`、`topP=0.9` | Retrieveで作ったEvidence Setを使って回答を生成 |
| `RetrieveAndGenerate` | `RAG_KB_ID`、`RAG_GENERATION_MODEL_ARN`、検索方式`SEMANTIC`、候補数`5` | 9章でRetrieveと生成を一つのAPIで実行 |

## 作成後にstate fileへ保存する値

| 変数 | 生成元 | 後続で使う場所 |
|---|---|---|
| `RAG_VECTOR_BUCKET_ARN` | `get-vector-bucket` | Knowledge Base、Cleanup |
| `RAG_INDEX_ARN` | `get-index` | role policy、bucket policy、Knowledge Base、Retrieve、Cleanup |
| `RAG_ROLE_ARN` | `get-role` | Knowledge Base、vector bucket policy |

## 最終確認

このページの設定と実際の作成結果が一致していることを、次の値で確認します。

- [ ] リージョンが`ap-northeast-1`
- [ ] S3ソースバケット名とS3 Vectors vector bucket名が`RAG_ACCOUNT_ID`と`RAG_RUN_ID`を含む
- [ ] S3ソースバケットのPublic Access Block 4項目がすべて`true`
- [ ] S3 Vectors indexが`float32 / 1024 / cosine`
- [ ] Knowledge Baseが`ACTIVE`で、storage typeが`S3_VECTORS`
- [ ] data sourceが`AVAILABLE`で、`documents/`・`DELETE`・`FIXED_SIZE / 300 / 10`
- [ ] ingestion jobが`COMPLETE`

実際のAWSリソースが不要になったら、[10. リソースを削除する](/rag-guide/10-cleanup/)を実行し、S3、S3 Vectors、Knowledge Base、data source、IAM roleが残っていないことを確認してください。
