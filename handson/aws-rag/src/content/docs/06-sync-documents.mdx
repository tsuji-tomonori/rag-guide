同期は、PDFのRAG 4ステップのうち「文書をチャンク化・埋め込みしてベクトルデータベースへ取り込む」段階です。成功は「APIが受け付けた」だけでは判定しません。job終端状態、statistics、可能なら文書単位の状態、vector indexを分けて確認します。ここで確認するのは取り込みの成功であり、質問に対する根拠の関連性や回答の正しさは7〜9章で別に判定します。ターミナルセッションが途中で切り替わっても別の受講者のresourceを誤って使わないよう、このrunで保存したIDとARNを復元してから進めます。

## 手順 6.1. 状態と取り込み前提を検証してジョブを開始する

<CliStep number="6.1" title="状態と取り込み前提を検証してジョブを開始する">

ターミナルを開き直した場合は、最初にこのrunのstate fileを読み戻します。

<Command phase="prepare" title="現在のrunを復元して必須変数を準備">

```bash
if [ -f "$HOME/.rag-handson-current" ]; then
  source "$HOME/.rag-handson-current"
fi

: "${AWS_REGION:?AWS_REGION is not set}"
: "${RAG_RUN_ID:?RAG_RUN_ID is not set}"
: "${RAG_WORK_DIR:?RAG_WORK_DIR is not set}"
: "${RAG_STATE_FILE:?RAG_STATE_FILE is not set}"
: "${RAG_KB_ID:?RAG_KB_ID is not set}"
: "${RAG_DS_ID:?RAG_DS_ID is not set}"
: "${RAG_INDEX_ARN:?RAG_INDEX_ARN is not set}"

export RAG_ROLE_ARN="$(aws iam get-role \
  --role-name "$RAG_ROLE_NAME" \
  --query 'Role.Arn' \
  --output text)"

printf '[CHECK] ingestion variables: READY (region=%s run=%s kb=%s ds=%s index=%s)\n' \
  "$AWS_REGION" "$RAG_RUN_ID" "$RAG_KB_ID" "$RAG_DS_ID" "$RAG_INDEX_ARN"
printf 'ingestion variables verification: PASS\n'
```

</Command>

<ExpectedResult id="s6-1-state" verification="現在のrunを復元して必須変数を準備">

次の2行が表示されれば成功です。state fileから復元できること自体は成功条件にせず、取り込みに必要な5つの値が現在そろっていることだけを確認します。

```text
[CHECK] ingestion variables: READY (region=ap-northeast-1 run=0816071530-a41f92 kb=RQVIZHNFAN ds=H63CPNRSM9 index=arn:aws:s3vectors:...)
ingestion variables verification: PASS
```

- `[CHECK] ingestion variables: READY`が表示される
- `ingestion variables verification: PASS`が表示される

</ExpectedResult>

まず、Knowledge Baseが4章で作成したservice roleを使っていることと、ingestionに必要な4系統の権限が実際にroleへ付与されていることを確認します。

<Command phase="verify" title="ナレッジベースのロールと取り込み権限を事前検証">

```bash
export RAG_EXPECTED_EMBED_MODEL_ARN="arn:aws:bedrock:${AWS_REGION}::foundation-model/${RAG_EMBED_MODEL_ID}"
export RAG_EXPECTED_SOURCE_BUCKET_ARN="arn:aws:s3:::${RAG_SOURCE_BUCKET}"
export RAG_EXPECTED_SOURCE_OBJECT_ARN="arn:aws:s3:::${RAG_SOURCE_BUCKET}/documents/*"

export RAG_KB_ROLE_ARN="$(aws bedrock-agent get-knowledge-base \
  --region "$AWS_REGION" \
  --knowledge-base-id "$RAG_KB_ID" \
  --query 'knowledgeBase.roleArn' \
  --output text)"

test "$RAG_KB_ROLE_ARN" = "$RAG_ROLE_ARN"

aws iam get-role-policy \
  --role-name "$RAG_ROLE_NAME" \
  --policy-name "$RAG_POLICY_NAME" \
  --query 'PolicyDocument' \
  --output json \
  | tee "$RAG_WORK_DIR/bedrock-kb-policy-readback.json" >/dev/null

jq -e \
  --arg modelArn "$RAG_EXPECTED_EMBED_MODEL_ARN" \
  --arg bucketArn "$RAG_EXPECTED_SOURCE_BUCKET_ARN" \
  --arg objectArn "$RAG_EXPECTED_SOURCE_OBJECT_ARN" \
  --arg indexArn "$RAG_INDEX_ARN" '
  def actions: (.Action | if type == "array" then . else [.] end);
  any(.Statement[]; .Effect == "Allow" and (actions | index("bedrock:InvokeModel")) and .Resource == $modelArn)
  and any(.Statement[]; .Effect == "Allow" and (actions | index("s3:ListBucket")) and .Resource == $bucketArn)
  and any(.Statement[]; .Effect == "Allow" and (actions | index("s3:GetObject")) and .Resource == $objectArn)
  and any(.Statement[];
    .Effect == "Allow"
    and .Resource == $indexArn
    and (actions | index("s3vectors:PutVectors"))
    and (actions | index("s3vectors:GetVectors"))
    and (actions | index("s3vectors:DeleteVectors"))
    and (actions | index("s3vectors:QueryVectors"))
    and (actions | index("s3vectors:GetIndex")))
' "$RAG_WORK_DIR/bedrock-kb-policy-readback.json" >/dev/null

printf '[CHECK] Knowledge Base role: MATCH (%s)\n' "$RAG_KB_ROLE_ARN"
printf '[CHECK] ingestion permissions: embedding / S3 source / vector index\n'
printf 'ingestion preflight: PASS\n'
```

</Command>

<ExpectedResult id="s6-1-preflight" verification="ナレッジベースのロールと取り込み権限を事前検証">

次の3行が表示されれば成功です。

```text
[CHECK] Knowledge Base role: MATCH (arn:aws:iam::123456789012:role/BedrockKnowledgeBaseRole-0816071530-a41f92)
[CHECK] ingestion permissions: embedding / S3 source / vector index
ingestion preflight: PASS
```

- `[CHECK] Knowledge Base role: MATCH`が表示される
- `[CHECK] ingestion permissions: embedding / S3 source / vector index`が表示される
- `ingestion preflight: PASS`が表示される

</ExpectedResult>

<Aside type="caution" title="事前検証で失敗した場合">
  4章のpermissions policyを再生成・再適用してから、このpreflightを再実行してください。特に`s3:ListBucket`がない場合、ingestion jobはS3 documentをscanする前に403で`FAILED`になります。すでに`FAILED`になったjobは再開せず、権限修正後にこの6.1から新しいingestion jobを開始します。
</Aside>

<Command phase="execute" title="取り込みジョブを開始してIDを保存">

```bash
aws bedrock-agent start-ingestion-job \
  --region "$AWS_REGION" \
  --knowledge-base-id "$RAG_KB_ID" \
  --data-source-id "$RAG_DS_ID" \
  --description "Initial sync for RAG hands-on $RAG_RUN_ID" \
  | tee "$RAG_WORK_DIR/start-ingestion-output.json"

export RAG_INGESTION_JOB_ID="$(jq -r '.ingestionJob.ingestionJobId' "$RAG_WORK_DIR/start-ingestion-output.json")"
test "${#RAG_INGESTION_JOB_ID}" -eq 10

export RAG_INITIAL_INGESTION_STATUS="$(jq -r '.ingestionJob.status' \
  "$RAG_WORK_DIR/start-ingestion-output.json")"
case "$RAG_INITIAL_INGESTION_STATUS" in
  STARTING|IN_PROGRESS) ;;
  *)
    printf 'ERROR: unexpected initial ingestion status: %s\n' \
      "$RAG_INITIAL_INGESTION_STATUS" >&2
    exit 1
    ;;
esac

declare -p RAG_INGESTION_JOB_ID >> "$RAG_STATE_FILE"
grep -Fq 'RAG_INGESTION_JOB_ID' "$RAG_STATE_FILE"

printf '[CHECK] ingestion job ID saved to state file: %s\n' "$RAG_INGESTION_JOB_ID"
printf '[CHECK] initial ingestion status: %s\n' "$RAG_INITIAL_INGESTION_STATUS"
printf 'ingestion start verification: PASS\n'
```

</Command>

<ExpectedResult id="s6-1-start" verification="取り込みジョブを開始してIDを保存">

次の3行が表示されれば成功です。初期statusには`STARTING`または`IN_PROGRESS`の実値が表示されます。

```text
[CHECK] ingestion job ID saved to state file: TW6ZYORG1P
[CHECK] initial ingestion status: STARTING
ingestion start verification: PASS
```

- `[CHECK] ingestion job ID saved to state file:`が表示される
- `[CHECK] initial ingestion status:`に`STARTING`または`IN_PROGRESS`が表示される
- `ingestion start verification: PASS`が表示される

</ExpectedResult>

</CliStep>

## 手順 6.2. 終端状態まで監視する

<CliStep number="6.2" title="終端状態まで監視する">

AWS CLIの既定Regionに依存せず、各API callでこのrunの`AWS_REGION`を明示します。

<Command phase="verify" title="終端状態まで監視する" final>

```bash
for attempt in {1..80}; do
  RAG_INGESTION_STATUS="$(aws bedrock-agent get-ingestion-job \
    --region "$AWS_REGION" \
    --knowledge-base-id "$RAG_KB_ID" \
    --data-source-id "$RAG_DS_ID" \
    --ingestion-job-id "$RAG_INGESTION_JOB_ID" \
    --query 'ingestionJob.status' \
    --output text)"
  printf '[%02d/80] ingestion status: %s\n' "$attempt" "$RAG_INGESTION_STATUS"
  case "$RAG_INGESTION_STATUS" in
    COMPLETE) break ;;
    FAILED|STOPPED)
      aws bedrock-agent get-ingestion-job \
        --region "$AWS_REGION" \
        --knowledge-base-id "$RAG_KB_ID" \
        --data-source-id "$RAG_DS_ID" \
        --ingestion-job-id "$RAG_INGESTION_JOB_ID" \
        --query 'ingestionJob.{status:status,statistics:statistics,failures:failureReasons}' \
        --output yaml
      exit 1
      ;;
  esac
  sleep 15
done

test "$RAG_INGESTION_STATUS" = "COMPLETE"

printf '[CHECK] ingestion status: %s\n' "$RAG_INGESTION_STATUS"
printf 'ingestion monitoring: PASS\n'
```

</Command>

<ExpectedResult id="s6-2-ingestion" verification="終端状態まで監視する">

次の2行が表示されれば成功です。`FAILED`または`STOPPED`ではコマンドが終了し、この表示には到達しません。

```text
[CHECK] ingestion status: COMPLETE
ingestion monitoring: PASS
```

- `[CHECK] ingestion status: COMPLETE`が表示される
- `ingestion monitoring: PASS`が表示される

</ExpectedResult>

</CliStep>

## 手順 6.3. 同期結果を多層で検証する

<CliStep number="6.3" title="同期結果を多層で検証する">

<Command phase="verify" title="ジョブ統計を確認">

```bash
aws bedrock-agent get-ingestion-job \
  --region "$AWS_REGION" \
  --knowledge-base-id "$RAG_KB_ID" \
  --data-source-id "$RAG_DS_ID" \
  --ingestion-job-id "$RAG_INGESTION_JOB_ID" \
  --output json \
  | tee "$RAG_WORK_DIR/ingestion-final.json" >/dev/null
```

</Command>

<Command phase="verify" title="文書単位の状態を確認（権限がある場合）">

```bash
if aws bedrock-agent list-knowledge-base-documents \
  --region "$AWS_REGION" \
  --knowledge-base-id "$RAG_KB_ID" \
  --data-source-id "$RAG_DS_ID" \
  --output json \
  > "$RAG_WORK_DIR/knowledge-base-documents.json" \
  2> "$RAG_WORK_DIR/knowledge-base-documents.err"; then
  jq -e '
    (.documentDetails | length) > 0 and
    all(.documentDetails[]; .status == "INDEXED")
  ' "$RAG_WORK_DIR/knowledge-base-documents.json" >/dev/null
  export RAG_DOCUMENT_CHECK="INDEXED"
elif grep -q 'AccessDeniedException' "$RAG_WORK_DIR/knowledge-base-documents.err"; then
  export RAG_DOCUMENT_CHECK="SKIPPED (caller lacks bedrock:ListKnowledgeBaseDocuments)"
else
  cat "$RAG_WORK_DIR/knowledge-base-documents.err" >&2
  exit 1
fi
```

</Command>

<Aside type="note" title="ListKnowledgeBaseDocumentsは実行者側の追加権限です">
  ingestionで使うKnowledge Base service roleの権限とは別に、この確認コマンドを実行するcallerには`bedrock:ListKnowledgeBaseDocuments`が必要です。実習環境のpermission setや組織ポリシーで許可されていない場合、この確認だけをskipできます。jobの`COMPLETE`とvector登録確認は引き続き必須です。
</Aside>

<Command phase="verify" title="ベクトルが登録されたことを確認" final>

```bash
if [ -z "${RAG_INDEX_ARN:-}" ]; then
  export RAG_INDEX_ARN="$(aws s3vectors get-index \
    --region "$AWS_REGION" \
    --vector-bucket-name "$RAG_VECTOR_BUCKET" \
    --index-name "$RAG_INDEX_NAME" \
    --query 'index.indexArn' \
    --output text)"
fi

test -n "$RAG_INDEX_ARN"

jq -e '
  .ingestionJob.status == "COMPLETE" and
  ((.ingestionJob.failureReasons // []) | length) == 0
' "$RAG_WORK_DIR/ingestion-final.json" >/dev/null

aws s3vectors list-vectors \
  --region "$AWS_REGION" \
  --index-arn "$RAG_INDEX_ARN" \
  --max-items 20 \
  --return-metadata \
  --output json \
  | tee "$RAG_WORK_DIR/indexed-vectors.json" >/dev/null

export RAG_VECTOR_COUNT="$(jq '.vectors | length' \
  "$RAG_WORK_DIR/indexed-vectors.json")"
test "$RAG_VECTOR_COUNT" -ge 1
: "${RAG_DOCUMENT_CHECK:?Run the document-level status command first}"

printf '[CHECK] ingestion job status: COMPLETE\n'
printf '[CHECK] failure reasons: NONE\n'
printf '[CHECK] document status: %s\n' "$RAG_DOCUMENT_CHECK"
printf '[CHECK] indexed vectors: %s (>= 1)\n' "$RAG_VECTOR_COUNT"
printf 'sync verification: PASS\n'
```

</Command>

<ExpectedResult id="s6-3-sync" verification="ベクトルが登録されたことを確認">

次の5行が表示されれば成功です。文書一覧の権限がない場合だけ、document statusは`SKIPPED`になります。

```text
[CHECK] ingestion job status: COMPLETE
[CHECK] failure reasons: NONE
[CHECK] document status: INDEXED
[CHECK] indexed vectors: 20 (>= 1)
sync verification: PASS
```

- `[CHECK] ingestion job status: COMPLETE`が表示される
- `[CHECK] failure reasons: NONE`が表示される
- `[CHECK] document status:`に`INDEXED`または権限不足による`SKIPPED`が表示される
- `[CHECK] indexed vectors:`に`1`以上の件数が表示される
- `sync verification: PASS`が表示される

</ExpectedResult>

<Aside type="note" title="1 PDF = 1ベクトルではありません">
  Knowledge Basesは長いPDFを多数のchunkへ分割してからembeddingします。同期確認では「vector数が文書数と同じ」を条件にせず、job statistics、可能ならdocument status、vectorの存在を分けて検証します。`list-vectors --max-items 20`の`count`は全vector数ではなく、取得した先頭pageの件数です。
</Aside>

</CliStep>

<Checkpoint>

- Knowledge Baseが4章で作成したservice roleを使用している
- service roleに`s3:ListBucket`、`s3:GetObject`、`bedrock:InvokeModel`、S3 Vectors必要権限がある
- ingestion jobは`COMPLETE`である
- failure reasonがない
- 文書一覧確認はcaller権限がある場合に`INDEXED`を確認した
- vector indexに1件以上のvectorがある

</Checkpoint>
