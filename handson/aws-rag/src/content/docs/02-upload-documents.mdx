数行の自作文書ではなく、AWSが公開している日本語版 **AWSのRAGオプションとアーキテクチャ** PDFを検索対象にします。複数ページにまたがる実文書を使うことで、PDF解析、chunk分割、複数candidateのscoreと本文を実際に観察できます。

<CliStep number="2.1" title="AWS公式PDFをcurlで取得する">

AWS Docsの`latest` URLからPDFを取得します。途中で切れたファイルを完成品として扱わないよう、`.part`へ保存してからrenameします。

<Command phase="execute" title="AWS公式PDFを取得">

```bash
curl --fail --location \
  --retry 3 --retry-all-errors \
  --connect-timeout 20 --max-time 300 \
  --output "$RAG_DOCUMENT_PATH.part" \
  --write-out 'downloaded=%{size_download} bytes\ncontent_type=%{content_type}\nurl=%{url_effective}\n' \
  "$RAG_DOCUMENT_URL"

mv "$RAG_DOCUMENT_PATH.part" "$RAG_DOCUMENT_PATH"
```

</Command>

<Command phase="verify" title="PDFの形式とサイズを検証" final>

```bash
test "$(head -c 5 "$RAG_DOCUMENT_PATH")" = "%PDF-"

export RAG_PDF_BYTES="$(wc -c < "$RAG_DOCUMENT_PATH")"
test "$RAG_PDF_BYTES" -gt 1048576
test "$RAG_PDF_BYTES" -lt 50000000

printf 'PDF bytes: %s\n' "$RAG_PDF_BYTES"
sha256sum "$RAG_DOCUMENT_PATH" \
  | tee "$RAG_WORK_DIR/aws-rag-options-and-architectures.sha256"
```

</Command>

<ExpectedResult id="s2-1-pdf" verification="PDFの形式とサイズを検証">

- `curl`がHTTP errorなしで完了し、最終URLとdownload byte数を表示します。
- 先頭5 byteが`%PDF-`です。HTMLのerror pageを誤って保存した場合はここで停止します。
- file sizeは1 MiBより大きく、Knowledge Basesの1 fileあたりの上限である50 MB未満です。SHA-256 digestも記録されます。

```text
downloaded=6843210 bytes
content_type=application/pdf
url=https://docs.aws.amazon.com/ja_jp/wellarchitected/latest/framework/wellarchitected-framework.pdf
PDF bytes: 6843210
9f2c...  $HOME/rag-handson-0816071530-a41f92/documents/aws-rag-options-and-architectures.pdf
```

- `content_type=application/pdf`と`PDF bytes:`が表示される
- `PDF bytes`が1 MiBより大きく、50 MB未満である
- SHA-256ファイルが作成される

</ExpectedResult>

<Aside type="note" title="最新版は将来更新されます">
  このハンズオンでは、AWSの現行文書を試すため`latest`を使います。そのため取得時期によってfile size、hash、ページ内容が変わる場合があります。本番評価で同じcorpusを再現する場合は、取得日、hash、S3 Version IDを固定してください。
</Aside>

</CliStep>

<CliStep number="2.2" title="出典メタデータを作成する">

Amazon Bedrock Knowledge Basesは、`元ファイル名.metadata.json`というsidecar fileからmetadata属性を取り込みます。出典URL、取得日、文書種別を検索結果へ引き継ぎます。

<Command phase="prepare" title="出典メタデータを準備">

```bash
export RAG_RETRIEVED_AT="$(date -u +%Y-%m-%dT%H:%M:%SZ)"

jq -n \
  --arg sourceUrl "$RAG_DOCUMENT_URL" \
  --arg retrievedAt "$RAG_RETRIEVED_AT" \
  '{
    metadataAttributes:{
      category:"rag-guidance",
      status:"published",
      language:"ja",
      source_title:"AWSのRAGオプションとアーキテクチャ",
      source_url:$sourceUrl,
      retrieved_at:$retrievedAt
    }
  }' | tee "$RAG_DOCUMENT_PATH.metadata.json"
```

</Command>

<Command phase="verify" title="メタデータJSONを検証" final>

```bash
jq -e '
  .metadataAttributes.category == "framework" and
  .metadataAttributes.status == "published" and
  .metadataAttributes.language == "ja" and
  (.metadataAttributes.source_url | startswith("https://docs.aws.amazon.com/"))
' "$RAG_DOCUMENT_PATH.metadata.json" >/dev/null

test "$(wc -c < "$RAG_DOCUMENT_PATH.metadata.json")" -lt 10240
```

</Command>

<ExpectedResult id="s2-2-metadata" verification="メタデータJSONを検証">

`jq`とsize検査がエラーなく終了します。metadata fileは10 KiB未満で、AWS公式URLと取得時刻を含みます。

```json
{
  "metadataAttributes": {
    "category": "framework",
    "status": "published",
    "language": "ja",
    "source_title": "AWS Well-Architected Framework",
    "source_url": "https://docs.aws.amazon.com/ja_jp/...",
    "retrieved_at": "2026-08-16T12:00:00Z"
  }
}
```

- `category=rag-guidance`、`status=published`、`language=ja`が確認できる
- `source_url`がAWS公式URLである
- metadata fileが10 KiB未満である

</ExpectedResult>

</CliStep>

<CliStep number="2.3" title="S3バケットを作成してアップロードする">

<Command phase="execute" title="S3バケットを作成してアップロード">

```bash
aws s3api create-bucket \
  --bucket "$RAG_SOURCE_BUCKET" \
  --region "$AWS_REGION" \
  --create-bucket-configuration "LocationConstraint=$AWS_REGION"

aws s3api put-public-access-block \
  --bucket "$RAG_SOURCE_BUCKET" \
  --public-access-block-configuration \
    'BlockPublicAcls=true,IgnorePublicAcls=true,BlockPublicPolicy=true,RestrictPublicBuckets=true'

aws s3 cp "$RAG_WORK_DIR/documents" "s3://$RAG_SOURCE_BUCKET/documents/" --recursive
```

</Command>

<Command phase="verify" title="バケットとオブジェクトを検証" final>

```bash
aws s3api get-bucket-location \
  --bucket "$RAG_SOURCE_BUCKET" \
  --query LocationConstraint \
  --output text

aws s3api get-public-access-block \
  --bucket "$RAG_SOURCE_BUCKET" \
  --query 'PublicAccessBlockConfiguration' \
  --output table

aws s3api list-objects-v2 \
  --bucket "$RAG_SOURCE_BUCKET" \
  --prefix documents/ \
  --query '{count:KeyCount,objects:Contents[].{key:Key,size:Size}}' \
  --output table

test "$(aws s3api head-object \
  --bucket "$RAG_SOURCE_BUCKET" \
  --key documents/aws-rag-options-and-architectures.pdf \
  --query ContentLength --output text)" = "$RAG_PDF_BYTES"

printf '[CHECK] source bucket creation: COMPLETE (%s)\n' "$RAG_SOURCE_BUCKET"
printf '[CHECK] source objects uploaded: 2 (PDF + metadata)\n'
printf '[CHECK] PDF byte size: %s\n' "$RAG_PDF_BYTES"
printf 'upload verification: PASS\n'
```

</Command>

<ExpectedResult id="s2-3-s3" verification="バケットとオブジェクトを検証">

- locationは`ap-northeast-1`です。
- 4つのpublic access block設定がすべて`True`です。
- `count`は`2`で、PDFと対応するmetadata fileが表示されます。
- local PDFとS3 objectのbyte数が一致し、最後の`test`が成功します。

```text
location: ap-northeast-1
BlockPublicAcls       True
IgnorePublicAcls      True
BlockPublicPolicy     True
RestrictPublicBuckets True
[CHECK] source bucket creation: COMPLETE (rag-handson-123456789012-0816071530-a41f92)
[CHECK] source objects uploaded: 2 (PDF + metadata)
[CHECK] PDF byte size: 6843210
upload verification: PASS
```

- `[CHECK] source bucket creation: COMPLETE`が表示される
- `[CHECK] source objects uploaded: 2`が表示される
- public access blockが4項目とも`True`である
- PDFとmetadataの2 objectが存在し、byte数が一致する

</ExpectedResult>

</CliStep>
