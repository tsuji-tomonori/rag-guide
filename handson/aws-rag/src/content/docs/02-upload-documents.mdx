3つの短い文書と、それぞれに対応する`.metadata.json`を作ります。文書をあえて分けることで、検索結果の出典とmetadata filterを観察できます。

<CloudShellStep number="2.1" title="サンプル文書を作成する">

<Command>

```bash
tee "$RAG_WORK_DIR/documents/return-policy.txt" >/dev/null <<'EOF'
返品ポリシー

購入日から30日以内で、未使用かつ購入時の包装が残っている商品は返品できます。
返品を希望する場合は、注文番号を添えてサポート窓口へ連絡してください。
開封済みのソフトウェアとデジタル商品は返品対象外です。
EOF

tee "$RAG_WORK_DIR/documents/support.txt" >/dev/null <<'EOF'
サポート窓口

通常サポートの受付時間は、祝日を除く平日の日本時間9時から18時までです。
重大障害専用窓口はProプランの契約者に限り24時間利用できます。
問い合わせには契約IDと発生時刻を記載してください。
EOF

tee "$RAG_WORK_DIR/documents/plans.txt" >/dev/null <<'EOF'
サービスプラン

Standardプランの保存容量は10 GBです。
Proプランの保存容量は100 GBで、重大障害専用窓口を利用できます。
プラン変更は管理画面から申請し、翌請求期間から適用されます。
EOF
```

</Command>

<Command title="文書の内容を検証">

```bash
find "$RAG_WORK_DIR/documents" -maxdepth 1 -name '*.txt' -type f -print -exec wc -c {} \;
grep -R --line-number -E '30日|9時|100 GB' "$RAG_WORK_DIR/documents"
```

</Command>

<ExpectedResult>

3ファイルが表示され、`30日`、`9時`、`100 GB`を含む行がそれぞれ見つかります。

</ExpectedResult>

</CloudShellStep>

<CloudShellStep number="2.2" title="filter用metadataを作成する">

Amazon Bedrock Knowledge Basesは、`元ファイル名.metadata.json`というsidecar fileからmetadata属性を取り込みます。

<Command>

```bash
tee "$RAG_WORK_DIR/documents/return-policy.txt.metadata.json" >/dev/null <<'EOF'
{"metadataAttributes":{"category":"policy","status":"published","version":"2026-08"}}
EOF

tee "$RAG_WORK_DIR/documents/support.txt.metadata.json" >/dev/null <<'EOF'
{"metadataAttributes":{"category":"support","status":"published","version":"2026-08"}}
EOF

tee "$RAG_WORK_DIR/documents/plans.txt.metadata.json" >/dev/null <<'EOF'
{"metadataAttributes":{"category":"product","status":"published","version":"2026-08"}}
EOF
```

</Command>

<Command title="metadata JSONを検証">

```bash
for file in "$RAG_WORK_DIR"/documents/*.metadata.json; do
  jq -e '.metadataAttributes.category and .metadataAttributes.status and .metadataAttributes.version' "$file" >/dev/null
done
printf 'metadata files: %s\n' "$(find "$RAG_WORK_DIR/documents" -name '*.metadata.json' | wc -l)"
```

</Command>

<ExpectedResult>

`metadata files: 3`と表示され、`jq`のエラーがありません。

</ExpectedResult>

</CloudShellStep>

<CloudShellStep number="2.3" title="S3 bucketを作成してアップロードする">

<Command>

```bash
aws s3api create-bucket \
  --bucket "$RAG_SOURCE_BUCKET" \
  --region "$AWS_REGION" \
  --create-bucket-configuration "LocationConstraint=$AWS_REGION"

aws s3api put-public-access-block \
  --bucket "$RAG_SOURCE_BUCKET" \
  --public-access-block-configuration \
    'BlockPublicAcls=true,IgnorePublicAcls=true,BlockPublicPolicy=true,RestrictPublicBuckets=true'

aws s3 cp "$RAG_WORK_DIR/documents" "s3://$RAG_SOURCE_BUCKET/documents/" --recursive
```

</Command>

<Command title="bucketとobjectを検証">

```bash
aws s3api get-bucket-location \
  --bucket "$RAG_SOURCE_BUCKET" \
  --query LocationConstraint \
  --output text

aws s3api get-public-access-block \
  --bucket "$RAG_SOURCE_BUCKET" \
  --query 'PublicAccessBlockConfiguration' \
  --output table

aws s3api list-objects-v2 \
  --bucket "$RAG_SOURCE_BUCKET" \
  --prefix documents/ \
  --query '{count:KeyCount,objects:Contents[].{key:Key,size:Size}}' \
  --output table
```

</Command>

<ExpectedResult>

- locationは`ap-northeast-1`です。
- 4つのpublic access block設定がすべて`True`です。
- `count`は`6`で、3文書と3 metadata fileが表示されます。

</ExpectedResult>

<Aside type="tip" title="なぜmetadataを今付けるのか">
  後で`category=policy`を必須条件として検索します。score順の検索と業務上の必須条件を分けて扱うため、アクセス制御や公開状態のような条件をprompt任せにしません。
</Aside>

</CloudShellStep>

<Checkpoint>

- source bucketは東京リージョンにある
- public accessはすべてblockされている
- `documents/`配下に6 objectある
- 文書とmetadata fileが1対1で対応している

</Checkpoint>
