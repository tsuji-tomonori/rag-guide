数行の自作文書ではなく、AWSが公開している日本語版 **AWSのRAGオプションとアーキテクチャ** PDFを検索対象にします。複数ページにまたがる実文書を使うことで、PDF解析、chunk分割、複数candidateのscoreと本文を実際に観察できます。

## 手順 2.1. AWS公式PDFをcurlで取得する

<CliStep number="2.1" title="AWS公式PDFをcurlで取得する">

AWS Docsの`latest` URLからPDFを取得します。途中で切れたファイルを完成品として扱わないよう、`.part`へ保存してからrenameします。

<Command phase="execute" title="AWS公式PDFを取得">

```bash
export RAG_DOWNLOAD_INFO="$(curl --fail --location \
  --retry 3 --retry-all-errors \
  --connect-timeout 20 --max-time 300 \
  --output "$RAG_DOCUMENT_PATH.part" \
  --write-out 'downloaded=%{size_download} bytes\ncontent_type=%{content_type}\nurl=%{url_effective}\n' \
  "$RAG_DOCUMENT_URL")"

printf '%s' "$RAG_DOWNLOAD_INFO" \
  | tee "$RAG_WORK_DIR/pdf-download-info.txt"

mv "$RAG_DOCUMENT_PATH.part" "$RAG_DOCUMENT_PATH"
```

</Command>

<Command phase="verify" title="PDFの形式とサイズを検証" final>

```bash
export RAG_DOWNLOAD_CONTENT_TYPE="$(sed -n 's/^content_type=//p' "$RAG_WORK_DIR/pdf-download-info.txt")"
export RAG_DOWNLOAD_URL="$(sed -n 's/^url=//p' "$RAG_WORK_DIR/pdf-download-info.txt")"

[[ "$RAG_DOWNLOAD_CONTENT_TYPE" == application/pdf* ]]
[[ "$RAG_DOWNLOAD_URL" == https://docs.aws.amazon.com/* ]]
test "$(head -c 5 "$RAG_DOCUMENT_PATH")" = "%PDF-"

export RAG_PDF_BYTES="$(wc -c < "$RAG_DOCUMENT_PATH")"
test "$RAG_PDF_BYTES" -gt 1048576
test "$RAG_PDF_BYTES" -lt 50000000

export RAG_PDF_SHA256="$(sha256sum "$RAG_DOCUMENT_PATH" \
  | tee "$RAG_WORK_DIR/aws-rag-options-and-architectures.sha256" \
  | awk '{print $1}')"
test -s "$RAG_WORK_DIR/aws-rag-options-and-architectures.sha256"

printf '[CHECK] HTTP download: COMPLETE\n'
printf '[CHECK] download source: AWS Docs\n'
printf '[CHECK] PDF type: application/pdf / %%PDF-\n'
printf '[CHECK] PDF size: %s bytes (1 MiB < size < 50 MB)\n' "$RAG_PDF_BYTES"
printf '[CHECK] SHA-256 record: %s\n' "$RAG_PDF_SHA256"
printf 'PDF verification: PASS\n'
```

</Command>

<ExpectedResult id="s2-1-pdf" verification="PDFの形式とサイズを検証">

次の6行が表示されれば成功です。取得元、PDF形式、サイズ範囲、SHA-256記録をコマンドが検証済みです。

```text
[CHECK] HTTP download: COMPLETE
[CHECK] download source: AWS Docs
[CHECK] PDF type: application/pdf / %PDF-
[CHECK] PDF size: 6843210 bytes (1 MiB < size < 50 MB)
[CHECK] SHA-256 record: 9f2c...
PDF verification: PASS
```

- `[CHECK] HTTP download: COMPLETE`が表示される
- `[CHECK] download source: AWS Docs`が表示される
- `[CHECK] PDF type: application/pdf / %PDF-`が表示される

- `[CHECK] SHA-256 record:`が表示される
- `PDF verification: PASS`が表示される

## 手順 2.2. 出典メタデータを作成する

<CliStep number="2.2" title="出典メタデータを作成する">

Amazon Bedrock Knowledge Basesは、`元ファイル名.metadata.json`というsidecar fileからmetadata属性を取り込みます。出典URL、取得日、文書種別を検索結果へ引き継ぎます。

<Command phase="prepare" title="出典メタデータを準備">

```bash
export RAG_RETRIEVED_AT="$(date -u +%Y-%m-%dT%H:%M:%SZ)"

jq -n \
  --arg sourceUrl "$RAG_DOCUMENT_URL" \
  --arg retrievedAt "$RAG_RETRIEVED_AT" \
  '{
    metadataAttributes:{
      category:"rag-guidance",
      status:"published",
      language:"ja",
      source_title:"AWSのRAGオプションとアーキテクチャ",
      source_url:$sourceUrl,
      retrieved_at:$retrievedAt
    }
  }' | tee "$RAG_DOCUMENT_PATH.metadata.json"
```

</Command>

<Command phase="verify" title="メタデータJSONを検証" final>

```bash
jq -e '
  .metadataAttributes.category == "rag-guidance" and
  .metadataAttributes.status == "published" and
  .metadataAttributes.language == "ja" and
  (.metadataAttributes.source_url | startswith("https://docs.aws.amazon.com/")) and
  (.metadataAttributes.retrieved_at | test("^[0-9]{4}-[0-9]{2}-[0-9]{2}T[0-9]{2}:[0-9]{2}:[0-9]{2}Z$"))
' "$RAG_DOCUMENT_PATH.metadata.json" >/dev/null

export RAG_METADATA_BYTES="$(wc -c < "$RAG_DOCUMENT_PATH.metadata.json")"
if [ "$RAG_METADATA_BYTES" -ge 10240 ]; then
  printf 'ERROR: metadata size is %s bytes; it must be less than 10240 bytes\n' \
    "$RAG_METADATA_BYTES" >&2
  exit 1
fi

printf '[CHECK] metadata attributes: rag-guidance / published / ja\n'
printf '[CHECK] metadata source: AWS Docs\n'
printf '[CHECK] metadata timestamp: UTC ISO 8601\n'
printf '[CHECK] metadata size: %s bytes (< 10240 bytes)\n' "$RAG_METADATA_BYTES"
printf 'metadata verification: PASS\n'
```

</Command>

<ExpectedResult id="s2-2-metadata" verification="メタデータJSONを検証">

次の5行が表示されれば成功です。metadata fileが`10240 bytes`以上の場合は、`ERROR: metadata size is ...; it must be less than 10240 bytes`と表示して終了します。

```text
[CHECK] metadata attributes: rag-guidance / published / ja
[CHECK] metadata source: AWS Docs
[CHECK] metadata timestamp: UTC ISO 8601
[CHECK] metadata size: 428 bytes (< 10240 bytes)
metadata verification: PASS
```

- `[CHECK] metadata attributes: rag-guidance / published / ja`が表示される
- `[CHECK] metadata source: AWS Docs`が表示される
- `[CHECK] metadata timestamp: UTC ISO 8601`が表示される
- `[CHECK] metadata size:`に`< 10240 bytes`が表示される
- `metadata verification: PASS`が表示される

</ExpectedResult>

</CliStep>

## 手順 2.3. S3バケットを作成してアップロードする

<CliStep number="2.3" title="S3バケットを作成してアップロードする">

<Command phase="execute" title="S3バケットを作成してアップロード">

```bash
aws s3api create-bucket \
  --bucket "$RAG_SOURCE_BUCKET" \
  --region "$AWS_REGION" \
  --create-bucket-configuration "LocationConstraint=$AWS_REGION"

aws s3api put-public-access-block \
  --bucket "$RAG_SOURCE_BUCKET" \
  --public-access-block-configuration \
    'BlockPublicAcls=true,IgnorePublicAcls=true,BlockPublicPolicy=true,RestrictPublicBuckets=true'

aws s3 cp "$RAG_WORK_DIR/documents" "s3://$RAG_SOURCE_BUCKET/documents/" --recursive
```

</Command>

<Command phase="verify" title="バケットとオブジェクトを検証" final>

```bash
export RAG_SOURCE_BUCKET_LOCATION="$(aws s3api get-bucket-location \
  --bucket "$RAG_SOURCE_BUCKET" \
  --query LocationConstraint \
  --output text)"
test "$RAG_SOURCE_BUCKET_LOCATION" = "$AWS_REGION"

aws s3api get-public-access-block \
  --bucket "$RAG_SOURCE_BUCKET" \
  --output json \
  | tee "$RAG_WORK_DIR/source-public-access-block.json" >/dev/null

jq -e '
  .PublicAccessBlockConfiguration.BlockPublicAcls and
  .PublicAccessBlockConfiguration.IgnorePublicAcls and
  .PublicAccessBlockConfiguration.BlockPublicPolicy and
  .PublicAccessBlockConfiguration.RestrictPublicBuckets
' "$RAG_WORK_DIR/source-public-access-block.json" >/dev/null

aws s3api list-objects-v2 \
  --bucket "$RAG_SOURCE_BUCKET" \
  --prefix documents/ \
  --output json \
  | tee "$RAG_WORK_DIR/source-objects.json" >/dev/null

jq -e \
  --arg pdf 'documents/aws-rag-options-and-architectures.pdf' \
  --arg metadata 'documents/aws-rag-options-and-architectures.pdf.metadata.json' '
  .KeyCount == 2 and
  ([.Contents[].Key] | sort) == ([$pdf, $metadata] | sort)
' "$RAG_WORK_DIR/source-objects.json" >/dev/null

export RAG_S3_PDF_BYTES="$(aws s3api head-object \
  --bucket "$RAG_SOURCE_BUCKET" \
  --key documents/aws-rag-options-and-architectures.pdf \
  --query ContentLength --output text)"
test "$RAG_S3_PDF_BYTES" = "$RAG_PDF_BYTES"

printf '[CHECK] source bucket region: %s\n' "$RAG_SOURCE_BUCKET_LOCATION"
printf '[CHECK] public access block: 4 / 4 True\n'
printf '[CHECK] source objects uploaded: 2 (PDF + metadata)\n'
printf '[CHECK] PDF byte size: MATCH (%s bytes)\n' "$RAG_S3_PDF_BYTES"
printf 'upload verification: PASS\n'
```

</Command>

<ExpectedResult id="s2-3-s3" verification="バケットとオブジェクトを検証">

次の5行が表示されれば成功です。

```text
[CHECK] source bucket region: ap-northeast-1
[CHECK] public access block: 4 / 4 True
[CHECK] source objects uploaded: 2 (PDF + metadata)
[CHECK] PDF byte size: MATCH (6843210 bytes)
upload verification: PASS
```

- `[CHECK] source bucket region: ap-northeast-1`が表示される
- `[CHECK] public access block: 4 / 4 True`が表示される
- `[CHECK] source objects uploaded: 2`が表示される
- `[CHECK] PDF byte size: MATCH`が表示される
- `upload verification: PASS`が表示される

</ExpectedResult>

</CliStep>

<Checkpoint>

- AWS公式URLから実際のPDFを`curl`で取得した
- PDF magic bytes、1 MiB超〜50 MB未満のsize、SHA-256を確認した
- source URLと取得日をmetadataへ記録した
- source bucketは東京リージョンでpublic accessがblockされている
- `documents/`配下にPDFとmetadataの2 objectがある
- localとS3のPDF byte数が一致する

</Checkpoint>
