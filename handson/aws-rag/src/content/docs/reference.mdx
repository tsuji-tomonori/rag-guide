## Baseline構成

| 項目 | このハンズオンの値 | 理由 |
|---|---|---|
| Region | `ap-northeast-1` | 東京でBedrockとS3 Vectorsを同一リージョンに配置 |
| Data source | Amazon S3 | 小さな文書集合とsidecar metadataを観察しやすい |
| Embedding | Titan Text Embeddings V2 | Knowledge Basesで1024次元floatを利用 |
| Dimension | 1024 | embedding設定とvector indexを明示的に一致 |
| Vector store | S3 Vectors | infrastructure provision不要のsemantic baseline |
| Distance | cosine | 正規化された意味比較のbaseline |
| Chunking | 300 token / 10% overlap | 比較を始めるための固定長baseline。評価後に変更 |
| Retrieval | `SEMANTIC` / 5 candidates | 検索結果を生成前に観察 |
| Generation | Amazon Nova Lite / Converse | Evidence Setを明示的に入力 |
| Data deletion | `DELETE` | data source削除時に取り込みvectorも削除 |

## 本書との接続

このハンズオンは、`rag-guide`第10章のカスタマーマネージド型baselineである`S3 → Knowledge Bases → S3 Vectors → Retrieve → Converse`を操作へ落としたものです。概念と設計判断は次を参照してください。

- `docs/3.回答に使う資料を準備する/`：data source、chunking、metadata、embedding、index
- `docs/4.質問に合う根拠を探す/`：semantic search、hybrid retrieval、filter
- `docs/5.根拠を選別・整形する/`：Evidence Set、reranking、validation
- `docs/6.根拠に基づいて回答する/`：grounded prompt、citation、answerability
- `docs/7.品質を評価し改善する/`：Recall@k、generation・end-to-end評価
- `docs/10.AWSで設計・実装する/`：AWSサービスへの対応付け
