Knowledge Baseのembedding設定とindex設定を接続します。両方を`1024 / FLOAT32`へ固定し、作成後にAPIからread-backします。作成されたIDはstate fileへ保存し、ターミナルセッションが切り替わっても同じrunを継続できるようにします。

## 手順 5.1. ナレッジベースを作成する

<CliStep number="5.1" title="ナレッジベースを作成する">

<Command phase="prepare" title="Knowledge Baseの作成設定を生成">

```bash
jq -n \
  --arg name "$RAG_KB_NAME" \
  --arg roleArn "$RAG_ROLE_ARN" \
  --arg region "$AWS_REGION" \
  --arg embedModel "$RAG_EMBED_MODEL_ID" \
  --arg vectorBucketArn "$RAG_VECTOR_BUCKET_ARN" \
  --arg indexArn "$RAG_INDEX_ARN" \
  '{
    name:$name,
    description:"RAG hands-on knowledge base",
    roleArn:$roleArn,
    knowledgeBaseConfiguration:{
      type:"VECTOR",
      vectorKnowledgeBaseConfiguration:{
        embeddingModelArn:("arn:aws:bedrock:"+$region+"::foundation-model/"+$embedModel),
        embeddingModelConfiguration:{bedrockEmbeddingModelConfiguration:{dimensions:1024,embeddingDataType:"FLOAT32"}}
      }
    },
    storageConfiguration:{type:"S3_VECTORS",s3VectorsConfiguration:{vectorBucketArn:$vectorBucketArn,indexArn:$indexArn}}
  }' | tee "$RAG_WORK_DIR/create-kb.json"

```

</Command>

<Command phase="execute" title="Knowledge Baseを作成してIDを保存">

```bash
aws bedrock-agent create-knowledge-base \
  --region "$AWS_REGION" \
  --cli-input-json "file://$RAG_WORK_DIR/create-kb.json" \
  | tee "$RAG_WORK_DIR/create-kb-output.json"

export RAG_KB_ID="$(jq -r '.knowledgeBase.knowledgeBaseId' "$RAG_WORK_DIR/create-kb-output.json")"
test "${#RAG_KB_ID}" -eq 10
declare -p RAG_KB_ID >> "$RAG_STATE_FILE"
```

</Command>

<Aside type="tip" title="IAM反映待ちで失敗した場合">
  `Invalid service role`などが返った場合は60秒以内を目安に待ち、roleとpolicyのread-backに成功することを確認してから、この作成コマンドを1回再実行します。異なるroleを作り直す必要はありません。
</Aside>

<Command phase="verify" title="ナレッジベースを検証" final>

```bash
for attempt in {1..20}; do
  RAG_KB_STATUS="$(aws bedrock-agent get-knowledge-base \
    --region "$AWS_REGION" \
    --knowledge-base-id "$RAG_KB_ID" \
    --query 'knowledgeBase.status' \
    --output text)"
  printf 'knowledge base status: %s\n' "$RAG_KB_STATUS"
  case "$RAG_KB_STATUS" in
    ACTIVE) break ;;
    FAILED) aws bedrock-agent get-knowledge-base --region "$AWS_REGION" --knowledge-base-id "$RAG_KB_ID"; exit 1 ;;
  esac
  sleep 10
done

test "$RAG_KB_STATUS" = "ACTIVE"

aws bedrock-agent get-knowledge-base \
  --region "$AWS_REGION" \
  --knowledge-base-id "$RAG_KB_ID" \
  --output json \
  | tee "$RAG_WORK_DIR/knowledge-base-readback.json" >/dev/null

jq -e \
  --arg kbId "$RAG_KB_ID" \
  --arg roleArn "$RAG_ROLE_ARN" \
  --arg vectorBucketArn "$RAG_VECTOR_BUCKET_ARN" \
  --arg indexArn "$RAG_INDEX_ARN" '
  .knowledgeBase.knowledgeBaseId == $kbId and
  .knowledgeBase.status == "ACTIVE" and
  .knowledgeBase.roleArn == $roleArn and
  .knowledgeBase.storageConfiguration.type == "S3_VECTORS" and
  .knowledgeBase.storageConfiguration.s3VectorsConfiguration.vectorBucketArn == $vectorBucketArn and
  .knowledgeBase.storageConfiguration.s3VectorsConfiguration.indexArn == $indexArn and
  .knowledgeBase.knowledgeBaseConfiguration.vectorKnowledgeBaseConfiguration.embeddingModelConfiguration.bedrockEmbeddingModelConfiguration.dimensions == 1024 and
  .knowledgeBase.knowledgeBaseConfiguration.vectorKnowledgeBaseConfiguration.embeddingModelConfiguration.bedrockEmbeddingModelConfiguration.embeddingDataType == "FLOAT32"
' "$RAG_WORK_DIR/knowledge-base-readback.json" >/dev/null

grep -Fq 'RAG_KB_ID' "$RAG_STATE_FILE"

printf '[CHECK] knowledge base creation: COMPLETE\n'
printf '[CHECK] knowledge base status: ACTIVE\n'
printf '[CHECK] storage and embedding: S3_VECTORS / FLOAT32 / 1024\n'
printf '[CHECK] service role ARN: MATCH\n'
printf '[CHECK] vector index ARN: MATCH\n'
printf '[CHECK] knowledge base ID saved to state file: %s\n' "$RAG_KB_ID"
printf 'knowledge base verification: PASS\n'
```

</Command>

## 手順 5.2. S3データソースを作成する

<CliStep number="5.2" title="S3データソースを作成する">

AWS PDFが説明するRAGの最初のステップでは、データのクリーニング、フォーマット、チャンク化、埋め込み、ベクトルデータベースへの保存を行います。ここでは300 token、10% overlapの固定長chunkingを開始値にします。これは万能な推奨値ではなく、後から検索結果のcoverageとノイズで比較するbaselineです。chunking設定はdata source作成後に変更できません。

<Command phase="prepare" title="S3データソースの作成設定を生成">

```bash
jq -n \
  --arg kbId "$RAG_KB_ID" \
  --arg name "$RAG_DS_NAME" \
  --arg bucketArn "arn:aws:s3:::$RAG_SOURCE_BUCKET" \
  '{
    knowledgeBaseId:$kbId,
    name:$name,
    description:"S3 documents for RAG hands-on",
    dataSourceConfiguration:{type:"S3",s3Configuration:{bucketArn:$bucketArn,inclusionPrefixes:["documents/"]}},
    dataDeletionPolicy:"DELETE",
    vectorIngestionConfiguration:{chunkingConfiguration:{chunkingStrategy:"FIXED_SIZE",fixedSizeChunkingConfiguration:{maxTokens:300,overlapPercentage:10}}}
  }' | tee "$RAG_WORK_DIR/create-data-source.json"

```

</Command>

<Command phase="execute" title="S3データソースを作成してIDを保存">

```bash
aws bedrock-agent create-data-source \
  --region "$AWS_REGION" \
  --cli-input-json "file://$RAG_WORK_DIR/create-data-source.json" \
  | tee "$RAG_WORK_DIR/create-data-source-output.json"

export RAG_DS_ID="$(jq -r '.dataSource.dataSourceId' "$RAG_WORK_DIR/create-data-source-output.json")"
test "${#RAG_DS_ID}" -eq 10
declare -p RAG_DS_ID >> "$RAG_STATE_FILE"
```

</Command>

<Command phase="verify" title="データソースを検証" final>

```bash
aws bedrock-agent get-data-source \
  --region "$AWS_REGION" \
  --knowledge-base-id "$RAG_KB_ID" \
  --data-source-id "$RAG_DS_ID" \
  --output json \
  | tee "$RAG_WORK_DIR/data-source-readback.json" >/dev/null

jq -e \
  --arg dsId "$RAG_DS_ID" \
  --arg bucketArn "arn:aws:s3:::${RAG_SOURCE_BUCKET}" '
  .dataSource.dataSourceId == $dsId and
  .dataSource.status == "AVAILABLE" and
  .dataSource.dataSourceConfiguration.type == "S3" and
  .dataSource.dataSourceConfiguration.s3Configuration.bucketArn == $bucketArn and
  .dataSource.dataSourceConfiguration.s3Configuration.inclusionPrefixes == ["documents/"] and
  .dataSource.dataDeletionPolicy == "DELETE" and
  .dataSource.vectorIngestionConfiguration.chunkingConfiguration.chunkingStrategy == "FIXED_SIZE" and
  .dataSource.vectorIngestionConfiguration.chunkingConfiguration.fixedSizeChunkingConfiguration.maxTokens == 300 and
  .dataSource.vectorIngestionConfiguration.chunkingConfiguration.fixedSizeChunkingConfiguration.overlapPercentage == 10
' "$RAG_WORK_DIR/data-source-readback.json" >/dev/null

grep -Fq 'RAG_DS_ID' "$RAG_STATE_FILE"

printf '[CHECK] data source creation: COMPLETE\n'
printf '[CHECK] data source status: AVAILABLE\n'
printf '[CHECK] S3 scope: current source bucket / documents/\n'
printf '[CHECK] chunking: FIXED_SIZE / 300 / 10%%\n'
printf '[CHECK] deletion policy: DELETE\n'
printf '[CHECK] data source ID saved to state file: %s\n' "$RAG_DS_ID"
printf 'data source verification: PASS\n'
```

</Command>
