# 10. AWSでRAGを設計・実装する

本章では、AWS上のRAGを四つの工程に分け、各工程で使うサービス、選択基準、主要な設定値を対応付けます。
前半で構成を選び、後半で架空のMarkdown文書3件を使う最小構成を実際に動かします。

1. **検索前処理（Pre-retrieval）**：文書を解析・分割し、embeddingと索引を作ります。
2. **検索（Retrieval）**：質問に関係する根拠候補を取得します。
3. **検索後処理（Post-retrieval）**：候補を再順位付け、重複排除、選別します。
4. **生成（Generation）**：選んだ根拠から回答と引用を作ります。

四工程の考え方は[第2章 アーキテクチャ](../2.アーキテクチャ/序文.md)で説明しています。
本章では、その考え方をAWSリソースとAPI設定へ落とし込みます。

AWSサービスの画面、対応リージョン、モデルID、quotaは変更されることがあります。
AWS固有情報は2026年8月22日に公式ドキュメントで確認しています。
実装時には、本文からリンクしたAWS公式ドキュメントで利用リージョンの現行仕様も確認してください。

### 10.0.1 この章で構築するもの

ハンズオンでは、東京リージョンに次の構成を作ります。

- Amazon S3へUTF-8のMarkdown文書3件を配置します。
- Amazon Bedrock Knowledge Basesで文書を解析・分割します。
- Amazon Titan Text Embeddings V2で1024次元のembeddingを作ります。
- Amazon S3 Vectorsへembeddingを保存します。
- `Retrieve`で順位、score、本文、出典を確認します。
- 必要に応じてAmazon Bedrockのrerankerを追加します。
- `RetrieveAndGenerate`で回答、引用、session IDを取得します。

最小構成の想定所要時間は60分から90分です。
AWSアカウントの権限やリソース作成の待ち時間によって前後します。

### 10.0.2 この章の範囲

ハンズオンは、検証用の公開情報だけを扱う一つのAWSアカウントを想定します。
認証、文書ACL、テナント分離、VPC、PrivateLink、顧客管理KMS鍵、WAF、負荷試験、災害復旧、CI/CD、Web画面は構築しません。

これらを省略した構成をそのまま本番公開してはいけません。
本番化するときは、[第7章 品質を評価し改善する](../7.品質を評価し改善する/序文.md)と[第8章 安全に運用する](../8.安全に運用する/序文.md)の要件を追加します。

### 10.0.3 読み進め方

1. [10.1 全体構成](10.1.全体構成.md)で、工程とサービスの対応、共通設計、構築順序を決めます。
2. [10.2 Pre-retrieval構成](10.2.Pre-retrieval構成.md)で、data source、parser、chunking、embedding、vector storeを選び、文書を同期します。
3. [10.3 Retrieval構成](10.3.Retrieval構成.md)で、検索方式、取得件数、filterを選び、`Retrieve`を実行します。
4. [10.4 Post-retrieval構成](10.4.Post-retrieval構成.md)で、reranker、重複排除、採用件数を選びます。
5. [10.5 Generation構成](10.5.Generation構成.md)で、生成モデル、prompt、推論パラメータ、引用、Guardrailsを設定します。

コマンドは、特に断りがない限りリポジトリのルートで実行します。
`YOUR_VALUE`と書かれた箇所は、自分の値に置き換えてください。
