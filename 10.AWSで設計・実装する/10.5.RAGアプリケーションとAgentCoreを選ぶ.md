# RAGアプリケーションとAgentCoreを選ぶ

Knowledge BaseとVector Storeは根拠を探す基盤です。利用者を認証し、検索、Evidence、生成、回答保留をつなぐアプリケーションは別に必要です。まず通常の一問一答RAGを検討し、複数Step、Tool、Memory、Tool単位Policyが必要な場合だけAgentCoreを追加します。

## 通常アプリケーションをBaselineにする

次の条件なら、API GatewayまたはALBとLambda、ECS、EKSなどで動かす通常アプリケーションをBaselineにできます。

- 一つの質問に対し、検索・生成を一巡すれば完了する
- Knowledge Baseまたは検索先が一つで、動的Routingが不要である
- Toolで業務状態を変更しない
- 長時間処理や複数Stepの再開が不要である
- SessionをアプリケーションのStorageで管理できる

通常構成でも、認証、Metadata Filter、Evidence Set、Model呼び出し、回答保留、監視は必要です。AgentCoreを使わないことは、これらの責任がなくなることを意味しません。

## AgentCoreを追加する条件

AgentCoreは、RAGや業務Toolを使うAgentアプリケーションへ実行・統制基盤を提供します。Knowledge BaseやVector Storeを置き換えません。

- **Runtime**：AgentまたはToolを隔離して実行し、Scalingする
- **Gateway**：API、Lambda、MCP、Managed Knowledge BaseをToolとして接続する
- **Identity**：Inbound / Outbound認証とCredentialを管理する
- **Memory**：Short-term Eventと、Strategyで抽出したLong-term Memoryを保持する
- **Policy**：Gatewayを通るTool CallをCedar Policyで許可・拒否する
- **Observability**：Model、Tool、MemoryをまたぐMetricsとTraceを関連づける
- **Evaluations**：Task successとAgent trajectoryを評価する

AWSはRuntimeのhosting、Session isolation、Gateway endpoint、Credential連携、Memory基盤、Policy engine、観測基盤を提供します。利用者はAgentの計画、検索先、Tool schema、引数、停止条件、Fallback、Human approval、Memoryへ保存する情報を決めます。

[Amazon Bedrock AgentCore](https://docs.aws.amazon.com/bedrock-agentcore/latest/devguide/what-is-bedrock-agentcore.html)、[Runtime](https://docs.aws.amazon.com/bedrock-agentcore/latest/devguide/agents-tools-runtime.html)、[Gateway](https://docs.aws.amazon.com/bedrock-agentcore/latest/devguide/gateway-core-concepts.html)、[Policy](https://docs.aws.amazon.com/bedrock-agentcore/latest/devguide/policy-core-concepts.html)を参照します（確認日：2026年8月22日）。

## Runtime、Memory、Knowledge Baseを分ける

三つは保存目的と評価方法が異なります。

- **Runtimeの一時状態**：処理の継続と隔離に必要な最小状態
- **Short-term Memory**：会話Session内のEvent
- **Long-term Memory**：利用者同意とStrategyに基づくSession横断の記憶
- **Knowledge Base**：組織文書を検索するための索引
- **原文S3**：版、所有者、公開状態を持つ正本

個人情報や業務秘密をMemoryへ保存する場合、文書検索のACLとは別に、保存目的、Namespace、保持期間、削除、同意、KMS Key、Log maskingを設計します。[Memory terminology](https://docs.aws.amazon.com/bedrock-agentcore/latest/devguide/memory-terminology.html)を参照します（確認日：2026年8月22日）。

## AgentCoreの採否を評価する

次の能力が必要な場合だけAgentCoreを比較します。

- 一つの質問で複数回検索し、次のQueryや検索先をAgentが決める
- 複数Knowledge Base、社内API、Lambda、MCP Toolを選択する
- 回答後に申請、登録、通知などのTool実行を行う
- 長時間処理、複数Step、Session隔離が必要である
- Short-termまたはLong-term Memoryが必要である
- Tool Callを決定的なPolicyで許可・拒否する
- Model、Tool、MemoryをまたぐStep Traceが必要である

これらがなければ、AgentCoreを追加しても検索品質そのものは改善しません。Task success、Trajectory、Tool選択・引数、Loop停止、Policy Allow/Deny、Memory汚染、P95 Latency、Stepごとの費用を評価します。

Managed Knowledge Baseのagentic retrievalだけが必要なら、通常アプリケーションから`AgenticRetrieveStream`を呼ぶ構成も比較します。AgentCore全体は必須ではありません。Managed Knowledge BaseはGatewayのNative targetにできますが、Customer-managed Knowledge BaseはRuntimeからAPIを呼ぶか、Lambda / API Toolとして接続します。[Managed KB Gateway connector](https://docs.aws.amazon.com/bedrock-agentcore/latest/devguide/gateway-target-connector-managed-kb.html)を参照します（確認日：2026年8月22日）。
