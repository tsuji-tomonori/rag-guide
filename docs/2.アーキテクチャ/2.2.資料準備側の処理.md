# 2.2 資料準備側の処理

資料準備側は、質問が来る前に知識源を検索可能な状態へ変える処理です。ここでは処理順と責務だけを確認し、parser、chunk、embedding、indexの選択は第3章で扱います。

最初に、RAGが参照してよいdata sourceを定めます。正本、所有者、更新頻度、版、有効期間、機密区分を記録し、検索対象外にするsourceも明示します。単に接続できる資料をすべて取り込むことは避けます。

PDF、Office文書、HTML、表、画像などを、読み順と出典位置を保ったcanonical documentへ変換します。解析に失敗した文書を黙って登録せず、失敗理由と再処理可否を記録します。詳細は第3章で扱います。

文書を検索と引用に適したchunkへ分けます。chunkは小さければ文脈を失い、大きければ検索精度とtoken効率を下げるため、文書構造と質問の粒度に合わせて決めます。

各documentとchunkへ、source、版、時点、分類、provenance、ACLを付与します。検索時の認可に必要な情報は生成後ではなく、この段階から欠損なく保持します。

chunkをembedding化し、sparseまたはvector indexへ登録します。model、dimension、distance、index schemaをversion付きで固定し、更新前後を比較できる状態にします。

資料準備の具体的な設計、初期値、失敗条件は第3章で説明します。本章では、回答側が参照するのは公開済みversionのindexであり、作成途中の成果物ではないことだけを確認します。
