# 2.5 最初に作る構成

最初からGraphRAGやAgentic RAGを組み込むと、効果の原因と失敗箇所を判断しにくくなります。まず、限定した正本、再現可能な資料準備、baseline retrieval、Evidence Set、引用付き回答、回答保留、trace、評価datasetから成る基礎構成を作ります。

初期段階から、query、filter、取得candidate、rerank結果、採用evidence、citation、model・prompt・index versionをtraceします。同時に、少数でもgolden questionとgold evidenceを用意し、変更前後を比較します。最小構成とは機能が少ないことではなく、失敗を観測し、比較できることです。

PoCは価値仮説を短期間で確かめる構成ですが、本番候補にはACL、削除反映、version、監査、SLO、cost、rollbackが必要です。一体型APIを使う場合も、内部で検索と生成を区別して評価できる記録を残します。

基礎構成で評価し、失敗がどのlayerに残るかを確認してから拡張します。通常のchunk、embedding、検索、rerank、promptの調整で解消できない場合にだけ、第9章の方式を比較します。AWSでの具体的なサービス接続と設定値は[AWSでAdvanced RAGを構成する](../10.AWSで設計・実装する/序文.md)で扱います。
