# 2.5 最初に作る構成

最初からGraphRAGやAgentic RAGを組み込むと、効果の原因と失敗箇所を判断しにくくなります。本節では比較可能な最小構成を定め、評価結果から段階的に拡張する方針を示します。

最小構成は、限定した正本、再現可能なingestion、baseline retrieval、Evidence Set、引用付き回答、回答保留、trace、評価datasetから成ります。まずこの構成で失敗を観測できるようにします。

PoCは価値仮説を短期間で確かめる構成ですが、本番候補にはACL、削除反映、version、監査、SLO、cost、rollbackが必要です。PoCの一体型APIを、そのまま本番設計とみなさないようにします。

初期段階から、query、filter、取得candidate、rerank結果、採用evidence、citation、model・prompt・index versionをtraceします。同時に少数でもgolden questionとgold evidenceを用意し、変更前後を比較します。

基本構成で評価し、失敗がどのlayerに残るかを確認してから拡張します。retrieval不足をagent loopで隠したり、権限設計の不足をpromptで補ったりしません。

Conversational、Federated、Structured Data、Long-context、Graph、Multimodal、Agenticなどの方式は第9章で扱います。導入条件は技術名ではなく、評価で再現した失敗パターンです。
