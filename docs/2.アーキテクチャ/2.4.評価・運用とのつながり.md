# 2.4 評価・運用とのつながり

RAGは、初回構築後も資料、index、prompt、modelの変更によって品質が変わります。本節では評価と運用がpipeline全体を支えることだけを示し、具体的な指標と統制は第7章と第8章へ委ねます。

資料、embedding、index、reranker、prompt、modelは継続的に変化します。したがって、RAGは一度正解率を測って完成とせず、変更ごとに品質と安全性を再確認するsystemとして運用します。

評価では、最終回答だけでなく、parse、chunk、retrieval、evidence、generationを分けて測ります。失敗をlayerへ戻せる評価設計にすると、効果のない高度化や場当たり的なprompt修正を避けられます。

本番では、利用者権限、監査証跡、latency、availability、cost、知識更新を同時に管理します。品質が高くても、権限外情報を返す構成や、更新を追跡できない構成は公開できません。

評価dataset、metric、regression、release gateは第7章で扱います。security、privacy、監査、性能、cost、更新、governanceは第8章で扱い、2章では管理項目の一覧へ展開しません。
