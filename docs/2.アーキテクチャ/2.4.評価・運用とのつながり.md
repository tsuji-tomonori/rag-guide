# 2.4 評価・運用とのつながり

RAGは、初回構築後も資料、index、prompt、modelの変更によって品質が変わります。本節では評価と運用がpipeline全体を支えることを示し、具体的な指標と統制は[品質を評価し改善する](../7.品質を評価し改善する/序文.md)と[安全に運用する](../8.安全に運用する/序文.md)で扱います。

評価では、最終回答だけでなく、parse、chunk、retrieval、evidence、generationを分けて測ります。失敗を最初に逸脱した工程へ戻せる評価設計にすると、効果のない高度化や場当たり的なprompt修正を避けられます。変更前後は同じ評価データと合格基準で比較し、改善と回帰を同時に確認します。

本番では、文書アクセス権、監査証跡、latency、availability、cost、知識更新を同時に管理します。品質が高くても、権限外情報を返す構成や、削除と更新を追跡できない構成は公開できません。評価結果、構成version、実行traceを結び付けることで、公開判断と切り戻しを再現できます。

基本構成で失敗を再現し、通常の設定調整で解消できない場合にだけ[失敗パターンに応じた高度化](../9.失敗パターンに応じて高度化する/序文.md)へ進みます。高度化の採否は技術名ではなく、対象失敗、品質差、遅延、費用、安全性、停止条件で決めます。
