# 2.1 RAGパイプライン全体像

RAGは一つのモデルではなく、資料を検索可能にし、質問に合う根拠を探し、回答へ変換し、品質を測る一連の処理です。本節では各工程の名前と受け渡す成果物だけを示し、詳細は後続章へ委ねます。

RAGを、`資料準備 → 検索 → 根拠整形 → 回答 → 評価`というpipelineとして捉えます。各工程は入力と出力を持ち、後段は前段の成果物だけを前提にします。これにより、modelの性能だけでなく、文書解析、検索、根拠選択のどこが回答品質を制約したかを説明できます。

資料準備は質問とは独立して実行でき、再現性と更新反映を重視します。回答処理は質問ごとに実行され、権限、latency、回答可能性を重視します。両者を分けることで、資料更新の失敗をonline処理へ持ち込まず、質問時の処理を必要以上に重くしません。

Pre-retrievalは資料を検索可能にし、Retrievalは根拠候補を集め、Post-retrievalは候補をEvidence Setへ整え、Generationは回答・引用・回答保留へ変換します。Evaluationは独立した末尾工程ではなく、各工程の成果物を測り、改善先へ戻す横断loopです。

最終回答だけでは、正しい資料を取得できなかったのか、取得後に落としたのか、LLMが根拠を誤読したのかを区別できません。工程ごとに入力、出力、version、traceを残すと、失敗を再現し、変更すべき箇所を限定できます。
