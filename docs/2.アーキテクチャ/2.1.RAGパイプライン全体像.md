# 2.1. 四工程と二層で全体を捉える

## 2.1.1. 四工程は処理の目的を表す

RAGの構成要素は増え続けていますが、各要素が受け取る入力と作る出力は四工程へ整理できます。
[Huangらのサーベイ](https://doi.org/10.1145/3805774)は、単一回の検索だけでなく、反復検索や複数段階の検索も、検索前処理、検索、検索後処理、生成の四段階で整理しています。
本書もこの枠組みを採用し、どの工程で最初の逸脱が起きたかを評価できる構成にします。

1. **検索前処理**は、文書と質問を検索に使える表現へ変換します。成果物は、公開済み索引、メタデータ、検索条件、検索クエリです。
2. **検索**は、質問に関係する根拠候補を集めます。成果物は、検索方式ごとの候補、順位、スコア、適用した検索条件です。
3. **検索後処理**は、候補を選別・整形して回答に使う根拠集合へ変換します。成果物は、採用理由と出典位置を持つ**Evidence Set（根拠集合）**です。
4. **生成**は、Evidence Setが支える範囲で回答、引用、または回答保留を作ります。成果物は、主張と根拠を対応付けた回答です。

四工程を分けると、「検索対象に正解があるか」「候補へ取得できたか」「取得後に残せたか」「回答が根拠を正しく使ったか」を個別に確認できます。
評価と非機能は、四工程すべての品質と制約を測る横断的な活動です。

## 2.1.2. 二層は処理の実行時点を表す

**Batch Layer**は、質問を受ける前に文書を収集・解析し、検索可能な索引として公開します。
文書更新と索引更新を版単位で管理するため、同じ入力から同じ成果物を再構築できる再現性を重視します。

**Real-time Layer**は、質問ごとに検索条件を作り、候補取得、根拠整形、生成を実行します。
利用者の権限、応答時間、回答可能性を質問単位で扱い、Batch Layerが公開した版を参照します。

四工程と二層は一対一には対応しません。
検索前処理のうち、文書解析、分割、埋め込み、索引作成はBatch Layerで動き、質問理解と質問変換はReal-time Layerで動きます。
検索、検索後処理、生成は主にReal-time Layerで動きますが、評価用の再実行はBatch Layerでも行います。

## 2.1.3. 後続章を四工程から選ぶ

四工程ごとに、設計する技術要素と参照先を対応付けると、現在の課題から読む章を選べます。

| 工程 | 技術要素 | 章番号・ページ |
|---|---|---|
| 検索前処理 | 情報源、取り込み、解析、分割、メタデータ、埋め込み、索引 | [第3章](../3.回答に使う資料を準備する/序文.md) |
| 検索前処理 | 質問理解、検索計画、質問変換 | [第4章](../4.質問に合う根拠を探す/序文.md) |
| 検索 | 疎検索、密検索、ハイブリッド検索、検索時フィルター、失敗診断 | [第4章](../4.質問に合う根拠を探す/序文.md) |
| 検索後処理 | 候補の正規化、重複排除、再順位付け、圧縮、Evidence Set、矛盾処理 | [第5章](../5.根拠を選別・整形する/序文.md) |
| 生成 | プロンプト、回答形式、回答可能性、引用、主張検証、会話履歴 | [第6章](../6.根拠に基づいて回答する/序文.md) |

四工程を横断する評価は[第7章](../7.品質を評価し改善する/序文.md)、RAG固有の非機能と運用は[第8章](../8.安全に運用する/序文.md)で確認します。
基準構成で再現した失敗に対応する発展方式は、[第9章](../9.失敗パターンに応じて高度化する/序文.md)で選びます。
