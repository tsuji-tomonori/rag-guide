# 2.1 RAGパイプライン全体像

RAGは一つのモデルではなく、資料を検索可能にし、質問に合う根拠を探し、回答へ変換し、品質を測る一連の処理です。本節では各工程の名前と受け渡す成果物を示し、詳細はリンク先へ委ねます。

RAGを、`資料準備 → 検索 → 根拠整形 → 回答`というpipelineとして捉えます。評価と安全な運用は独立した末尾工程ではなく、各工程の成果物を測り、変更を統制する横断的な活動です。工程ごとに入力、出力、version、traceを残すと、正しい資料を取得できなかったのか、取得後に落としたのか、LLMが根拠を誤読したのかを区別できます。

資料準備は質問とは独立して実行でき、再現性と更新反映を重視します。回答処理は質問ごとに実行され、権限、latency、回答可能性を重視します。両者を分けることで、資料更新の失敗をonline処理へ持ち込まず、質問時の処理を必要以上に重くしません。
