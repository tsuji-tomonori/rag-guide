# 2.3. 検索の概要

検索は、検索前処理が作った質問と索引を使い、正解根拠を含み得る候補集合を作る工程です。
この工程では候補の回収を優先し、最終的に回答へ採用する根拠は検索後処理で決めます。

## 2.3.1. 複数の検索表現を組み合わせる

疎検索は、製品コード、条文番号、専門用語などの語彙一致を捉えます。
密検索は、質問と文書の言い換えや意味の近さを捉えます。
ハイブリッド検索は両方の候補を統合し、どちらか一方だけでは回収しにくい質問へ対応します。

検索時には、利用者のアクセス権、版、有効期間、地域、製品などの条件を候補取得へ適用します。
検索方式ごとの候補、順位、スコア、フィルター前後の件数を記録すると、語彙、埋め込み、条件、索引のどこを調整すべきか判断できます。

## 2.3.2. 検索の完了条件を候補回収で測る

検索工程の完了条件は、評価対象の質問に必要な根拠が上位候補へ含まれることです。
正解根拠を定めた評価データを使い、Recall@k、順位、ゼロ件率、フィルター前後の件数、応答時間を質問種類別に測ります。

**Recall@k**は、検索結果の上位k件までに、質問へ答えるための正解根拠をどの程度回収できたかを表す指標です。
指標の計算方法と、正解根拠が複数ある場合の扱いは[Retrieval評価](../7.品質を評価し改善する/7.4.Retrieval評価.md)で説明します。

検索方式と失敗診断の詳細は[質問に合う根拠候補を探す](../4.質問に合う根拠を探す/序文.md)で扱います。
候補へ入った根拠の選別は、次の[検索後処理](../5.根拠を選別・整形する/序文.md)へ渡します。
