# 2.8 最初に作るAdvanced RAG

最初に、検索品質、根拠の選別、引用、回答保留、評価を含むAdvanced RAGの最小構成を作ります。
この構成は、単純な検索結果をそのまま生成モデルへ渡す方式に、実務で必要な検索統合、根拠整形、検査可能性を加えた出発点です。

## 2.8.1 最小構成に必要な処理をそろえる

Batch Layerは、範囲を定めた正本、再現可能な取り込み、構造を保つ解析と分割、出典・版・アクセス制御属性、疎検索と密検索の索引、公開前ゲートで構成します。
Real-time Layerは、質問理解、検索時のアクセス制御、疎検索と密検索の統合、再順位付け、Evidence Set、根拠に基づく回答、引用、回答保留、実行記録で構成します。

評価には、少数から始められる正解付き質問、正解根拠、工程別指標、変更前後の回帰検査を含めます。
非機能には、削除反映、版管理、監査、性能目標、費用計測、切り戻しを含めます。
この範囲をそろえると、各変更の効果と失敗箇所を同じ基準で比較できます。

## 2.8.2 観測した問題から発展機能を選ぶ

最小構成を評価すると、会話の省略、複数情報源、長文全体の関係、図表、複数段階の探索など、基準構成に残る問題を特定できます。
問題を再現する質問と実行記録を固定し、対象工程に対応する手法を一つずつ追加します。

会話履歴の解決にはConversational RAG、情報源の分散にはFederated・Routed RAG、関係探索にはGraphRAG、図表にはMultimodal RAG、反復的な探索にはAgentic RAGが候補です。
導入判断と停止条件は[失敗パターンに応じて高度化する](../9.失敗パターンに応じて高度化する/序文.md)で扱い、**AWS（Amazon Web Services）**のサービス接続と設定値は[AWSでAdvanced RAGを構成する](../10.AWSで設計・実装する/序文.md)で扱います。
