# 2.3 回答側の処理

回答側は、質問ごとに根拠候補を取得し、回答に使える形へ整え、引用可能な回答を生成する処理です。検索、根拠整形、生成の詳細は第4章から第6章で扱います。

質問から対象、意図、版、期間、否定条件、会話中の省略を読み取り、検索計画へ変換します。質問文をそのままvector化するだけで十分とは限りません。

keyword、semantic、metadata filterを組み合わせ、正解根拠を含み得るcandidate集合を作ります。この段階の役割は最終回答を決めることではなく、必要な根拠を後段へ残すことです。

candidateをACL、鮮度、版、信頼度で絞り、重複を除き、質問への適合度でrerankします。検索scoreが異なる方式を混ぜる場合は、fusionとrerankを区別します。

選択した根拠をEvidence Setとして整理し、supporting、conflicting、backgroundなどの役割とprovenanceを持たせます。token budgetへ収めるときも引用位置を失わないようにします。

LLMには命令とEvidence Setを区別して渡し、根拠が支える範囲で回答させます。根拠不足、権限不足、矛盾が解消できない場合は、回答保留を正常な出力として返します。

Query理解と検索は第4章、Evidence Setへの整形は第5章、回答・引用・回答保留は第6章で説明します。2章では個々のalgorithmや設定値へ踏み込みません。
