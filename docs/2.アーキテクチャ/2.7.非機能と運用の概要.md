# 2.7. 非機能と運用の概要

RAGの非機能は、根拠を安全に取得し、必要な時間と費用の範囲で回答し、知識や構成の変更後も回答品質を維持するための条件です。
一般的なシステム基盤の説明ではなく、文書、索引、検索候補、Evidence Set、回答、引用、評価データがつながるRAGパイプラインへ適用する条件を扱います。

## 2.7.1. 権限・根拠・命令の境界を保つ

文書の閲覧権限は、取り込み時にメタデータへ保持し、検索時の候補制約と生成前のEvidence Set検査へ引き継ぎます。
本文だけでなく、埋め込み、検索候補、引用、trace、評価データにも同じ保護区分を適用し、権限のない文書の存在や内容が回答から推測される経路を検査します。

検索対象の文書は根拠データとして扱い、文書内の命令をシステムや利用者の命令から分離します。
Prompt injectionとdata poisoningに対しては、情報源の信頼区分、取り込み時検査、命令らしい記述の隔離、生成後の主張と引用の照合を組み合わせます。
詳細は[セキュリティと権限制御](../8.安全に運用する/8.1.セキュリティと権限制御.md)と[Prompt injection・data poisoning対策](../8.安全に運用する/8.3.Prompt injection・data poisoning対策.md)で扱います。

## 2.7.2. RAGパイプラインの性能・可用性・費用を測る

応答時間は、質問変換、検索、再順位付け、Evidence Set構築、生成へ分解して測ります。
検索のタイムアウトやゼロ件時には、候補数の変更、別の検索方式、回答保留など、根拠を捏造しない代替動作を定めます。
可用性は回答の返却率だけでなく、権限を適用した検索が実行できること、引用可能な根拠を取得できること、根拠不足時に安全に停止できることを含めて判定します。

費用は、取り込み文書・chunk・埋め込み・検索候補・再順位付け候補・入出力token・評価件数の単位へ分け、質問種類と構成版へ結び付けます。
これにより、費用削減がRecall、Evidence sufficiency、citation correctnessへ与えた影響を同時に比較できます。
詳細は[性能と可用性](../8.安全に運用する/8.5.性能と可用性.md)と[コスト管理](../8.安全に運用する/8.6.コスト管理.md)で扱います。

## 2.7.3. 知識とRAG構成の変更を統制する

文書の追加、変更、削除、権限変更は、索引とキャッシュへ反映されたことを文書IDと版で確認します。
文書snapshot、chunking、embedding model、index、検索設定、prompt、生成model、評価datasetを一つの構成版として記録すると、回答と引用を再現し、変更前の版へ切り戻せます。

新しい構成は、権限漏えい、検索Recall、Evidence sufficiency、faithfulness、citation correctness、応答時間、費用の回帰試験を通過してから公開します。
本番traceでは、利用者、質問、適用した権限、取得候補、採用根拠、回答、引用、構成版を対応付けます。
詳細は[監査とトレーサビリティ](../8.安全に運用する/8.4.監査とトレーサビリティ.md)、[知識更新と運用](../8.安全に運用する/8.7.知識更新と運用.md)、[ガバナンス](../8.安全に運用する/8.8.ガバナンス.md)で扱います。
