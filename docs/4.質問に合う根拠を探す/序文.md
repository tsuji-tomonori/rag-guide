# 4. 質問に合う根拠候補を探す

利用者の質問は、資料に書かれた言葉と同じとは限りません。会話の省略、略語、誤字、期間や版の条件を解決し、権限と鮮度を満たす根拠候補を集める必要があります。

**この章を読むと決められること**：質問をどう解釈し、どの検索器、filter、統合方式で候補を集めるかを決められます。

本章では、query理解、query変換、sparse・dense・hybrid retrieval、検索時filteringを整理します。最後に、検索失敗を語彙、embedding、filter、routing、chunk、indexの問題へ切り分けます。

検索の目的は、最終回答をその場で決めることではなく、回答に必要な根拠を候補集合へ残すことです。したがって、上位1件の見た目だけでなく、正解根拠のcandidate recall、filter前後の件数、検索方式ごとの寄与を測ります。

語彙一致、意味一致、属性条件は得意な失敗が異なります。単一方式を前提にせず、評価データで不足を確認し、hybrid、query変換、routingを必要な範囲だけ追加します。
