# RAGエンジニアガイド 章構成

<!-- chapter-structure:v3 -->

本書は、RAGを導入判断、資料準備、検索、根拠整形、回答、評価、運用、高度化の順に説明します。
見出しは論点を列挙するためではなく、独立した説明・判断・比較が成立する単位にだけ置きます。

## 構成原則

- 章を問わず、小節見出しを置く場合は `x.x.x` の番号を維持します。小節を統合しても、残した見出しだけを無番号にはしません。
- 第1章と第2章は導入と全体地図を優先し、短い説明や参照だけの小節は隣接する論点へ統合します。
- 第3章から第9章も、単一の短い説明や他章への参照だけでは小節を作りません。
- 一つの小節には、原則として複数段落または同等の情報量を持つ表・checklist・例を置きます。
- 同じ概念を複数章で扱う場合は、作る、使う、評価する、守るという責務で分けます。
- 高度化は技術名から選ばず、評価で観測したfailure patternから選びます。
