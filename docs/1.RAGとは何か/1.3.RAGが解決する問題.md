# 1.3 RAGが扱う問題

## 1.3.1 更新可能な外部知識

モデルを再学習せずに検索対象を更新できることが、RAGの基本的な利点です。
規程改訂や製品更新を反映するには、原文、索引、削除、版の切替を一体で管理します。

検索対象を更新しただけでは、回答の鮮度は保証されません。
古い版の除外、更新時刻の記録、索引への反映確認が必要です。

## 1.3.2 組織固有の情報

一般公開されていない手順、製品仕様、社内FAQを検索対象にすると、組織固有の質問へ回答できます。
利用者の権限を検索時に適用し、閲覧できない資料を回答や引用へ含めないことが前提です。

## 1.3.3 根拠の確認

回答と原文の対応を保持すると、利用者は結論の出所を確認できます。
[ALCE](https://aclanthology.org/2023.emnlp-main.398/)は、引用の正しさと、引用が必要な主張を覆う網羅性を分けて評価しています。

引用番号が付いているだけでは、回答の主張を原文が支持しているとは限りません。
引用先、該当範囲、文書の版を検査できる状態にします。

## 1.3.4 回答できない質問

根拠が見つからない場合に回答を保留することも、RAGの設計対象です。
[SQuAD 2.0](https://aclanthology.org/P18-2124/)は、回答可能な質問と回答不能な質問を区別する課題を扱いました。

本番システムでは、回答保留、確認質問、担当者への引継ぎを業務に合わせて定めます。
