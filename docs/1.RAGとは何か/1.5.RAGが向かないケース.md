# 1.5 RAGが向かないケース

次の処理は、RAGだけでは完結しません。

| 問題 | 適する方式 |
|---|---|
| 正確な集計、残高、在庫の取得 | データベース照会または業務API |
| 承認、発注、更新などの状態変更 | 認可された業務ワークフロー |
| 厳密な計算 | 検証可能な計算処理 |
| 高リスクな最終判断 | 専門家の確認と定められた判断手続 |
| 根拠文書が存在しない質問 | 情報整備、調査、または回答保留 |

RAGからこれらの処理を呼び出す場合は、ツール利用として入力検証、認可、監査を別に設計します。

対象が短い固定文書だけで、全体を毎回入力できる場合は、検索索引を持たない構成の方が単純です。
利用者が原文を読むことが目的なら、検索システムだけで十分な場合があります。

方式を選ぶときは、RAGを使うこと自体を目的にせず、対象文書の量、更新頻度、質問の種類、監査の必要性を比較します。
