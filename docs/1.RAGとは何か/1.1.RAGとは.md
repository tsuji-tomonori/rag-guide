# 1.1. RAGとは

## 1.1.1. RAGの定義

RAGは、外部の情報源から質問に関係する根拠を取得し、その根拠を条件として言語モデルに回答を生成させる方式です。
[LewisらのRAG研究](https://proceedings.neurips.cc/paper/2020/hash/6b493230205f780e1bc26945df7481e5-Abstract.html)では、言語モデルの内部知識と外部の検索可能な記憶を組み合わせています。

業務システムでは、学習時の方式に限らず、質問時に文書を検索して回答へ渡す構成もRAGと呼びます。
本書もこの実務上の広い意味で扱います。

## 1.1.2. 最小の処理

RAGは、次の四工程で捉えると全体像を把握できます。

1. **検索前処理**：文書を解析し、検索できる単位へ分けて索引へ登録します。
2. **検索**：質問に関係する根拠候補を集めます。
3. **検索後処理**：候補を選別し、回答に使う根拠を確定します。
4. **生成**：根拠に基づく回答と引用を作り、根拠が足りなければ回答を保留します。

第2章では、この四工程と第3章から第9章の対応を示します。

## 1.1.3. RAGが提供するもの

RAGを適切に設計すると、情報源の更新、組織固有の情報の利用、引用元の提示、検索と生成の分離評価が可能になります。
回答品質は、登録した資料の鮮度、検索の回収能力、言語モデルによる根拠の利用に左右されます。

RAGの価値は、外部情報を利用し、回答の根拠と失敗箇所を検査できることにあります。
本ガイドでは工程別の成果物を同じquestion IDへ結び、資料の古さ、検索の取りこぼし、取得済み根拠の誤読を別の失敗段階として診断します。
