# 7.8 Regression・A-B・Canary

回帰テストは、変更によって以前動いていた機能が壊れていないかを確認する試験です。
コード変更ごとに基本動作、夜間に主要項目、公開前に拡張、限界条件、安全性の各評価項目群を実行します。

平均値だけでなく、質問ごとの改善と悪化、重要スライスの下限を比較します。
本番で発生した障害は、修正後に固定の評価例へ追加します。

解析器やチャンク分割を変えると、正解スパンのチャンクIDが変わることがあります。
元文書の位置から正解ラベルを移行し、単にID不一致を無視しないようにします。
失敗時の入力、取得候補、最終コンテキスト、回答、設定を保存し、同じ条件を再現可能にします。

## 7.8.1 変更別のregression matrix

index、embedding model、dimension、chunking、reranker、prompt、modelの変更は、影響するlayerが異なります。変更ごとに直接指標と下流指標を定め、改善した局所指標が最終回答を悪化させていないことを確認します。

**表7-2　変更と主な回帰確認**

| 変更 | 直接確認 | 下流確認 |
|---|---|---|
| parser・chunking | 構造保持、正解span保持 | retrieval recall、citation位置 |
| embedding・dimension | dense recall、ANN recall | hybrid順位、answer correctness |
| index設定 | recall、latency、容量 | end-to-end latency、cost |
| reranker | nDCG、top-k保持 | Evidence completeness |
| prompt・model | faithfulness、format | answerability、safety、UX |

## 7.8.2 A-B test

オフライン評価に合格した候補でも、実際の利用者にとっての使いやすさや遅延は変わる可能性があります。
A/Bテストでは、利用者またはセッションを基準構成と候補構成へ固定的に割り当て、結果を比較します。

主要指標、安全性や遅延の監視指標、必要な標本数、実験期間、停止条件を事前に登録します。
[オンライン比較実験の実践指針](https://doi.org/10.1145/1281192.1281295)に沿って、割り当て比率の異常や同時に行われた変更も監視します。

安全性を十分に確認していない候補は、利用者へ回答を返さない並行実行から始めます。
次に少量の利用要求だけで試す段階的公開へ進み、重大違反や遅延急増があれば統計的な有意差を待たずに停止します。

A-B testでは、利用者割当、期間、主要metric、guardrail metric、停止条件を事前に固定します。クリック率や満足度だけでなく、権限、重大誤回答、回答保留率、latency、costを同時に監視します。

## 7.8.3 canary・release gate・rollback

新しいindex、prompt、modelは、全trafficへ一度に適用せず、限定したtenant、query type、traffic比率で公開します。旧構成と同じtraceを取得し、品質・安全性・性能の差を比較します。

canary中に重大なsecurity failure、SLO違反、想定外の回答不能増加が起きた場合は、自動または明示した手順で旧versionへ戻します。

公開の可否は、解析器、チャンク分割、埋め込み、検索器、再順位付け、プロンプト、生成モデルのどれを変えても、同じ原則で判断します。
最低品質、重要スライスの非劣化、安全性、遅延と費用の上限、元に戻す準備をすべて満たすことを要求します。

基本動作確認、夜間、公開前、少量公開の各段階へ評価項目群を割り当てます。
候補の成果物、設定マニフェスト、評価報告を同じ版IDで結び付けます。

平均が改善しても重大事例が悪化すれば公開を止めます。
例外承認には、責任者、期限、監視指標、利用範囲、停止条件を付けます。
