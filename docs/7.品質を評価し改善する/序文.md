# 7. 品質を評価し改善する

RAGの良し悪しは、最終回答だけを見ても判断できません。資料準備、検索、根拠整形、生成のどこで失敗したかを分け、変更による改善と回帰を測る必要があります。

本章では、評価データセット、各layerの指標、end-to-end評価、regression、A-B、canary、trace分析を扱います。第3章のPublish前ゲートから受け取った成果物について、品質面のpublish可否とrelease gateをここで判断します。

本章の節を、次のラベル付きトピック群に分けます。

| トピック群 | 対象節 | 評価上の問い |
|---|---|---|
| G7-A 評価基盤 | 7.1、7.2 | 目的、失敗、正解、対象範囲を固定できるか |
| G7-B 工程別評価 | 7.3から7.6 | 最初に失敗した工程を測定できるか |
| G7-C システム評価 | 7.7、7.8 | 品質、遅延、費用、安全性の回帰を検出できるか |
| G7-D 改善統制 | 7.9、7.10 | 処理履歴から原因を分類し、再評価できるか |

各トピック群では、評価対象、実行方法、合格・停止条件の順に確認します。
