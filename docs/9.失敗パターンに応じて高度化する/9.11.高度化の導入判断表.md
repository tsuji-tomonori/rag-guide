# 9.11. 高度化の導入判断表

高度化手法は、baselineで再現したfailureから選びます。
観測した失敗、最初に確認するbaseline、候補となる高度化を次に対応付けます。

## 9.11.1. failure patternと候補手法

- **会話中の省略や過去turn**：query rewritingとsession境界を確認し、Conversational RAGを比較します。
- **複数sourceの横断**：source catalog、routing、fusionを確認し、Federated・Routed RAGを比較します。
- **DB集計・現在値・厳密計算**：文書RAGとの責務分離を確認し、Structured Data RAGまたは検証済みtoolを比較します。
- **一文書全体の論旨**：chunk、parent-child、packingを確認し、Long-context RAGまたはHierarchical RAGを比較します。
- **entity関係やmulti-hop**：query decompositionとmulti-queryを確認し、GraphRAGを比較します。
- **図表・画像の根拠**：parser、layout、captionを確認し、Multimodal RAGを比較します。
- **複数stepの探索・検証・業務操作**：固定workflowとread-only APIを確認し、Agentic RAGを比較します。
- **モデルによる根拠の軽視**：prompt、context、verificationを確認し、Retrieval-aware trainingを比較します。
- **distractorへの過度な追従**：reranker、Evidence Set、verificationを確認し、Retrieval-aware trainingを比較します。
- **品質向上に伴う応答時間・費用の増加**：routing、cache、model選択を確認し、条件付きroutingまたはcascadeを比較します。

一つのfailureに複数手法が候補となる場合は、最も小さく、rollbackしやすく、既存のevaluation contractを保てる方式から試します。例えば長文の失敗に対して、最初からGraphRAGとAgentic RAGを同時導入せず、parent-child retrievalまたはlong-context routingを個別に比較します。

## 9.11.2. 適用境界と先に試す代替

表9-3は、方式名ではなく再現した失敗から候補を絞るための比較表です。前提を満たさない方式は、研究上の性能にかかわらず導入候補から外します。

**表9-3　高度化手法の適用境界と小さい代替**

| 手法 | 対象の失敗スライス | 適用条件 | 先に試す小さい代替 |
|---|---|---|---|
| Conversational RAG | 省略、照応、過去turn | session境界と参照先を評価できます | 単一turnへの書き換え |
| Federated・Routed RAG | 複数source、source選択 | sourceごとの正解とSLOがあります | 全source並列検索とRRF |
| Structured Data RAG | 集計、現在値、厳密計算 | 許可schemaとread-only実行があります | 固定query API |
| Long-context RAG | 文書全体、遠距離の条件 | 入力上限と位置別評価があります | parent-child retrieval |
| Hierarchical RAG | 概要、複数粒度 | 要約から原文へ戻れます | 見出し階層と親chunk |
| GraphRAG | 関係経路、multi-hop、全体傾向 | 関係schemaと原文provenanceがあります | query分解とmulti-query |
| Multimodal RAG | 図表、画像、layout | ページ画像と正解領域があります | parserとcaption改善 |
| Agentic RAG | 反復探索、検証、tool | step上限、認可、監査があります | 決定的な固定workflow |
| Retrieval-aware training | 根拠の軽視、distractor | 学習・評価分離と再学習予算があります | prompt、配置、生成後検証 |

## 9.11.3. コスト、最低評価、切り戻し

表9-4は、導入後に増える主な負担と、最低限分けて測る値を示します。「追加コスト」は金額だけでなく、構築、更新、推論、監査の複雑さを含みます。

**表9-4　高度化手法の追加負担と切り戻し**

| 手法 | 主な追加コスト | 最低限の評価指標 | 切り戻し先 |
|---|---|---|---|
| Conversational RAG | 履歴保存、書き換え推論 | 意図保持率、Recall、再質問率 | 元質問の単発検索 |
| Federated・Routed RAG | 複数検索、router運用 | source別Recall、誤routing、p95、費用 | 全source基準経路 |
| Structured Data RAG | schema管理、実行検証 | 実行正確性、禁止操作0件、遅延 | 固定APIまたは文書回答 |
| Long-context RAG | 入力token、model遅延 | 位置別正答、支持なし主張、p95、費用 | 通常の検索とpacking |
| Hierarchical RAG | tree構築、要約更新 | 粒度別Recall、要約忠実性、更新時間 | 平坦index |
| GraphRAG | 抽出、統合、graph更新 | 関係precision・recall、経路正解、費用 | 平坦またはhybrid検索 |
| Multimodal RAG | 画像処理、保存、推論 | 領域Recall、OCR差、引用位置、費用 | text parser経路 |
| Agentic RAG | 複数step、tool、監査 | 成功率、step数、誤操作0件、p95、費用 | 固定workflowまたはread-only |
| Retrieval-aware training | 学習data、GPU、再配布 | 未見slice、根拠利用、回帰、学習費用 | 学習前model |

高度化の比較記録では、次の項目を一枚にまとめます。数値は説明用の記入例であり、ほかの業務へ流用しません。

**表9-5　高度化前後の評価記録例**

| 項目 | Baseline | Candidate | 公開条件の例 | 結果 |
|---|---:|---:|---:|---|
| 対象スライスのRecall@20 | 0.72 | 0.84 | 0.80以上 | 合格 |
| 支持なし主張率 | 0.03 | 0.04 | 0.03以下 | 不合格 |
| 回答不能質問の適切な保留率 | 0.91 | 0.94 | 0.90以上 | 合格 |
| p95遅延 | 1.2秒 | 2.1秒 | 2.0秒以下 | 不合格 |
| 一質問当たり費用 | 0.8円 | 1.4円 | 1.5円以下 | 合格 |
| 権限違反 | 0件 | 0件 | 0件 | 合格 |
| 切り戻し試験 | 成功 | 成功 | 成功必須 | 合格 |

この例ではRecallが改善しても、支持なし主張率とp95遅延が条件を外れるため公開しません。結果には、dataset版、対象slice、構成版、実行日時、評価コード版、担当者、証跡URI、切り戻し先も記録します。

## 9.11.4. 導入順序と停止条件

導入前にfailureを固定datasetとtraceで再現し、期待改善、guardrail metric、最大latency、cost budget、security条件を決めます。新方式とbaselineを同じ条件で比較し、局所的な成功例だけで判断しません。

高度化後も改善が再現しない、別sliceを悪化させる、運用負荷やsecurity riskが許容範囲を超える場合は採用を止めます。限定公開では旧経路を残し、異常時にbaselineへ戻せるようにします。

高度化の完了条件は部品の実装ではなく、対象failureの改善、回帰なし、trace可能性、運用手順、rollback試験が揃うことです。
