# 9.11. 高度化の導入判断表

高度化手法は、基準構成で再現した失敗から選びます。
観測した失敗、最初に確認する基準構成、候補となる高度化を次に対応付けます。

## 9.11.1. 失敗パターンと候補手法

- **会話中の省略や過去対話の往復**：質問の書き換えとセッション境界を確認し、Conversational RAGを比較します。
- **複数情報源の横断**：情報源台帳、振り分け、統合を確認し、Federated・Routed RAGを比較します。
- **DB集計・現在値・厳密計算**：文書RAGとの責務分離を確認し、Structured Data RAGまたは検証済みツールを比較します。
- **一文書全体の論旨**：チャンク、親子チャンク、入力への配置を確認し、Long-コンテキスト RAGまたはHierarchical RAGを比較します。
- **実体（人・物・組織など）関係や複数段階の探索**：質問の分解と複数の検索文を確認し、GraphRAGを比較します。
- **図表・画像の根拠**：解析器、レイアウト、説明文を確認し、Multimodal RAGを比較します。
- **複数段階の探索・検証・業務操作**：固定処理手順と読み取り専用 APIを確認し、Agentic RAGを比較します。
- **モデルによる根拠の軽視**：プロンプト、コンテキスト、検証を確認し、Retrieval-aware trainingを比較します。
- **紛らわしい文書への過度な追従**：再順位付け器、Evidence Set、検証を確認し、Retrieval-aware trainingを比較します。
- **品質向上に伴う応答時間・費用の増加**：振り分け、キャッシュ、モデル選択を確認し、条件付き振り分けまたは段階的な切り替えを比較します。

一つの失敗に複数手法が候補となる場合は、最も小さく、切り戻ししやすく、既存の評価契約を保てる方式から試します。
例えば長文の失敗に対して、最初からGraphRAGとAgentic RAGを同時導入せず、親子チャンク検索または長文入力への振り分けを個別に比較します。

## 9.11.2. 適用境界と先に試す代替

表9-3は、方式名ではなく再現した失敗から候補を絞るための比較表です。
前提を満たさない方式は、研究上の性能にかかわらず導入候補から外します。
**表9-3　高度化手法の適用境界と小さい代替**




| 手法 | 対象の失敗スライス | 適用条件 |
|---|---|---|
| Conversational RAG | 省略、照応、過去対話の往復 | セッション境界と参照先を評価できます |
| Federated・Routed RAG | 複数情報源、情報源選択 | 情報源ごとの正解とSLOがあります |
| Structured Data RAG | 集計、現在値、厳密計算 | 許可スキーマと読み取り専用実行があります |
| Long-コンテキスト RAG | 文書全体、遠距離の条件 | 入力上限と位置別評価があります |
| Hierarchical RAG | 概要、複数粒度 | 要約から原文へ戻れます |
| GraphRAG | 関係経路、複数段階の探索、全体傾向 | 関係スキーマと原文来歴があります |
| Multimodal RAG | 図表、画像、レイアウト | ページ画像と正解領域があります |
| Agentic RAG | 反復探索、検証、ツール | 段階上限、認可、監査があります |
| Retrieval-aware training | 根拠の軽視、紛らわしい文書 | 学習・評価分離と再学習予算があります |

## 9.11.4. 導入順序と停止条件

導入前に失敗を固定評価データと処理記録で再現し、期待改善、悪化を監視する指標、最大応答時間、費用上限、安全性条件を決めます。
新方式と基準構成を同じ条件で比較し、局所的な成功例だけで判断しません。

高度化後も改善が再現しない、別部分集合を悪化させる、運用負荷や安全上のリスクが許容範囲を超える場合は採用を止めます。
限定公開では旧経路を残し、異常時に基準構成へ戻せるようにします。

高度化の完了条件は部品の実装ではなく、対象失敗の改善、回帰なし、処理記録可能性、運用手順、切り戻し試験が揃うことです。
