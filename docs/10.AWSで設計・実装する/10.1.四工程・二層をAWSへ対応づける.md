# 四工程・二層をAWSへ対応づける

AWSリソースを選ぶ前に、質問より前に作るものと、質問ごとに動かすものを分けます。
四工程と二層は、処理の目的と実行時の責任という、異なる軸で整理します。
検索前処理のうち、文書解析、チャンク分割、埋め込み、索引作成はBatch Layerに置き、質問理解、質問変換、検索条件作成はReal-time Layerに置きます。
検索、検索後処理、生成は主にReal-time Layerで動きます。
**表10-1 四工程・二層とAWS機能の対応**

| 層／工程 | 入力 | 主な処理 |
|---|---|---|
| Batch Layer／文書側の検索前処理 | 原文、メタデータ | 収集、解析、チャンク分割、埋め込み、索引作成 |
| Real-time Layer／質問側の検索前処理 | 質問、会話、認証済み利用者属性 | 質問理解、質問変換、検索条件作成 |
| Real-time Layer／検索 | 検索文、フィルター | キーワード、ベクトル、ハイブリッド、メタデータフィルター |
| Real-time Layer／検索後処理 | 根拠候補 | 再順位付け、選別、根拠整形 |
| Real-time Layer／生成 | 質問、根拠集合 | 回答、引用、回答保留 |
| 横断する管理面／全工程 | 識別情報、キー、設定版、実行記録、評価データ | 認可、暗号化、監視、評価、版管理、費用配賦 |

| 層／工程 | 出力 | 主なAWS機能 |
|---|---|---|
| Batch Layer／文書側の検索前処理 | 検索可能なチャンクと索引 | Amazon S3、Bedrock Knowledge Bases、Bedrock 埋め込みモデル、S3 Vectors、OpenSearch Serverless |
| Real-time Layer／質問側の検索前処理 | 検索文、フィルター、検索計画 | アプリケーション、Bedrock生成モデル、Managed KBのエージェント型検索 |
| Real-time Layer／検索 | 根拠候補 | Knowledge Bases、S3 Vectors、OpenSearch Serverless |
| Real-time Layer／検索後処理 | 根拠集合 | Bedrock 再順位付けモデル、アプリケーション実行基盤 |
| Real-time Layer／生成 | 根拠付き回答 | Bedrock生成モデル、Customer-managed KBのRetrieveAndGenerate、Converse |
| 横断する管理面／全工程 | 監査可能な実行記録 | IAM、KMS、CloudWatch、CloudTrail、Guardrails、AgentCore Observability、AWS Budgets |


```text
                      検索前処理                  検索          検索後処理          生成
Batch Layer       原文→解析→Chunk→Embedding→索引
                  S3 / Knowledge Bases / Embedding / S3 Vectors・OpenSearch

Real-time Layer   質問理解→Query・Filter ─────→候補取得──────→Rerank・Evidence──→回答・引用・保留
                  Application / Bedrock       KB・Store       Rerank / App       Bedrock Model

横断する管理面     IAM・KMS・監視・評価・版管理・コスト管理を全区間へ適用
```

**図10-1 四工程・二層とAWSサービスの全体対応**

Batch Layerの終点は、単にベクトルが保存された状態ではありません。
原文の版、チャンクの由来、メタデータ、埋め込みモデルと次元、索引版を関連づけ、公開可能な索引としてReal-time Layerへ引き渡せる状態です。
Real-time Layerの終点も、単にモデルの文章を返す状態ではありません。
採用根拠、引用、利用した設定版、回答保留理由を追跡できる状態です。

## 入力と出力の境界を固定する

工程間の境界を固定すると、検索品質と生成品質を分けて評価できます。
検索の出力は取得候補、検索後処理の出力は根拠集合、生成の出力は根拠付き回答です。
`RetrieveAndGenerate`のように複数工程をまとめるAPIを使う場合でも、この論理境界は評価上残します。

| 境界 | 最低限保持する情報 | 第3〜7章との対応 |
|---|---|---|
| Batch→Real-time | 原文ID、チャンク ID、メタデータ、索引版、埋め込み版 | 第3章の分割・埋め込み、第7章の評価再現性 |
| 検索前処理→検索 | 原質問、検索文、フィルター、利用者コンテキスト | 第4章の検索文理解とメタデータフィルター |
| 検索→検索後処理 | 候補本文、出典位置、検索スコア、検索器 | 第4章のSparse・Dense・ハイブリッド検索 |
| 検索後処理→生成 | 根拠、出典、採否理由、矛盾、回答可能性 | 第5章の根拠集合とコンテキスト設計 |
| 生成→利用者 | 回答、引用、保留理由、モデル・プロンプト・Guardrail版 | 第6章の根拠に基づく生成、第7章の回答評価 |

AWSに基盤の運用を任せた後も、検索品質と回答品質を対象データで評価します。
設定は基準構成から始め、第7章の評価で工程別に比較します。
[Knowledge Basesの仕組み](https://docs.aws.amazon.com/bedrock/latest/userguide/kb-how-it-works.html)と[Knowledge Basesの評価](https://docs.aws.amazon.com/bedrock/latest/userguide/evaluation-kb.html)も、この分離を前提に利用します（確認日：2026年9月5日）。
