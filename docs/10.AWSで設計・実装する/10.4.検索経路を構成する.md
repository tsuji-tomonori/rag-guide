# 10.4. 検索経路を設定する

## 10.4.1. Retrieveの候補数と検索方式を設定する

検索と生成を分ける場合は、Bedrock Agent Runtimeの`Retrieve`を呼び出します。`numberOfResults`は1から100まで指定できます。初期値は20とし、5、10、20、50でRecall@k、reranking後の採用率、p95 latencyを比較します。生成へ渡す件数ではなく、初段検索が返すcandidate数として扱います。

`overrideSearchType`は`SEMANTIC`または`HYBRID`です。[KnowledgeBaseVectorSearchConfiguration API](https://docs.aws.amazon.com/bedrock/latest/APIReference/API_KnowledgeBaseVectorSearchConfiguration.html)では、Knowledge Basesの`HYBRID`はfilterable text fieldを持つOpenSearch Serverlessだけで利用できます。S3 Vectors、Aurora、MongoDBなど、ほかのvector storeでは`SEMANTIC`を指定します。

OpenSearch Serverlessで`HYBRID`を使うindexは、vector engineを`faiss`とし、embedding modelと同じdimensionのvector field、元のchunkを格納するfilterableなtext field、filter対象のmetadata field、Bedrockが管理するmetadata fieldを作成します。たとえば、`bedrock-knowledge-base-default-vector`をvector field、`AMAZON_BEDROCK_TEXT_CHUNK`をfilterableなtext field、`AMAZON_BEDROCK_METADATA`をBedrock metadata fieldとしてKnowledge Base作成時に対応付けます。field名は任意ですが、index mappingとKnowledge Baseの設定を一致させます。

```json
{
  "retrievalConfiguration": {
    "vectorSearchConfiguration": {
      "numberOfResults": 20,
      "overrideSearchType": "SEMANTIC"
    }
  }
}
```

## 10.4.2. S3 Vectorsで疎検索を補う

S3 Vectorsはdense vectorによるsemantic searchとmetadata filterを提供し、BM25などのsparse searchは提供しません。固有名詞や識別子の取りこぼしがある場合は、S3 VectorsへHYBRID指定を送るのではなく、次のいずれかを選びます。

1. vector storeをOpenSearch Serverlessへ変更し、Knowledge Basesの`HYBRID`を使います。
2. S3 Vectorsのsemantic結果とOpenSearchのBM25結果を別々に取得し、LambdaでRRFを適用します。
3. sparse結果とdense結果をまとめてBedrock rerankerへ渡します。

複数検索器のscoreは尺度が異なるため直接加算しません。RRFでは各検索器の順位を使い、rerankerでは統合後のcandidate本文を再評価します。実装根拠と評価方法は[Hybrid retrieval](../4.質問に合う根拠を探す/4.5.Hybrid retrieval.md)を参照します。

二つの検索器には同じ安定した`chunk_id`を登録し、本文、version、filter metadata、アクセス制御属性を対応付けます。更新と削除は両方へ伝播させ、片方だけに残ったchunkを定期的に検出します。初期比較ではdenseとBM25を各20件、統合後を20件、rerank後を5件とし、各retrieverのcandidate数、timeout、zero-result、失敗時の扱いを独立に記録します。これらの値は固定仕様ではなく、Recallとonline latency budgetを測るための開始値です。

## 10.4.3. Metadata filterを必須条件として渡す

検索条件は`retrievalConfiguration.vectorSearchConfiguration.filter`へ指定します。公開状態と版を同時に限定する例は次のとおりです。

```json
{
  "andAll": [
    {"equals": {"key": "status", "value": "published"}},
    {"equals": {"key": "version", "value": "2026-07"}}
  ]
}
```

`equals`、`in`、`greaterThan`、`listContains`などの候補は[RetrievalFilter API](https://docs.aws.amazon.com/bedrock/latest/APIReference/API_agent-runtime_RetrievalFilter.html)で確認します。`startsWith`はOpenSearch Serverlessだけに対応します。それ以外のoperatorもvector storeごとに実装範囲が異なるため、Bedrock APIに列挙されているだけで同じ式を全storeへ流用できるとは判断しません。S3 Vectorsを直接queryする場合は、[S3 Vectorsのmetadata filter](https://docs.aws.amazon.com/AmazonS3/latest/userguide/s3-vectors-metadata-filtering.html)に記載されたoperatorだけを使います。filter後の候補不足を見落とさないように、filter前後の件数とzero-result率を記録します。

## 10.4.4. Rerankingを設定する

rerankerを使うときは、初段の`numberOfResults`をrerank後の件数より大きくします。初期値は20件を取得して5件へrerankし、10→5、20→5、50→10を比較します。[Bedrock reranker](https://docs.aws.amazon.com/bedrock/latest/userguide/rerank-use.html)の`numberOfResults`は、rerank後に返す件数です。

初段Recallが不足している場合、rerankerは見つからなかった根拠を復元できません。Recall@20、rerank後nDCGまたはMRR、生成に採用した件数、追加latencyを分けて評価します。
