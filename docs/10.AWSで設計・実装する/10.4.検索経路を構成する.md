# 10.4 検索経路を構成する

オンライン検索の基本経路は、`API Gateway → Lambda → Retrieve → ベクトルストア`です。
Lambdaで利用者の認証情報を検証し、認可済み属性をメタデータフィルターへ変換してから検索します。

| 境界 | 責務 |
|---|---|
| API GatewayのJWT authorizerまたはIAM authorizer | 呼び出し主体を確定し、未検証の要求を拒否します。 |
| Lambda | 検証済みの属性だけから、利用者が変更できない必須フィルターを作ります。 |
| Lambda実行ロール | Knowledge BasesとBedrock Runtimeの呼び出しなど、処理に必要なAWS権限だけを持たせます。 |

利用者の文書アクセス権とLambda実行ロールのAWS権限は別の認可です。
IAM権限だけで文書単位の利用者認可を代替しません。

[Retrieve API](https://docs.aws.amazon.com/bedrock/latest/userguide/kb-test-retrieve.html)は、回答生成を行わず、根拠候補と出典情報を返します。
検索と生成を分けて評価する場合や、独自の根拠整形を入れる場合に使います。

[検索設定](https://docs.aws.amazon.com/bedrock/latest/userguide/kb-test-config.html)では、候補件数、メタデータフィルター、検索方式、再順位付け、クエリ分解を設定できます。
ハイブリッド検索は語彙一致とベクトル一致を組み合わせますが、利用できる検索方式はベクトルストアと構成によって異なります。
メタデータの型、比較演算子、ハイブリッド検索、フィルター付き近似検索、アクセス制御属性の表現は、選択したベクトルストアで検証します。

再順位付けを有効にする場合も、初段検索のRecallと再順位付け後の採用率を分けて記録します。
クエリ分解やエージェント検索は、複数段階の質問で基準構成を上回ることを第7章のデータセットで確認してから有効にします。

構造化データを参照する場合は、LambdaからAurora、Amazon Redshift、Amazon Athenaなどへ読み取り専用で問い合わせます。
関係探索を追加する場合はNeptune Analyticsを別検索器として接続し、通常検索との順位統合をLambdaで行います。
どちらも生成されたクエリを無条件に実行せず、許可したスキーマ、操作、件数、時間へ制限します。
