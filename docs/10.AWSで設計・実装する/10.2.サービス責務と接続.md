# 10.2 Embeddingとvector indexを設定する

## 10.2.1 Embeddingの役割を確認する

embeddingは、textやimageを固定長の数値vectorへ変換し、意味の近さを距離として比較できるようにする処理です。queryとdocumentを同じ検索空間で比較するため、index作成時とquery時で互換性のないmodel、revision、dimensionを混ぜません。仕組み、similarity、chunkとの関係は[Embedding設計](../3.回答に使う資料を準備する/3.6.Embedding設計.md)を参照します。

Knowledge Basesで選べるmodelとリージョンは[対応embedding model](https://docs.aws.amazon.com/bedrock/latest/userguide/knowledge-base-supported.html)で確認します。日本語を含む場合は、Cohere Embed Multilingual v3を比較対象に含めます。Titan Text Embeddings V2も候補にし、日本語のgold queryでRecall@kを直接比較します。model名だけで日本語適合を断定しません。採用したmodel ID、region、model revision、dimension、正規化の有無、Cohereで使う`input_type`はdeployment manifestへ保存し、query経路と取り込み経路で同じ設定を参照します。

## 10.2.2 Modelとdimensionを選ぶ

**Amazon Titan Text Embeddings V2**は、Knowledge Basesで1024、512、256次元を選べます。
初期比較は`dimensions=1024`、`normalize=true`、`embeddingTypes=["float"]`で始め、512次元と256次元はRecall、保存量、応答時間を同じ質問で比較します。

**Cohere Embed Multilingual v3**は1024次元を使います。
documentは`input_type="search_document"`、queryは`input_type="search_query"`とし、日本語、多言語、固有名詞、短いqueryを含む評価データで確認します。

**managed embedding**は、modelとdimensionの運用をサービスへ委ねる選択です。
modelの固定要件、再索引の条件、managed rerankerとの組み合わせを確認して採用します。

[Titan Text Embeddings V2のrequest](https://docs.aws.amazon.com/bedrock/latest/userguide/model-parameters-titan-embed-text.html)では、1024、512、256次元と正規化を指定できます。[Cohere Embed v3](https://docs.aws.amazon.com/bedrock/latest/userguide/model-parameters-embed-v3.html)では、documentとqueryで`input_type`を使い分けます。modelまたはdimensionを変えると既存vectorと互換にならないため、新しいindexを作成して再embeddingします。

## 10.2.3 S3 Vector indexを作成する

Titan Text Embeddings V2の1024次元、正規化済みfloat vectorを使う、S3 Vector index単体の初期例は次のとおりです。

```sh
aws s3vectors create-index \
  --vector-bucket-name rag-vector-bucket \
  --index-name rag-titan-v2-1024 \
  --data-type float32 \
  --dimension 1024 \
  --distance-metric cosine \
  --metadata-configuration \
    '{"nonFilterableMetadataKeys":["text","source_uri"]}'
```

`dimension`、`distance-metric`、non-filterable metadata keyはindex作成後に変更できません。[S3 Vector indexの設定](https://docs.aws.amazon.com/AmazonS3/latest/userguide/s3-vectors-create-index.html)に従い、正規化vectorには`cosine`を初期値とし、magnitudeも意味を持つmodelでは`euclidean`を比較します。Knowledge BasesとS3 Vectorsを組み合わせる場合、custom metadataはvector当たり1 KB、35 keyまでです。parent-child情報を持つhierarchical chunkingでは上限超過も確認します。

Knowledge Basesへ既存indexを接続するときは、embeddingのdimensionとindexのdimensionが一致することを確認します。OpenSearch Serverlessを接続する場合は、vector field、filterableなtext field、filter対象のmetadata field、Bedrockが管理するmetadata fieldの名前も接続設定と同じmanifestへ記録します。
