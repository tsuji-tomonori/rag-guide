# 10.2 サービス責務と接続

基本構成は、次の接続で表せます。

`Amazon S3またはカスタムデータソース → Bedrock Knowledge Bases → ベクトルストア`

`Amazon API Gateway → AWS Lambda → Bedrock Knowledge Bases → Amazon Bedrock生成モデル`

`処理ログ → Amazon CloudWatch、AWS CloudTrail → 評価データ用Amazon S3`

| 責務 | AWSサービス | 接続先 |
|---|---|---|
| 原本保存 | Amazon S3 | Bedrock Knowledge Basesのデータソース |
| 任意データ取り込み | カスタムデータソース、AWS Lambda | Bedrock Knowledge Bases |
| 解析・分割・埋め込み | Bedrock Knowledge Bases、Bedrock Data Automation、基盤モデル、Lambda | ベクトルストア |
| ベクトル検索 | S3 Vectors、OpenSearch Serverless、Aurora PostgreSQLなど | Bedrock Agent Runtime API |
| 関係検索 | Amazon Neptune Analytics | Lambdaまたは検索オーケストレーター |
| API公開 | API Gateway、Lambda | `Retrieve`、`AgenticRetrieveStream`、`Converse` |
| 認証・認可 | Amazon Cognito、AWS IAM | API Gateway、Lambda、各データプレーン |
| 入出力保護 | Amazon Bedrock Guardrails | Lambda、Bedrock Runtime |
| 監視・監査 | CloudWatch、CloudTrail、AWS X-Ray | アラーム、監査用S3 |
| 評価 | Amazon Bedrock Evaluations、S3 | 評価レポート、公開判定 |

ネットワークを閉域化する場合は、VPC、セキュリティグループ、AWS PrivateLinkの対応状況をサービスごとに確認します。
暗号鍵を統制する場合は、AWS Key Management Serviceのカスタマーマネージドキーと、各サービスのキー利用権限をそろえます。

サービス境界を越えるたびに、文書ID、チャンクID、版、アクセス制御属性、処理トレースIDを保持します。
この情報が欠けると、引用、削除反映、認可、障害調査を一貫して実施できません。
