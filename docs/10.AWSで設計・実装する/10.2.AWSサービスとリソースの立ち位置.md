# AWSサービスとリソースの立ち位置を整理する

RAGで使うAWSサービスは、同じ責任を持つ代替製品ではありません。原文を保持する資源、検索を仲介する資源、検索そのものを実行する資源、Model推論を行う資源、Agentアプリケーションを動かす資源に分けます。

| AWS機能 | RAGでの立ち位置 | 主な責務 | 担わない責務 |
|---|---|---|---|
| Amazon S3 | 原文・正本ストレージ | 原文、版、取り込み対象、付随Metadataの保存 | Vector検索、Chunking、回答生成 |
| Bedrock Managed Knowledge Base | AWS管理のRAG検索基盤 | 取り込み、保存、索引、検索基盤、既定のEmbeddingとReranking | 回答品質の保証、業務固有ルール |
| Customer-managed Knowledge Base | 利用者選択のModel・Storeを仲介するRAG基盤 | 取り込み、Chunkと出典の管理、検索API、任意の生成連携 | Vector Storeの方式選定とSchema設計の代行 |
| Amazon S3 Vectors | Semantic Search中心のVector Store | Vector、Metadata、類似検索 | 原文解析、Keyword Search、回答生成 |
| Amazon OpenSearch Serverless | Keyword・Vector検索エンジン | 全文、Vector、Hybrid、Filter、検索分析 | RAG全体のオーケストレーション |
| Bedrock Embedding Model | 表現変換 | 文書と質問をVectorへ変換 | Vector保存、検索 |
| Bedrock Rerank Model | 検索後処理 | 質問に対する候補の関連度を再計算 | 検索漏れの回復、業務上の信頼度判定 |
| Bedrock生成モデル | 生成 | Evidenceから回答、要約、構造化出力を生成 | Evidenceの正しさ、ACLの保証 |
| Bedrock Guardrails | 入出力制御 | 有害内容、禁止話題、機密情報などのPolicy評価 | 取得Reference自体の検査と認可 |
| Amazon Bedrock AgentCore | Agentアプリケーション基盤 | Runtime、Tool接続、Identity、Memory、Policy、Observability | Knowledge BaseやVector Storeの代替 |

**表10-2 AWSサービスとリソースの立ち位置**

Amazon Bedrockを一つの箱として扱うと、責任分界を誤ります。Knowledge Bases、Embedding、Rerank、Generation、Guardrailsはそれぞれ異なるAPI、権限、費用、版、評価指標を持つため、構成図と実行記録でも分けます。[Amazon Bedrock Knowledge Bases](https://docs.aws.amazon.com/bedrock/latest/userguide/knowledge-base.html)、[Rerank](https://docs.aws.amazon.com/bedrock/latest/userguide/rerank.html)、[Guardrails](https://docs.aws.amazon.com/bedrock/latest/userguide/guardrails.html)を個別の構成要素として扱います（確認日：2026年8月22日）。

## 接続関係を読む

Customer-managed Knowledge Baseを使う場合、S3はData Source、Embedding Modelは表現変換、S3 VectorsまたはOpenSearch Serverlessは検索先です。Knowledge Baseはこれらを接続し、Chunkと原文Locationを対応づけ、共通の検索APIを提供します。Knowledge Base自体をVector Databaseと呼ばない理由はここにあります。

Managed Knowledge Baseでは、保存・索引・検索基盤がサービス内へ隠蔽されます。利用者はVector Storeのリソースを作らず、`Retrieve`または`AgenticRetrieveStream`を境界にします。Customer-managed Knowledge Baseでは、利用者がEmbedding ModelとVector Storeを選び、`Retrieve`または`RetrieveAndGenerate`を境界にします。

AgentCoreはその外側に置きます。AgentCore Runtimeで動くAgentは、Gateway経由またはアプリケーションコードからKnowledge Baseや業務APIをToolとして利用できます。通常の一問一答RAGで、Tool、Memory、反復実行、Tool単位のPolicyが不要なら、Lambda、ECS、EKSなどの通常アプリケーションだけで十分な場合があります。[AgentCoreの概要](https://docs.aws.amazon.com/bedrock-agentcore/latest/devguide/what-is-bedrock-agentcore.html)（確認日：2026年8月22日）。

## AWSが提供する機能と利用者の判断を分ける

| 区分 | AWSが提供するもの | 利用者が引き受けるもの |
|---|---|---|
| 処理基盤 | Storage、Index、Model hosting、Auto Scaling、API | 要件、Schema、業務ルール、失敗時の振る舞い |
| 品質 | Retrieval Score、Rerank Score、引用元情報、評価機能 | 正解データ、合格基準、比較、回帰判定 |
| セキュリティ | IAM、KMS、Network Policy、Guardrails、監査ログ | Identityの信頼、最小権限、Data分類、Key Policy、Filter生成 |
| 運用 | Metrics、Logs、Trace、Service health | SLO、Alert、保持期間、Masking、費用配賦、復旧手順 |
| 変更 | Model・機能の版、リソース更新API | 変更承認、再Embedding・再索引、評価、切替、Rollback |

この責任分界は、以降の各機能説明で「RAGでの目的」から「個別実装が必要になる条件」まで同じ順序で具体化します。
