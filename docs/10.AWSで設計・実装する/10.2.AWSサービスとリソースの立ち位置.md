# AWSサービスとリソースの立ち位置を整理する

RAGで使うAWSサービスには、それぞれに異なる役割があります。
原文を保持する資源、検索を仲介する資源、検索そのものを実行する資源、モデル推論を行う資源、エージェントアプリケーションを動かす資源に分けます。
**表10-2 AWSサービスとリソースの立ち位置**

| AWS機能 | RAGでの立ち位置 | 主な責務 |
|---|---|---|
| Amazon S3 | 原文・正本ストレージ | 原文、版、取り込み対象、付随メタデータの保存 |
| Bedrock Managed Knowledge Base | AWS管理のRAG検索基盤 | 取り込み、保存、索引、検索基盤、既定の埋め込みと再順位付け |
| Customer-managed Knowledge Base | 利用者選択のモデル・ストアを仲介するRAG基盤 | 取り込み、チャンクと出典の管理、検索API、任意の生成連携 |
| Amazon S3 Vectors | 意味検索中心のベクトルストア | ベクトル、メタデータ、類似検索 |
| Amazon OpenSearch Serverless | キーワード・ベクトル検索エンジン | 全文、ベクトル、ハイブリッド、フィルター、検索分析 |
| Bedrock 埋め込みモデル | 表現変換 | 文書と質問をベクトルへ変換 |
| Bedrock 再順位付けモデル | 検索後処理 | 質問に対する候補の関連度を再計算 |
| Bedrock生成モデル | 生成 | 根拠から回答、要約、構造化出力を生成 |
| Bedrock Guardrails | 入出力制御 | 有害内容、禁止話題、機密情報などのポリシー評価 |
| Amazon Bedrock AgentCore | エージェントアプリケーション基盤 | 実行環境、ツール接続、識別情報、記憶管理、ポリシー、実行状態の観測 |

| AWS機能 | 担わない責務 |
|---|---|
| Amazon S3 | ベクトル検索、チャンク分割、回答生成 |
| Bedrock Managed Knowledge Base | 回答品質の保証、業務固有ルール |
| Customer-managed Knowledge Base | ベクトルストアの方式選定とスキーマ設計の代行 |
| Amazon S3 Vectors | 原文解析、キーワード検索、回答生成 |
| Amazon OpenSearch Serverless | RAG全体のオーケストレーション |
| Bedrock 埋め込みモデル | ベクトル保存、検索 |
| Bedrock 再順位付けモデル | 検索漏れの回復、業務上の信頼度判定 |
| Bedrock生成モデル | 根拠の正しさ、ACLの保証 |
| Bedrock Guardrails | 取得参照資料自体の検査と認可 |
| Amazon Bedrock AgentCore | Knowledge Baseやベクトルストアの代替 |


Amazon Bedrockを一つの箱として扱うと、責任分界を誤ります。
Knowledge Bases、埋め込み、再順位付け、生成、Guardrailsはそれぞれ異なるAPI、権限、費用、版、評価指標を持つため、構成図と実行記録でも分けます。
[Amazon Bedrock Knowledge Bases](https://docs.aws.amazon.com/bedrock/latest/userguide/knowledge-base.html)、[Rerank](https://docs.aws.amazon.com/bedrock/latest/userguide/rerank.html)、[Guardrails](https://docs.aws.amazon.com/bedrock/latest/userguide/guardrails.html)を個別の構成要素として扱います（確認日：2026年9月5日）。

## 接続関係を読む

Customer-managed Knowledge Baseを使う場合、S3はデータソース、埋め込みモデルは表現変換、S3 VectorsまたはOpenSearch Serverlessは検索先です。
Knowledge Baseはこれらを接続し、チャンクと原文出典位置を対応づけ、共通の検索APIを提供します。
Knowledge Base自体をベクトルデータベースと呼ばない理由はここにあります。

Managed Knowledge Baseでは、保存・索引・検索基盤がサービス内へ隠蔽されます。
利用者はベクトルストアのリソースを作らず、`Retrieve`または`AgenticRetrieveStream`を境界にします。
Customer-managed Knowledge Baseでは、利用者が埋め込みモデルとベクトルストアを選び、`Retrieve`または`RetrieveAndGenerate`を境界にします。

AgentCoreはその外側に置きます。
AgentCore Runtimeで動くエージェントは、Gateway経由またはアプリケーションコードからKnowledge Baseや業務APIをツールとして利用できます。
通常の一問一答RAGで、ツール、記憶管理、反復実行、ツール単位のポリシーが不要なら、Lambda、ECS、EKSなどの通常アプリケーションだけで十分な場合があります。
[AgentCoreの概要](https://docs.aws.amazon.com/bedrock-agentcore/latest/devguide/what-is-bedrock-agentcore.html)（確認日：2026年9月5日）。

## AWSが提供する機能と利用者の判断を分ける

| 区分 | AWSが提供するもの | 利用者が引き受けるもの |
|---|---|---|
| 処理基盤 | 保存容量、インデックス、モデルホスティング、自動拡張、API | 要件、スキーマ、業務ルール、失敗時の振る舞い |
| 品質 | 検索スコア、再順位付けスコア、引用元情報、評価機能 | 正解データ、合格基準、比較、回帰判定 |
| セキュリティ | IAM、KMS、ネットワークポリシー、Guardrails、監査ログ | 識別情報の信頼、最小権限、データ分類、キー ポリシー、フィルター生成 |
| 運用 | 指標、ログ、トレース、サービスの稼働状況 | SLO、通知、保持期間、マスキング、費用配賦、復旧手順 |
| 変更 | モデル・機能の版、リソース更新API | 変更承認、再埋め込み・再索引、評価、切替、切り戻し |

この責任分界は、以降の各機能説明で「RAGでの目的」から「個別実装が必要になる条件」まで同じ順序で具体化します。
