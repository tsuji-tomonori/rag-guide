# 10.1 構成方式を選ぶ

## 10.1.1 検索と生成の分離境界を決める

標準的な文書RAGは、Amazon Bedrock Knowledge Basesで取り込み、embedding、vector storeへの登録、`Retrieve`または`RetrieveAndGenerate`までを構成できます。最初の基準構成では、単一のKnowledge Base、単一のdata source、単一のembedding modelを使い、検索と生成を別々に評価できるようにします。

`RetrieveAndGenerate`は検索と引用付き生成を短く接続できます。重複排除、独自reranking、矛盾処理、Evidence Set、claim単位の検査を入れる場合は、`Retrieve → Lambdaなどの検索後処理 → Converse`へ分けます。分離する判断は[根拠整形](../5.根拠を選別・整形する/序文.md)で必要な処理が、Knowledge Basesの検索設定だけで表現できるかによって行います。

## 10.1.2 Vector storeを検索要件から選ぶ

vector storeは保存先ではなく、利用できる検索方式とfilterの制約を決めます。

| 選択肢 | 密検索 | 疎検索 | HYBRID | 主な使い分け |
|---|---|---|---|---|
| Amazon S3 Vectors | 対応 | 非対応 | 非対応 | float32のsemantic searchとmetadata filterを、単純な構成で使う場合 |
| Amazon OpenSearch Serverless | 対応 | 対応 | 対応 | vectorとraw textを組み合わせ、語彙一致、filter、facetも必要な場合 |
| Amazon Aurora PostgreSQL | 対応 | 構成による | Knowledge Basesでは非対応 | 既存のrelational dataとvectorを近い境界で管理する場合 |
| Knowledge Basesのmanaged vector store | 対応 | 対応storeに依存 | 対応storeに依存 | model、dimension、索引運用をサービスへ任せる場合 |

[S3 VectorsとKnowledge Basesの制約](https://docs.aws.amazon.com/AmazonS3/latest/userguide/s3-vectors-bedrock-kb.html)では、S3 Vectorsはsemantic searchのみで、hybrid searchとbinary embeddingには対応しません。語彙一致が必要なら、OpenSearch Serverlessを選ぶか、S3 Vectorsの密検索とOpenSearchのBM25を別々に実行し、[Hybrid retrieval](../4.質問に合う根拠を探す/4.5.Hybrid retrieval.md)のRRFまたはrerankerで統合します。

## 10.1.3 基準構成を固定する

開始構成は、`S3 data source → Knowledge Bases → S3 VectorsまたはOpenSearch Serverless → Retrieve → Converse`とします。初回の比較では、chunking、embedding、検索方式、候補数、reranking、生成modelを同時に変更しません。

S3 Vectorsはsemantic searchだけで要件を満たすかを確認する基準になります。固有名詞、製品コード、条文番号などで語彙一致の取りこぼしが再現した場合に、OpenSearch ServerlessのHYBRIDまたは複数検索器へ進みます。
