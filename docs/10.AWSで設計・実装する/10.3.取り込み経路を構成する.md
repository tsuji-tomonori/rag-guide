# 10.3 取り込み経路を構成する

標準の取り込み経路は、`S3 → Knowledge Basesの同期 → 文書解析 → 分割 → 埋め込み → ベクトルストア`です。
文書の追加、更新、削除後に同期し、公開中の索引版と処理中の版を区別します。

[データソースの取り込み設定](https://docs.aws.amazon.com/bedrock/latest/userguide/kb-data-source-customize-ingestion.html)では、解析方式、分割方式、埋め込み、ベクトルストアへの書き込みを設定します。
表や複雑なPDFには、[高度な文書解析](https://docs.aws.amazon.com/bedrock/latest/userguide/kb-advanced-parsing.html)でBedrock Data Automationまたは基盤モデルによる解析を選べます。

標準処理で出典位置や業務上の検索単位を保てない場合は、[カスタム変換Lambda](https://docs.aws.amazon.com/bedrock/latest/userguide/kb-custom-transformation.html)を接続します。
Lambdaは、解析済み文書とメタデータを受け取り、独自チャンクと属性を返します。
変換結果には、元S3オブジェクト、版、ページまたは位置、アクセス制御属性を残します。

S3以外の情報源や、利用者側で差分を送る処理には、[カスタムデータソース](https://docs.aws.amazon.com/bedrock/latest/userguide/custom-data-source-connector.html)を使います。
EventBridge SchedulerまたはStep Functionsで同期を起動する場合は、同じ変更を再送しても結果が壊れない冪等性を持たせます。

取り込み完了を、同期APIの成功だけで判断しません。
第3章と第7章に従い、解析失敗率、索引件数、削除反映、権限属性の欠損、固定質問の検索結果を確認してから参照先を切り替えます。
