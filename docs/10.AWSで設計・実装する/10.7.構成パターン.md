# 10.7 構成パターン

## 10.7.1 標準的な文書RAG

顧客管理Knowledge Baseの場合は、次の経路を使います。

`S3 → Bedrock Knowledge Bases → S3 VectorsまたはOpenSearch Serverless → RetrieveAndGenerate → Bedrock生成モデル`

マネージドKnowledge Baseの場合は、`AgenticRetrieveStream`または`Retrieve`から生成経路へ接続します。
どちらも文書中心で、標準的な解析、検索、引用を使う開始構成です。

## 10.7.2 検索と生成を分けるAdvanced RAG

`API Gateway → Lambda → Retrieve → 独自の再順位付け・Evidence Set → Converse`

第5章の重複除去、矛盾処理、根拠配置、独自引用を実装する構成です。
各処理の入出力をS3またはログへ残し、第7章の工程別評価へ接続します。

## 10.7.3 複数検索器を使うRAG

`Lambda → Knowledge Bases、OpenSearch、AuroraまたはAthena、Neptune Analytics → 順位統合 → Converse`

文書、構造化データ、関係グラフを別の検索器で取得する構成です。
情報源ごとの認可と鮮度を確認し、異なる検索スコアを直接加算せず、順位統合または再順位付けを使います。

## 10.7.4 マルチモーダル文書RAG

`S3 → Bedrock Data Automationまたは高度な解析 → Knowledge Bases → Retrieve → Converse`

PDFのレイアウト、表、画像を保持する構成です。
[マルチモーダルKnowledge Base](https://docs.aws.amazon.com/bedrock/latest/userguide/kb-multimodal.html)の対応モデル、保存先、引用情報を実装時に確認します。

どの構成でも、基準構成との差を固定評価データで比較します。
品質改善が遅延、費用、安全性の悪化に見合わない場合は、高度化を停止して単純な構成へ戻します。
