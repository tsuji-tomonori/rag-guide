# 10.6 評価と運用を接続する

評価経路は、`評価データ用S3 → Amazon Bedrock Evaluations → 評価レポート → 公開判定`です。
[Knowledge BaseのRAG評価](https://docs.aws.amazon.com/bedrock/latest/userguide/evaluation-kb.html)を使い、検索だけの評価と、検索から生成までの評価を分けます。

Bedrock Evaluationsの結果だけでなく、第7章で定義した検索Recall、引用の正確さ、回答保留、遅延、費用、安全性を同じ版へ結び付けます。
モデル、Knowledge Base、データソース同期、埋め込み、再順位付け、プロンプト、Guardrailの版を評価結果へ記録します。
変更前後で、`Recall@候補数`、Evidence sufficiency、p95遅延、質問当たり費用を同じS3評価データで比較します。
事前に定めた公開基準を一つでも満たさない場合は、参照先の切り替えを停止します。

実行ログとメトリクスはCloudWatchへ送り、API Gateway、Lambda、Bedrock呼び出し、検索、ベクトルストアの遅延を分けます。
AWS X-Rayを使う場合は、共通トレースIDでオンライン経路を結びます。
CloudTrailは設定変更とAPI操作の監査に使い、回答本文を含むアプリケーションログとは保存目的とアクセス権を分けます。
CloudWatchは運用メトリクス、CloudTrailはAWS APIと設定変更、アプリケーション監査ログは最小化した利用記録を保持します。
各保存先にKMS暗号化、保持期間、削除、閲覧権限を設定します。

エラー率、p95遅延、スロットリング、同期失敗、検索結果ゼロ、回答保留率、入力トークン、推論費用にCloudWatch Alarmを設定します。
Amazon SNSまたはインシデント管理先へ通知し、自動再試行では上限と冪等性を設定します。

索引、プロンプト、モデルを同時に切り替えません。
新しい構成を別版として評価し、限定トラフィックで確認してから参照先を切り替え、問題時は旧版へ戻します。
