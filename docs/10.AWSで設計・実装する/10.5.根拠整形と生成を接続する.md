# 10.5 根拠整形と生成を接続する

AWS上の生成経路は、一体型と分離型に分けます。

| 経路 | 接続 | 適する場合 |
|---|---|---|
| 一体型 | `RetrieveAndGenerate → Knowledge Base → Bedrock生成モデル` | 顧客管理Knowledge Baseで、標準の検索・引用・生成を使う場合 |
| マネージド検索 | `AgenticRetrieveStreamまたはRetrieve → マネージドKnowledge Base` | マネージドKnowledge Baseを使う場合 |
| 分離型 | `Retrieve → Lambdaで根拠整形 → Converse` | 重複除去、矛盾処理、独自引用、複数検索器を制御する場合 |

[RetrieveAndGenerate](https://docs.aws.amazon.com/bedrock/latest/userguide/kb-test-retrieve-generate.html)は、検索結果を使った回答と引用情報を返します。
検索後処理を細かく検査する場合は、`Retrieve`の結果をLambdaでEvidence Setへ変換し、Bedrock Runtimeの`Converse`へ渡します。

Evidence Setには、本文、出典、版、アクセス制御確認結果、検索順位、採用理由を含めます。
生成モデルには、根拠と命令を別領域で渡し、引用ID、回答不能、矛盾時の出力形式を指定します。

最小の要素は、`citation_id`、`chunk_id`、`version`、`allowed`、`text`です。
回答中の`citation_id`を取得結果の出典情報へ対応付け、利用者が原文位置へ戻れるようにします。
入力上限へ収まらない場合は根拠を無条件に切り捨てず、第5章のEvidence validationとfallbackへ戻します。

[Amazon Bedrock Guardrails](https://docs.aws.amazon.com/bedrock/latest/userguide/guardrails.html)は、禁止トピック、有害内容、機密情報、語句などの入力・出力検査に使います。
検索前後などモデル呼び出しと独立した位置で検査する場合は、[ApplyGuardrail API](https://docs.aws.amazon.com/bedrock/latest/userguide/guardrails-use-independent-api.html)をLambdaから呼び出します。
Guardrailsは文書アクセス認可を代替しないため、検索前の属性フィルターと取得後の認可再確認を残します。
