# 10. AWSでRAGアプリケーションを設計する

AWSでRAGアプリケーションを作るには、利用者の質問を受けて回答を返す仕組みだけでなく、その前に資料を検索できる形へ整えておく仕組みも必要です。
資料を保管し、内容を読み取り、適切な大きさに分けて検索用データを作る処理は、まとめて実行する**Batch Layer（バッチ層）**に置きます。
質問の意味に合う情報を探し、使う根拠を選び、回答と引用を返す処理は、質問のたびに動く**Real-time Layer（リアルタイム層）**に置きます。

AWSには、これらの処理をまとめて任せられるAmazon Bedrock Knowledge Basesのようなサービスと、ストレージ、検索、生成の機能を個別に組み合わせる方法があります。
どちらが適するかは、簡単に構築したいか、検索や回答の処理を細かく制御したいかによって変わります。
本章では代表的な構成を比べたうえで、原文が検索可能になるまでの流れと、質問が根拠付きの回答になるまでの流れをAWSのサービス、リソース、API、設定へ対応づけます。
通常のアプリケーションで実行する場合と、複数の処理を自律的につなぐAmazon Bedrock AgentCoreを利用する場合の違いも扱います。

権限を管理するIAM、データを暗号化するKMS、監視、評価、版管理、コスト管理は、特定の処理だけに追加するものではありません。
資料の準備から回答の生成までを安全に運用し、変更後に同じ品質を保つため、すべての工程に関わります。
本章では、第1章から第9章までに説明したRAGの設計を土台に、こうした運用面も含めてAWS上の一つのシステムとして整理します。

本章の構成例と設定値は絶対解ではなく、比較を始めるための基準構成です。
第7章の同じ評価データと指標で、品質、性能、費用、運用性を比較します。

構築手順は扱いません。
コンソール操作、AWS CLI、サンプル文書、成功確認、削除手順は `handson/aws-rag-application/` に分離しています。

AWS固有の仕様はAWS公式資料を根拠とし、本文中にリンクを示します。
