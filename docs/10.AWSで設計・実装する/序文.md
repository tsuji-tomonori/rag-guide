# 10. AWSでAdvanced RAGを構成する

本章では、第3章から第9章で説明した処理をAWSサービスへ対応付け、実装時に選ぶ機能、接続、主要な設定値を示します。Amazon Bedrock Knowledge Basesを中心に、取り込み、検索、根拠整形、生成、評価をどこまでマネージド機能へ任せ、どこから独自処理へ分けるかを扱います。

Amazon Bedrock Knowledge Basesには、利用者がembedding modelとvector storeを選択・接続するカスタマーマネージド型と、取り込み、索引、保存、検索の運用をサービスへ委ねる**Managed Knowledge Base**があります。Managed Knowledge Baseは2026年6月17日に一般提供され、native connector、権限を考慮した検索、hybrid search、document ranking、agentic retrievalを一体として利用できる構成です。利用可能な情報源、リージョン、モデル、上限は変わるため、採用時点のAWS公式文書と実際のAPI応答を確認します。

RAG固有の設定に焦点を当てます。embedding modelと次元、chunking、vector store、検索方式、候補数、metadata filter、reranking、Evidence Set、生成、評価を対象とします。AWSアカウント、**IAM（Identity and Access Management、アイデンティティとアクセス管理）**、network、暗号化は既知の前提とします。

サービスの対応機能は変わるため、本文では判断方法と基準値を示し、実装時はリンク先のAWS公式ドキュメントで利用リージョン、対応モデル、上限を確認します。数値は無条件の推奨値ではなく、固定評価データで比較を始めるための初期値です。変動しやすい機能は、ユーザーガイド、API Reference、リリース情報を同一日付で突き合わせ、対象リージョンで最小の疎通試験を行ってから確定します。
