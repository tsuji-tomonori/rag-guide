# 10. AWSでAdvanced RAGを構成する

本章では、第2章で定義した検索前処理、検索、検索後処理、生成の四工程と、Batch Layer、Real-time Layerの二層を起点に、AWSサービスと作成するリソースを対応付けます。そのうえで、第3章から第9章で説明した処理を実装するときに、管理方式、parser、vector store、API、独自処理の実行基盤をどう選ぶかを示します。Amazon Bedrock Knowledge Basesを中心に、取り込み、検索、根拠整形、生成、評価をどこまでマネージド機能へ任せ、どこから独自処理へ分けるかを扱います。

**この章を読むと決められること**：四工程・二層ごとに必要なAWSサービスとリソースを特定し、AWSへ委ねる処理と独自実装する処理、初期設定、評価・運用への接続を決められます。

Amazon Bedrock Knowledge Basesには、利用者がembedding modelとvector storeを選択・接続するカスタマーマネージド型と、取り込み、索引、保存、検索の運用をサービスへ委ねる**Managed Knowledge Base**があります。AWS User Guideの[document history](https://docs.aws.amazon.com/bedrock/latest/userguide/bedrock-ug-doc-history.html)では、fully managed Knowledge Baseとagentic retrievalの更新は2026年3月2日です。native connector、権限を考慮した検索、hybrid search、document ranking、agentic retrievalを一体として利用できる構成ですが、利用可能な情報源、リージョン、model、上限は変わるため、採用時点のAWS公式文書と実際のAPI応答を確認します。

RAG固有の設定に焦点を当てます。embedding modelと次元、chunking、vector store、検索方式、候補数、metadata filter、reranking、Evidence Set、生成、評価を対象とします。AWSアカウント、**IAM（Identity and Access Management、アイデンティティとアクセス管理）**、network、暗号化は既知の前提とします。

サービスの対応機能は変わるため、本文では判断方法と基準値を示し、実装時はリンク先のAWS公式ドキュメントで利用リージョン、対応モデル、上限を確認します。数値は無条件の推奨値ではなく、固定評価データで比較を始めるための初期値です。変動しやすい機能は、ユーザーガイド、API Reference、リリース情報を同一日付で突き合わせ、対象リージョンで最小の疎通試験を行ってから確定します。
