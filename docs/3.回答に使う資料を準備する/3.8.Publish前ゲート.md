# 3.8 Publish前ゲート

Publish前ゲートは、Batch処理の成果物が構造上壊れていないことを確認し、評価へ渡すための停止点です。検索品質の良否はここで重複評価せず、第7章のgolden datasetとrelease gateで判断します。

## 3.8.1 manifest・schema・ACL・削除のpreflight

ingestion対象、入力snapshot、parser、chunking、embedding、index schema、件数、digestがmanifestと一致することを確認します。不一致時はpublishを止め、部分的に成功した成果物を公開しません。

`document_id`、`chunk_id`、source、version、provenanceなど、後段が必須とするfieldの欠損と型違反を検出します。schema違反をdefault値で隠さず、対象を隔離して再処理します。

ACLを必要とするdocumentまたはchunkに権限情報がない場合は、公開側へ倒さずfail closedにします。継承元、tenant、group、policy versionを追跡できることも確認します。

削除済みdocument、失効版、権限剥奪対象がpublish候補に残っていないかを、source側の差分と照合します。追加だけでなく、削除と権限変更がindexへ伝播したことを確認します。

## 3.8.2 publish候補の固定・隔離・評価引き渡し・rollback

publish候補を一意に再現できるよう、data snapshot、処理設定、model、dimension、index schema、artifact digestをmanifestへ固定します。後から同名indexへ上書きしません。

作成中・検証中のindexはproduction aliasから分離し、評価が完了するまで検索対象にしません。隔離単位はversion、namespace、collectionなど、切替と削除を原子的に行えるものにします。

第7章へ、publish候補の識別子、manifest、変更内容、既知の警告、評価対象sliceを渡します。第3章のgate通過は品質合格を意味せず、評価可能な成果物が揃ったことだけを意味します。

第7章のrelease gate通過後にaliasやrouting先を原子的に切り替えます。異常時は直前の既知良好versionへ戻せるよう、旧indexとmanifestを保持し、rollback手順を事前に試験します。
