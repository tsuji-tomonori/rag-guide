# 社内勉強会スライドの実装報告

## 依頼と対応

1時間の勉強会枠に対し、実際の説明を30〜40分で行うHTML発表資料を既存サイトへ追加しました。
現行の `docs/` を基準に、RAG概要、四工程・二層、各層の重要技術を中心に扱い、末尾で評価・セキュリティ・非機能・高度化・AWSへつなぎます。
音声入力と思われる「引き」「セク」は文脈から評価・非機能とセキュリティとして扱いました。

| 要件 | 対応 |
|---|---|
| 30〜40分 | 同じ22枚に30分／40分の累積配分。40分用の補足ノートを用意 |
| 四工程・二層を詳しく | スライド4〜6で目的・時点・対応表を分け、以後の技術を位置付け |
| 重要技術 | チャンク、メタデータ、埋め込み、質問変換、BM25・密検索、ハイブリッド、再ランキング、Evidence Set、引用・回答保留 |
| 終盤の話題 | 評価、権限・インジェクション、鮮度・時間・費用、高度化、AWS |
| 発表前提 | 全画面、目次、キー操作、独立した発表者画面、同期、タイマー、参照リンク、印刷CSS |
| 既存HTMLへ組み込み | `/seminar/`、`/slides/rag-intro/`、トップ・本文入口・サイドバーにリンク |

## 判断と内容上の確認

- PDFのオフホワイト・ネイビー・くすんだ青を採用し、発表向けに文字量を減らしました。
- 四工程は検索前処理・検索・検索後処理・生成、二層はBatch/Real-timeです。検索前処理が両層に存在する点を明記しました。
- 同じ架空の旅費規程で、金額・事前承認条件・版・出典を回答まで残す流れを説明します。実在の社内規程ではありません。
- AWSは現行ハンズオンのCustomer-managed KB構成を例にし、原文S3、KB、埋め込み・生成モデル、S3 Vectorsを区別しました。
- Managed Knowledge BaseとCustomer-managedの違いは発表者ノートで補足し、2026年9月5日にAWS公式資料を確認しました。
- アプリは既存の静的Astroビルドに収まります。新規依存、AWSリソース、公開先の変更はありません。
